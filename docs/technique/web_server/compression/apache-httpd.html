Apache httpd 的回應壓縮設定

Apache httpd 2.4 用 mod_deflate 做 gzip、用 mod_brotli（2.4.26 起）做 Brotli， 兩者都是官方模組。沒有 zstd 動態壓縮模組，但可以送預先壓縮好的 .zst 檔。

note

本文設定以 Apache httpd 2.4.68 驗證過。指令語法請以 Apache httpd 2.4 官方文件為準。

1. 需要的模組​

模組用途備註
mod_deflategzip 動態壓縮（filter 名稱 DEFLATE）只支援 gzip 編碼
mod_brotliBrotli 動態壓縮（filter 名稱 BROTLI_COMPRESS）2.4.26 起才有
mod_filter提供 AddOutputFilterByType2.3.7 起這個指令移到 mod_filter
mod_headers修改 Vary、Content-Encoding 等回應標頭預先壓縮時需要
mod_rewrite把請求改寫到 .br／.gz預先壓縮時需要
mod_env、mod_setenvif用環境變數 no-gzip／no-brotli 排除特定請求通常已啟用

確認目前載入了哪些模組：

apachectl -M 2>/dev/null | grep -E 'deflate|brotli|filter|headers|rewrite'

啟用方式依發行版而定：

環境做法
Debian／Ubuntumod_deflate 與 mod_filter 預設已啟用。其他用 sudo a2enmod brotli headers rewrite，改完 sudo apachectl configtest && sudo systemctl reload apache2
RHEL 系模組在 /etc/httpd/conf.modules.d/ 下載入，請用上面的 apachectl -M 確認，缺的依發行版文件啟用
自行編譯mod_brotli 需要編譯時有 Brotli 函式庫（--enable-brotli，請以官方編譯文件為準）
warning

Debian／Ubuntu 預設的 /etc/apache2/mods-available/deflate.conf 已經有一組 AddOutputFilterByType DEFLATE ...，但清單裡沒有 application/json 與 image/svg+xml。 另外，AddOutputFilterByType 在同一個範圍內是累加的，但較內層的範圍（VirtualHost、Directory、Location） 會整個取代外層的設定，不是累加。在 vhost 裡寫了一行，就要把所有想壓的型別都列上。

2. 最小設定（只開 gzip）​

Debian：/etc/apache2/conf-available/compression.conf（再 a2enconf compression）；RHEL：/etc/httpd/conf.d/compression.conf
AddOutputFilterByType DEFLATE text/html text/plain text/css text/javascript application/javascript application/json application/xml image/svg+xml

這一行的意思是：回應的 Content-Type 是這些型別時，套用 DEFLATE 輸出 filter。 mod_deflate 會自己檢查用戶端的 Accept-Encoding，也會自己加上 Vary: Accept-Encoding。

3. 建議設定（Brotli + gzip）​

compression.conf（server 或 VirtualHost 範圍）
# 壓縮等級：這兩個指令只能放在 server config 或 VirtualHost，不能放 .htaccess
BrotliCompressionQuality 5
DeflateCompressionLevel 6

# 支援 br 的用戶端用 Brotli，其他退回 gzip
AddOutputFilterByType BROTLI_COMPRESS;DEFLATE \
    text/html text/plain text/css text/xml text/javascript text/csv \
    application/javascript application/json application/xml \
    application/ld+json application/manifest+json \
    application/rss+xml application/atom+xml application/wasm \
    image/svg+xml image/x-icon font/ttf font/otf
設定預設值說明
BrotliCompressionQuality5範圍 0–11。動態壓縮建議 4–6
DeflateCompressionLevelzlib 預設（等同 6）範圍 1–9
AddOutputFilterByType BROTLI_COMPRESS;DEFLATE ...—用分號串起兩個 filter，寫在前面的先處理。用戶端接受 br 時由 Brotli 壓，壓完帶了 Content-Encoding，後面的 DEFLATE 就不會再壓；用戶端不接受 br 時 Brotli 跳過，由 DEFLATE 壓
BrotliCompressionWindow18視窗大小（2 的次方），保持預設
DeflateBufferSize8096一次交給 zlib 壓縮的片段大小，保持預設

實測行為：

  • 不看 q 值。 Accept-Encoding: br;q=0.1, gzip 還是會拿到 br。
  • 沒有最小長度門檻的指令。 實測 mod_deflate 對幾十 bytes 的極小回應會自己跳過， 但 mod_brotli 連 3 bytes 的回應都會壓（變成 7 bytes）。影響很小，但要知道有這回事。
  • 兩個模組都會自動加 Vary: Accept-Encoding，也會在 ETag 後面加上 -gzip／-br（見下一節）。
  • 後端或應用程式已經送出 Content-Encoding 的回應，不會再被壓一次。

4. ETag 與 304：DeflateAlterETag／BrotliAlterETag​

同一個網址的壓縮版與未壓縮版內容不同，規格上 ETag 也應該不同， 所以 Apache 預設（AddSuffix）會把 "abc" 改成 "abc-gzip"、"abc-br"。

副作用是動態壓縮的內容幾乎拿不到 304：瀏覽器回驗證時送回 If-None-Match: "abc-gzip"， Apache 拿去跟檔案原本的 "abc" 比，對不上。實測瀏覽器同時送 If-None-Match 與 If-Modified-Since 時，每次都回完整的 200（依規格，有 If-None-Match 時 If-Modified-Since 會被忽略）。

值行為取捨
AddSuffix（預設）ETag 加上 -gzip／-br符合規格，但壓縮內容無法用 ETag 得到 304
NoChange不改 ETag實測可以正常回 304；但壓縮與未壓縮版共用同一個 ETag，不完全符合規格
Remove拿掉壓縮回應的 ETag退回用 Last-Modified 驗證
server config 或 VirtualHost
# DeflateAlterETag 需要 2.4.58 以上
DeflateAlterETag NoChange
BrotliAlterETag NoChange

如果你的靜態資源檔名帶 hash（例如 app.3f2a1c.js）並設了長效快取，瀏覽器根本不會回驗證， 這個問題就不重要；否則可以考慮上面的設定，或改用預先壓縮 —— 預先壓縮檔有自己的 ETag，沒有這個問題。

5. 排除特定請求：no-gzip／no-brotli​

兩個模組都會看環境變數：設了 no-gzip，DEFLATE 就不壓；設了 no-brotli，BROTLI_COMPRESS 就不壓。

# 依網址排除（例如某個會反射輸入又含 token 的頁面，見 BREACH）
<Location "/account/">
    SetEnv no-gzip 1
    SetEnv no-brotli 1
</Location>

# 用 SetOutputFilter 對「所有型別」開壓縮時，要自己排除已壓縮的格式
SetEnvIfNoCase Request_URI "\.(?:gif|jpe?g|png|webp|avif|mp4|webm|zip|gz|br|zst|woff2?)$" no-gzip no-brotli

用 AddOutputFilterByType 列白名單時，圖片、影片本來就不在清單裡，不需要第二段。 建議一律用 AddOutputFilterByType 白名單，而不是 SetOutputFilter 加排除清單。

6. 串流回應（SSE、串流 API）要排除​

實測 Apache 2.4 以 mod_proxy_http 代理 SSE（後端每秒送一個事件）：

設定結果
text/event-stream 在 AddOutputFilterByType 清單中每秒到一個，但每個事件都被壓縮（mod_proxy_http 在後端暫時沒資料時會 flush，壓縮 filter 跟著 flush）
SetOutputFilter BROTLI_COMPRESS;DEFLATE（所有型別）同上
上一列再加 SetEnv no-gzip 1、SetEnv no-brotli 1不壓縮，每秒到一個
型別清單不含 text/event-stream不壓縮，每秒到一個

也就是說，在這個組合下事件沒有被卡住，但每個小事件都付出壓縮的開銷， 而且能不能即時送出，取決於前面每一層有沒有正確 flush。建議明確排除：

VirtualHost 內
ProxyPass "/events" "http://127.0.0.1:3000/events" timeout=3600
<Location "/events">
    SetEnv no-gzip 1
    SetEnv no-brotli 1
</Location>
設定用途
timeout=3600這個 worker 等後端資料的逾時秒數（預設沿用 Timeout，通常 60 秒）。SSE 事件間隔可能很長，搭配後端定期送心跳
SetEnv no-gzip 1／no-brotli 1不管上層怎麼設，這個路徑一律不壓

其他情境：

  • mod_proxy_fcgi（例如 PHP-FPM）：ProxyPass 的 flushpackets=on 參數讓代理每收到一段就 flush。 依官方文件，這個參數目前只對 mod_proxy_ajp 與 mod_proxy_fcgi 有效。 PHP 端也要關掉輸出緩衝或自己呼叫 flush。
  • 長輪詢：一次一整包回應，壓縮不會卡住它，注意逾時設定即可。

7. 在 .htaccess 裡設定​

共用主機只能改 .htaccess 時：

  • AddOutputFilterByType、SetEnv、Header、RewriteRule 可以寫在 .htaccess（需要 AllowOverride FileInfo）。
  • DeflateCompressionLevel、BrotliCompressionQuality、*AlterETag 只能放在 server config 或 VirtualHost，寫在 .htaccess 會造成 500 錯誤。

8. 預先壓縮：用 mod_rewrite 送 .br ／ .zst ／ .gz​

Apache 沒有 nginx gzip_static 那樣的單一指令，官方文件的做法是用 mod_rewrite 把請求改寫到壓縮檔，再用 mod_headers 補上正確的標頭。下面是整理過、實測可用的版本， 支援 Brotli、zstd、gzip 三種（Apache 雖然不能動態壓 zstd，但送現成的 .zst 沒問題）：

VirtualHost 內（也可以把 Directory 裡的內容放進 .htaccess）
<Directory "/var/www/example">
    Require all granted

    RewriteEngine On

    # 1) 用戶端接受、且壓縮檔存在時，改寫到壓縮檔（依序嘗試 br → zstd → gzip）
    RewriteCond "%{HTTP:Accept-Encoding}" "\bbr\b"
    RewriteCond "%{REQUEST_FILENAME}.br" -s
    RewriteRule "^(.+)\.(css|js|mjs|html|json|svg|txt|xml|wasm)$" "$1.$2.br" [L]

    RewriteCond "%{HTTP:Accept-Encoding}" "\bzstd\b"
    RewriteCond "%{REQUEST_FILENAME}.zst" -s
    RewriteRule "^(.+)\.(css|js|mjs|html|json|svg|txt|xml|wasm)$" "$1.$2.zst" [L]

    RewriteCond "%{HTTP:Accept-Encoding}" "\bgzip\b"
    RewriteCond "%{REQUEST_FILENAME}.gz" -s
    RewriteRule "^(.+)\.(css|js|mjs|html|json|svg|txt|xml|wasm)$" "$1.$2.gz" [L]

    # 2) 修正 Content-Type（否則 .gz 會被當成 application/x-gzip），並避免被動態壓縮再壓一次
    RewriteRule "\.css\.(br|zst|gz)$"  "-" [T=text/css,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.m?js\.(br|zst|gz)$" "-" [T=text/javascript,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.html\.(br|zst|gz)$" "-" [T=text/html,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.json\.(br|zst|gz)$" "-" [T=application/json,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.svg\.(br|zst|gz)$"  "-" [T=image/svg+xml,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.txt\.(br|zst|gz)$"  "-" [T=text/plain,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.xml\.(br|zst|gz)$"  "-" [T=application/xml,E=no-gzip:1,E=no-brotli:1]
    RewriteRule "\.wasm\.(br|zst|gz)$" "-" [T=application/wasm,E=no-gzip:1,E=no-brotli:1]

    # 3) 標上正確的 Content-Encoding
    <FilesMatch "\.br$">
        Header set Content-Encoding br
    </FilesMatch>
    <FilesMatch "\.zst$">
        Header set Content-Encoding zstd
    </FilesMatch>
    <FilesMatch "\.gz$">
        Header set Content-Encoding gzip
    </FilesMatch>

    # 4) 原檔與壓縮檔都要帶 Vary，快取才會分開存
    <FilesMatch "\.(css|js|mjs|html|json|svg|txt|xml|wasm)(\.(br|zst|gz))?$">
        Header merge Vary Accept-Encoding
    </FilesMatch>
</Directory>

逐段說明：

區段用途
RewriteCond "%{HTTP:Accept-Encoding}" "\bbr\b"請求的 Accept-Encoding 含有 br 這個字
RewriteCond "%{REQUEST_FILENAME}.br" -s對應的 .br 檔存在且不是空檔
RewriteRule ... "$1.$2.br" [L]改寫到壓縮檔。放在 Directory（或 .htaccess）裡時，REQUEST_FILENAME 已是完整檔案路徑，所以可以直接檢查檔案
[T=...,E=no-gzip:1,E=no-brotli:1]T= 強制 Content-Type；E= 設環境變數，讓動態壓縮不要再壓
Header set Content-Encoding ...告訴瀏覽器這份內容要先解壓
Header merge Vary Accept-Encoding加上 Vary，已經有的話不重複加

注意事項：

  • 這裡的比對很陽春：Accept-Encoding: br;q=0（明確拒絕 br）也會命中。實務上瀏覽器不會這樣送，但自製用戶端可能會。
  • 規則寫在 VirtualHost 層（不包 Directory）時，REQUEST_FILENAME 還不是檔案路徑， 要改用 %{LA-U:REQUEST_FILENAME} 預查，寫法請參考 mod_brotli 官方文件的範例。
  • 預先壓縮檔有自己的 Content-Length 與 ETag，也支援 Range。
  • Apache 只檢查壓縮檔「存不存在」，不會比對版本。原檔更新後一定要重新產生壓縮檔， 否則使用者會拿到舊內容。

9. 驗證​

curl -s -o /dev/null -D - -H 'Accept-Encoding: br' https://example.com/assets/app.js
curl -s -o /dev/null -D - -H 'Accept-Encoding: gzip' https://example.com/api/data

要記錄壓縮比，可以用 DeflateFilterNote／BrotliFilterNote 把輸入、輸出位元組數寫進日誌， 範例見兩個模組的官方文件。完整驗證方法見驗證。

10. 常見錯誤​

症狀原因解法
Invalid command 'AddOutputFilterByType'沒載入 mod_filter啟用 mod_filter
Invalid command 'BrotliCompressionQuality'沒載入 mod_brotlia2enmod brotli 或載入模組
.htaccess 裡寫壓縮等級導致 500該指令只能放 server config／VirtualHost移到主設定
JSON API 沒被壓型別清單沒有 application/json（Debian 預設清單就沒有）補上
vhost 加了一行後，原本有壓的型別不壓了內層的 AddOutputFilterByType 取代外層vhost 裡列出完整清單
壓縮內容一直回 200 不回 304ETag 被加上 -gzip／-br見第 4 節
預先壓縮的 .js.gz 被瀏覽器當成下載檔Content-Type 是 application/x-gzip、沒有 Content-Encoding檢查 T= 與 Header set Content-Encoding 是否生效
更新網站後使用者看到舊內容殘留舊的預先壓縮檔build 時清空輸出目錄
