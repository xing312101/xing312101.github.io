自架中繼（GCP 免費 VM＋nginx＋SSH 反向通道）

自己開一台小機器當「中繼」：公開網址和 HTTPS 憑證都在它身上，本機用 ssh -R 把服務接過去。 適合有自己的網域、DNS 不想搬到 Cloudflare、要給好幾個服務各一個固定網址的情況。 怎麼選、通道接哪個 port、怎麼驗有沒有通、接 LINE webhook，見總覽。 最後更新：2026-11。GCP 主控台、Ubuntu 26.04 LTS、nginx 1.28、certbot 4.0、OpenSSH 10.2 實測過；沒實測的會標出來。主控台的選單名稱常改，對不上時以官方文件為準。

LINE／瀏覽器 ──HTTPS──▶ 中繼機的 nginx（有憑證）──▶ 中繼機的 127.0.0.1:13000
                                                          ▲
                                          SSH 反向通道（本機主動連出去）
                                                          │
                                                   本機的 127.0.0.1:3000
  • 本機不用開 port、不用固定 IP：連線是本機往外撥的，跟 ngrok、cloudflared 一樣。
  • 通道在中繼機上只開在 127.0.0.1，外面只碰得到 nginx。

0. 跟 ngrok、Cloudflare Tunnel 比​

ngrok 免費Cloudflare 固定通道自架中繼
網址系統配的 dev domain，只有一個自己的網域，但 nameserver 要搬到 Cloudflare自己的網域，DNS 留在原本那家，加 A 紀錄就好
好幾個服務要 internal endpoint＋Traffic Policy一個服務一個子網域一個服務一個子網域
本機要裝ngrokcloudflared不用（系統內建 ssh）
費用免費（每月 1 GB、2 萬個請求）免費機器在 GCP 免費額度內；外部 IP 要看帳單（§9）
要顧的沒有沒有一台機器：系統更新、憑證續期（都會自動跑）、IP 換了要改 DNS
看請求4040--loglevel debugnginx 的 access log（§8）

不要直接借正式環境的主機當中繼：開發站的流量、開發伺服器的漏洞（§10）就跟正式站在同一台上了。另開一台，而且跟正式環境的網路隔開（§2）。

1. 要準備的​

  • 網域：能自己加 DNS 紀錄。下面用 bot-dev.example.com、app2-dev.example.com 兩個子網域當例子，分別接本機的 3000、4000。
    • 最好用跟正式站不同的網域。用正式網域的子網域，瀏覽器會把開發站和正式站當成同一個網站（same-site），開發站被打下來就能對主網域設 cookie。
  • GCP 帳號：要綁付款方式（免費額度也要）。
  • 兩把 SSH 金鑰：管理用的（登入中繼機、有 sudo）和通道用的（只能開通道，§5）。分開的好處：通道那把要放在會自動重連的腳本裡、通常不設密碼，萬一外洩也只能開通道。
ssh-keygen -t ed25519 -f ~/.ssh/relay-admin_ed25519 -C relay            # 管理用：建議設密碼
ssh-keygen -t ed25519 -f ~/.ssh/relay-tunnel_ed25519 -C tunnel -N ''   # 通道用

GCE 會拿公鑰最後的註解（上面的 relay）當登入帳號，並給它不用密碼的 sudo。

2. 隔離的網路（VPC）​

不要放在 default 網路。 default 網路內建一條讓網路內全部互通的防火牆規則（default-allow-internal），同一個專案裡的其他 VM 都連得到。 實測：放在 default 網路時，中繼機連得到另一台 VM 內部 IP 上有在聽的 port（測了 6 個，全部連得到）；換到自己的網路之後，一個都連不到。 中繼機是對外的機器，它被打下來時不該碰得到別台。

主控台「VPC 網路 → 建立 VPC 網路」：

  • 名稱：dev-relay
  • 子網路建立模式「自訂」：名稱 dev-relay-us-west1、區域 us-west1、IPv4 範圍 10.200.0.0/24（跟其他網路不重疊就好）
  • 私人 Google 存取：關
  • 流量記錄：關（開了要收費）
  • 防火牆規則：建立頁會列出幾條常用規則可以勾，只勾 SSH（tcp:22）。來源最好限縮成自己的 IP。

再加一條給網頁用的（「VPC 網路 → 防火牆 → 建立防火牆規則」）：

  • 名稱 dev-relay-allow-web、網路 dev-relay、流量方向「輸入」、動作「允許」
  • 目標「網路中的所有執行個體」、來源 IPv4 範圍 0.0.0.0/0
  • TCP 80,443：80 給 Let's Encrypt 驗網域，443 是實際的 HTTPS
  • 記錄：關

3. 建 VM（免費額度）​

「Compute Engine → VM 執行個體 → 建立執行個體」，左邊各分頁：

分頁怎麼設為什麼
機器設定區域 us-west1、us-central1 或 us-east1；系列 E2、機器類型 e2-micro；佈建模型「標準」免費額度只給這三區、非 Spot 的 e2-micro
OS 和儲存空間Ubuntu 26.04 LTS（x86/64，不要選 Ubuntu Pro）；磁碟類型「標準永久磁碟」、30 GB預設的「平衡永久磁碟」不在免費額度內；Pro 要授權費
資料保護不備份快照排程要收費
網路網路介面改成 dev-relay；外部 IPv4「臨時」；Network Service Tier「標準級」；「允許 HTTP／HTTPS 流量」、IP 轉送、Tier_1 都不勾網路介面預設是 default，畫面上寫「一經設定即無法變更」；標準級每個區域每月 200 GB 流量免費（§9）；§2 的規則已經套用到整個網路
觀測能力Ops Agent 不裝會把記錄送出去，也要服務帳號
安全性服務帳戶「沒有服務帳戶」；受防護的 VM 三項都開；存取 VM：加管理用的公鑰、勾「封鎖專案層級的安全殼層金鑰」見下面
進階「防刪除功能」勾起來誤刪的話臨時 IP 就沒了（§4）
  • 為什麼不要服務帳號：預設會掛專案的 Compute Engine 預設服務帳號，存取範圍預設包含 Cloud Storage 唯讀。實測：這樣建的中繼機，對同專案的 bucket 有 storage.objects.list、storage.objects.get 權限 —— 它被打下來，專案裡的檔案就都讀得到。
  • 為什麼封鎖專案層級的金鑰：專案的中繼資料裡如果放了別人的 SSH 公鑰，預設每台 VM 都會收；勾了之後這台只認自己的。
  • 右邊的每月預估費用會顯示 e2-micro 約 6 美元：免費時數沒有算進去。磁碟選對的話，磁碟那一行是 0。

建好後連進去確認：

ssh -i ~/.ssh/relay-admin_ed25519 relay@<中繼機 IP>

# 以下在中繼機上
M() { curl -sf -H 'Metadata-Flavor: Google' "http://metadata.google.internal/computeMetadata/v1/instance/$1"; echo; }
M service-accounts/                   # 空的＝沒掛服務帳號
M attributes/block-project-ssh-keys   # true
M network-interfaces/0/network        # 結尾是 dev-relay

4. DNS​

到網域的 DNS（註冊商或 DNS 代管那邊）加 A 紀錄，都指到中繼機的外部 IP：

名稱類型值
bot-devA中繼機的外部 IP
app2-devA中繼機的外部 IP
dig +short bot-dev.example.com     # 印出中繼機的 IP 就生效了

⚠️ 臨時 IP 會換：主控台按「停止」再「啟動」、或刪掉 VM，IP 就換一個（在 VM 裡 sudo reboot 不會）。換了要馬上改 DNS： 舊 IP 會還給 Google、可能分給別人；DNS 沒改的話，你的子網域就指到別人的機器上（subdomain takeover），對方還能幫你的子網域申請憑證。 不想顧這件事就保留靜態 IP；但保留著卻沒在用（VM 停著、沒掛上）的靜態 IP 要收費。

5. 通道專用帳號（只准反向轉送）​

在中繼機上建一個沒有密碼、不能登入的系統帳號，放通道用的公鑰，前面加上限制：

sudo useradd --system --create-home --home-dir /var/lib/relay-tunnel --shell /usr/sbin/nologin tunnel
sudo install -d -m 700 -o tunnel -g tunnel /var/lib/relay-tunnel/.ssh

# restrict：先全部關掉；port-forwarding：再打開轉送；permitlisten：-R 只能聽這兩個位址
echo 'restrict,port-forwarding,permitlisten="127.0.0.1:13000",permitlisten="127.0.0.1:14000" ssh-ed25519 AAAA…（relay-tunnel_ed25519.pub 的內容）' \
  | sudo tee /var/lib/relay-tunnel/.ssh/authorized_keys
sudo chown tunnel:tunnel /var/lib/relay-tunnel/.ssh/authorized_keys
sudo chmod 600 /var/lib/relay-tunnel/.ssh/authorized_keys

sshd 那邊再擋一層，/etc/ssh/sshd_config.d/99-relay-tunnel.conf：

# 通道專用：只准 -R、只能聽兩個 127.0.0.1 的 port，不給 shell、不准拿這台當跳板
Match User tunnel
    AllowTcpForwarding remote
    PermitListen 127.0.0.1:13000 127.0.0.1:14000
    GatewayPorts no
    AllowStreamLocalForwarding no
    AllowAgentForwarding no
    X11Forwarding no
    PermitTTY no
    ForceCommand /usr/sbin/nologin
    # 本機突然斷線（睡眠、換網路）時，15 秒問一次、3 次沒回就斷，舊連線才不會一直佔著 port
    ClientAliveInterval 15
    ClientAliveCountMax 3
sudo sshd -T -C user=relay,host=x,addr=1.2.3.4 | sort > /tmp/before.txt    # 改之前：先存管理帳號的實際設定
# （寫好上面那個檔）
sudo sshd -t && echo 語法OK
sudo sshd -T -C user=relay,host=x,addr=1.2.3.4 | sort | diff /tmp/before.txt - && echo 管理帳號沒受影響
sudo sshd -T -C user=tunnel,host=x,addr=1.2.3.4 | grep -i -E '^(allowtcpforwarding|permitlisten|permittty|forcecommand|clientalive)'
sudo systemctl reload ssh      # Ubuntu 上 sshd 的服務叫 ssh
  • AllowTcpForwarding remote：只准 -R。-L、-W（借中繼機往別處連）都不准，中繼機就不會變成跳板。
  • authorized_keys 的選項跟著這把金鑰，Match User 跟著這個帳號。兩層各自都擋得住，多一層是怕其中一邊哪天被改掉。

在本機驗它真的擋住了（下面是實測的輸出）：

ssh -i ~/.ssh/relay-tunnel_ed25519 tunnel@<中繼機 IP> id
# This account is currently not available.

ssh -i ~/.ssh/relay-tunnel_ed25519 -W 1.1.1.1:443 tunnel@<中繼機 IP>
# open failed: administratively prohibited

ssh -i ~/.ssh/relay-tunnel_ed25519 -o ExitOnForwardFailure=yes -N -R 127.0.0.1:15555:127.0.0.1:3000 tunnel@<中繼機 IP>
# remote port forwarding failed for listen port 15555

ssh -i ~/.ssh/relay-tunnel_ed25519 -o ExitOnForwardFailure=yes -N -R 0.0.0.0:13000:127.0.0.1:3000 tunnel@<中繼機 IP>
# remote port forwarding failed for listen port 13000

6. nginx 與 HTTPS​

sudo apt-get update && sudo apt-get install -y nginx certbot python3-certbot-nginx

共用的轉送設定 /etc/nginx/snippets/relay-proxy.conf：

proxy_http_version 1.1;
# 原本的網址放在這幾個 header 給程式看（Host 會在各個 server 裡改掉，見下面）
proxy_set_header X-Forwarded-Host $host;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Real-IP $remote_addr;
# WebSocket
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection $connection_upgrade;
# 串流回應（SSE）不能被緩衝；長連線開久一點
proxy_buffering off;
proxy_read_timeout 1h;
# 上傳檔案（nginx 預設只收 1 MB，超過回 413）
client_max_body_size 100m;

網址 /etc/nginx/sites-available/relay：

map $http_upgrade $connection_upgrade { default upgrade; '' close; }

# 不認得的網域、直接打 IP：不回應
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;
    return 444;                    # 直接斷線
}
server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    server_name _;
    ssl_reject_handshake on;       # 拒絕 TLS 握手，憑證也不給看
}

server {
    listen 80;
    listen [::]:80;
    server_name bot-dev.example.com;
    location / {
        include snippets/relay-proxy.conf;
        proxy_set_header Host localhost:3000;
        proxy_pass http://127.0.0.1:13000;
    }
}

server {
    listen 80;
    listen [::]:80;
    server_name app2-dev.example.com;
    location / {
        include snippets/relay-proxy.conf;
        proxy_set_header Host localhost:4000;
        proxy_pass http://127.0.0.1:14000;
    }
}
sudo ln -s /etc/nginx/sites-available/relay /etc/nginx/sites-enabled/relay
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
  • 不要露出版本：Ubuntu 26.04 的 /etc/nginx/nginx.conf 寫的是 server_tokens build;，錯誤頁和 Server header 會帶版本。直接把那一行改成 server_tokens off;（在 conf.d/ 另外寫會報重複，§11）。
  • 為什麼把 Host 改成 localhost:3000：開發伺服器（例如 Vite）只認 localhost，別的網域會被擋成 403「Blocked request」（總覽 §5）。在 nginx 改掉，專案的設定就不用動。 代價：程式如果拿 Host 組完整網址（轉址、OAuth 回呼），會組出 localhost:3000。這種程式改看 X-Forwarded-Host；或者這裡改成 proxy_set_header Host $host;，在開發伺服器的 allowedHosts 加上這個網域。
  • SSE 那兩行是 nginx 轉串流的一般寫法，SSE 沒實測。

憑證（DNS 生效、從外面打得到 80 之後）：

sudo certbot --nginx --cert-name relay -d bot-dev.example.com -d app2-dev.example.com --redirect
  • certbot 會改 sites-available/relay：加上 443 和憑證；--redirect 再加 http→https 的 301。
  • 會問 email。Let's Encrypt 2025 年 6 月起已經不寄到期通知信，不想給可以加 --register-unsafely-without-email。
  • 自動續期：apt 裝的 certbot 會帶 certbot.timer，systemctl list-timers certbot.timer 看下次什麼時候跑。
  • 演練續期：sudo certbot renew --dry-run --no-random-sleep-on-renew（不加後面那個參數可能卡好幾分鐘，§11）。
  • 憑證會公開登記（Certificate Transparency）：申請完沒多久，crt.sh 這類網站就查得到這兩個子網域，掃描程式也會開始來敲門。不要以為網址沒告訴別人就沒人知道。

驗：

curl -sI https://bot-dev.example.com/ | head -1      # 502：nginx、憑證都好了，只是通道還沒開
curl -sI http://bot-dev.example.com/ | grep -i -E '^(HTTP|location)'   # 301，轉到 https
curl -s http://<中繼機 IP>/; echo "結束碼 $?"         # 52（Empty reply）：直接打 IP 不回應
curl -sk https://<中繼機 IP>/; echo "結束碼 $?"       # 35：直接打 IP 被拒絕握手

7. 本機開通道​

第一次先用管理帳號連一次，把中繼機的主機金鑰記進 known_hosts。通道一律用 StrictHostKeyChecking=yes：主機金鑰對不上就不連。

relay-tunnel.sh：

#!/bin/bash
# 要測的時候才開，Ctrl+C 關。斷線會自己重連。
RELAY=<中繼機 IP>
KEY="$HOME/.ssh/relay-tunnel_ed25519"

trap 'echo; echo "已關閉"; exit 0' INT TERM

while true; do
  echo "[$(date '+%H:%M:%S')] 連線中"
  # -n -N：不讀鍵盤、不跑指令，只開通道
  # ExitOnForwardFailure：port 沒開成就結束重來，不要變成連著卻沒在轉
  # ServerAliveInterval／CountMax：15 秒問一次中繼機，3 次沒回就當斷線
  ssh -n -N -i "$KEY" -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes \
      -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 \
      -R 127.0.0.1:13000:127.0.0.1:3000 \
      -R 127.0.0.1:14000:127.0.0.1:4000 \
      tunnel@"$RELAY"
  rc=$?                     # 要緊接在 ssh 後面存（§11）
  echo "[$(date '+%H:%M:%S')] 斷了（結束碼 ${rc}），10 秒後重連"
  sleep 10
done
bash relay-tunnel.sh

# 另一個終端機：本機 3000 回什麼，這裡就是什麼
curl -s -o /dev/null -w '%{http_code}\n' https://bot-dev.example.com/
  • -R 127.0.0.1:13000:127.0.0.1:3000：前半是中繼機上的位址（明寫 127.0.0.1，只開在中繼機自己身上），後半是本機的服務。兩邊的 port 不用一樣。
  • 實測：把 ssh 砍掉，10 秒後自己連回去，網址馬上恢復。
  • 沒實測：網路突然斷掉（筆電睡眠、換 Wi-Fi）時，中繼機要等 ClientAlive 逾時（約 45 秒）才放掉舊連線，在那之前重連會因為 port 還被佔著而失敗；迴圈會一直重試，照理一分鐘左右接得回來。
  • 不要常駐：通道開著，本機的開發伺服器就在網路上（§10）。

接 LINE webhook：網址固定，LINE 後台填一次就好；步驟和用 API 設定、驗證的方法見總覽 §4。

8. 看請求、除錯​

  • 每個請求：中繼機上 sudo tail -f /var/log/nginx/access.log（時間、來源 IP、方法、路徑、狀態碼）。body 不會記，要看 LINE 送來的內容，在自己的程式裡印。
  • 通道有沒有接上：中繼機上 sudo ss -ltnp | grep -E ':1[34]000 '，接上的話會看到 sshd-session（舊版是 sshd）在聽 127.0.0.1:13000。
看到什麼代表
502nginx 好的，但通道沒開，或本機那個 port 沒有程式在聽
curl 結束碼 52（Empty reply）DNS 指到這台了，但這個網域不在 nginx 的 server_name 裡
curl 結束碼 35（握手失敗）同上，HTTPS 版；或憑證還沒申請
405、400、404……已經到本機的程式了，照一般的方式除錯

9. 費用​

照 Google 的免費額度頁（2026-11）：

  • 每個帳單帳戶每月：一台非 Spot 的 e2-micro（us-west1／us-central1／us-east1）、30 GB 標準永久磁碟、從北美往外 1 GB 流量（不含往中國、澳洲）。
  • e2-micro 是算時數的：同一個帳單帳戶底下，這三區的 e2-micro 合起來在當月的總時數以內免費。開兩台就會超過。
  • 標準級網路：每個區域每月 200 GB 對外流量免費（2023 年 10 月起；建 VM 時選標準級，畫面上也這樣寫）。Premium（預設）只有上面那 1 GB。
  • 外部 IP：免費額度頁沒寫。第一個月看一下帳單最準。
  • 會讓你收到帳單的：平衡永久磁碟、Spot、Ubuntu Pro、快照排程、VPC 流量記錄、防火牆記錄、沒在用的靜態 IP。VM 有外部 IP 就能上網，不需要 Cloud NAT。

10. 安全​

  • 通道開著＝本機的開發伺服器在網路上。網址會出現在憑證的公開紀錄裡（§6），有人會來掃。只在要測的時候開。
  • 開發伺服器有過「對外才會被利用」的漏洞：Vite 公布過好幾個讓 dev server 讀得到 server.fs.deny 擋住的檔案（例如 .env）的漏洞，光 2026 年就有好幾個（見 Vite 的 Security Advisories）。 官方寫的條件是用 --host 開放到網路；用通道接到公開網址，效果是一樣的（這是推論，官方沒這樣寫）。
    • Vite 保持最新版：npm ls vite 看版本，對照上面的公告。
    • 開發伺服器本身不要綁 0.0.0.0：有通道就不需要。
    • 只要 webhook 的服務，通道直接接後端：前端的開發伺服器就不會對外（總覽 §2）。
  • 本機的開發站如果有測試帳號、預設密碼、不用登入的 API，通道開著時全世界都用得到。
  • 中繼機本身：沒有服務帳號、獨立網路、只開 22／80／443；Ubuntu 預設開著自動安全更新（/etc/apt/apt.conf.d/20auto-upgrades）。
  • 管理用的金鑰等於整台機器（有 sudo）：設密碼、不要放進腳本。通道用的那把外洩，只能在中繼機上聽那兩個 port（§5 的測試驗的就是這件事）。

11. 實測過的坑​

  • 網路介面預設是 default：建立畫面上寫「網路介面一經設定即無法變更」，建之前就要改成自己的網路。漏改的話，最省事的是刪掉重建。
  • "server_tokens" directive is duplicate：Ubuntu 26.04 的 nginx.conf 本來就有 server_tokens build;，在 conf.d/ 另外寫 server_tokens off; 就會報這個。改 nginx.conf 那一行。
  • nginx -t 沒過時，systemctl reload nginx 會失敗，但 nginx 繼續用舊設定跑：systemctl is-active 還是 active，網頁回 200（Ubuntu 的預設頁），看起來像成功了。改完一定先跑 nginx -t，再看實際回什麼。
  • certbot renew --dry-run 卡著不動：沒開終端機時（ssh 主機 '指令'、cron），certbot 會先隨機等一段時間才開始，log 寫 Non-interactive renewal: random delay of 299 seconds。加 --no-random-sleep-on-renew 就馬上跑（實測 9 秒）。
  • 重連腳本印出來的結束碼永遠是 0：寫成 echo "[$(date)] 結束碼 $?"，同一行先跑的 $(date) 會把 $? 換成 date 的結束碼。要在 ssh 的下一行就 rc=$?。
  • macOS 內建的 bash（3.2）把變數後面的全形字吃掉："結束碼 $rc），" 印出來是亂碼 —— ） 的前幾個位元組被當成變數名稱的一部分。寫成 ${rc}。
  • zsh 的迴圈變數不要叫 path：zsh 的 path 跟 PATH 綁在一起，path=/api/... 一指定，curl、head 全部變成 command not found。
