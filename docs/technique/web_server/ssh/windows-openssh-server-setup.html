Windows OpenSSH Server 架設教學（區網 + 金鑰登入）

在 Windows 10/11 上安裝 OpenSSH Server、把連線限制在區網、設定 SSH 金鑰（免密碼）登入並硬化。伺服器端指令請在系統管理員權限的 PowerShell 中執行。

用戶端（macOS / Linux）的金鑰產生、~/.ssh/config、傳檔與除錯，另見 SSH 用戶端設定與速查。

佔位符：

  • <SERVER_IP>：伺服器在區網的 IP（例如 192.168.1.100）
  • <USERNAME>：要登入的 Windows 使用者帳號
  • <PUBLIC_KEY_LINE>：用戶端公鑰 .pub 的整行內容

1. 安裝 OpenSSH Server​

方法 A：Windows 內建選用功能（優先嘗試）​

GUI：設定 → 應用程式 → 選用功能 → 新增功能，搜尋 OpenSSH，勾選 「OpenSSH 伺服器」（注意是伺服器 Server，不是用戶端 Client）。

或用 PowerShell：

# 查看目前狀態
Get-WindowsCapability -Online | Where-Object Name -like 'OpenSSH*'

# 安裝 Server
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0

方法 B：官方獨立安裝包（當方法 A 失敗時）​

若方法 A 出現錯誤碼 0x800f0950（詳見常見問題），或選用功能清單裡找不到「OpenSSH 伺服器」，改用微軟官方 Win32-OpenSSH 獨立安裝包，功能完全相同：

winget install --id Microsoft.OpenSSH.Preview --exact --source winget `
  --accept-package-agreements --accept-source-agreements

安裝後路徑為 C:\Program Files\OpenSSH，並會自動註冊 sshd 與 ssh-agent 服務。

2. 啟動並設定服務​

GUI：Win + R → services.msc → 找 「OpenSSH SSH Server」 → 右鍵內容 → 啟動類型「自動」→ 按「啟動」。

或用 PowerShell：

# 設為開機自動啟動並立即啟動
Set-Service -Name sshd -StartupType Automatic
Start-Service sshd
Set-Service -Name ssh-agent -StartupType Automatic

# 確認狀態（應為 Running）
Get-Service sshd, ssh-agent | Select-Object Name, Status, StartType

確認 sshd 正在監聽連接埠 22：

Get-NetTCPConnection -LocalPort 22 -State Listen

提示：若用戶端 22 埠不通，最常見的兩個原因是 (1) sshd 服務沒啟動、(2) 網路設定檔是「公用網路」被防火牆擋。請確認網路設定檔為 「私人網路」（設定 → 網路和網際網路 → 你的連線 → 網路設定檔 → 私人）。

3. 將連線限制在區網​

預設防火牆規則允許來自任何位址（含網際網路方向）的連線。以下把來源限縮為 LocalSubnet（僅本機所在區網），避免對外曝露。

# 建立（或確保存在）僅允許區網的輸入規則
$rule = Get-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -ErrorAction SilentlyContinue
if (-not $rule) {
    New-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -DisplayName 'OpenSSH Server (sshd)' `
        -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
}

# 將所有開放 TCP 22 的輸入規則來源限縮為區網
Get-NetFirewallPortFilter -Protocol TCP |
    Where-Object LocalPort -eq 22 |
    Get-NetFirewallRule |
    Where-Object { $_.Direction -eq 'Inbound' -and $_.Action -eq 'Allow' } |
    Set-NetFirewallRule -RemoteAddress LocalSubnet

驗證來源範圍已變為 LocalSubnet：

Get-NetFirewallPortFilter -Protocol TCP |
    Where-Object LocalPort -eq 22 |
    Get-NetFirewallRule |
    ForEach-Object { "{0} => {1}" -f $_.DisplayName, (($_ | Get-NetFirewallAddressFilter).RemoteAddress -join ', ') }

效果：同區網裝置可連入；網際網路方向與跨子網一律被防火牆擋下。即使路由器誤設連接埠轉發，本機防火牆仍會擋住外部來源。

4. 設定金鑰登入​

步驟 1：在用戶端產生金鑰對​

在你要用來連線的那台電腦（用戶端）執行（詳見 SSH 用戶端設定與速查）：

ssh-keygen -t ed25519 -C "my-ssh-key"
  • 產生私鑰（留在用戶端，絕不外流）與公鑰 .pub（可安全提供給伺服器）。
  • 複製公鑰整行內容備用（cat ~/.ssh/金鑰名.pub）。

步驟 2：把公鑰安裝到伺服器​

Windows 重點：公鑰要放哪裡取決於帳號類型。

  • 一般使用者：C:\Users\<USERNAME>\.ssh\authorized_keys
  • 系統管理員帳號：必須放在 C:\ProgramData\ssh\administrators_authorized_keys，且權限只能給 SYSTEM 與 Administrators，否則登入會失敗。

一般個人桌機的主帳號通常是系統管理員，多半要走管理員那條。

自動判斷帳號類型並寫入對的位置（在伺服器 PowerShell 整段貼上，先把 <PUBLIC_KEY_LINE> 換成你的公鑰整行）：

$pubkey = '<PUBLIC_KEY_LINE>'
$admin = ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
if ($admin) {
    $akf = 'C:\ProgramData\ssh\administrators_authorized_keys'
    Add-Content -Path $akf -Value $pubkey -Encoding ascii
    # 嚴格 ACL：關閉繼承，只授權 Administrators 與 SYSTEM（用 SID 避免語系差異）
    icacls $akf /inheritance:r /grant '*S-1-5-32-544:F' /grant '*S-1-5-18:F' | Out-Null
} else {
    New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh" | Out-Null
    $akf = "$env:USERPROFILE\.ssh\authorized_keys"
    Add-Content -Path $akf -Value $pubkey -Encoding ascii
}
Write-Host "已寫入: $akf"
  • 使用 -Encoding ascii 寫入可避免 BOM 破壞金鑰檔的第一行。
  • authorized_keys 的變更不需重啟服務即時生效。

系統管理員金鑰檔的對應設定，預設已存在於 C:\ProgramData\ssh\sshd_config：

Match Group administrators
       AuthorizedKeysFile __PROGRAMDATA__/ssh/administrators_authorized_keys

5. 關閉密碼登入（硬化）​

⚠️ 務必先確認金鑰登入成功，再關閉密碼登入，否則可能把自己鎖在門外。

編輯 C:\ProgramData\ssh\sshd_config，在全域區段（任何 Match 區塊之前）設定：

PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no

用 PowerShell 自動套用（會先備份設定檔）：

$cfg = 'C:\ProgramData\ssh\sshd_config'
Copy-Item $cfg "$cfg.bak" -Force

$c = Get-Content $cfg -Raw
$c = $c -replace '(?m)^\s*#?\s*PubkeyAuthentication\s+\w+',       'PubkeyAuthentication yes'
$c = $c -replace '(?m)^\s*#?\s*PasswordAuthentication\s+\w+',     'PasswordAuthentication no'
if ($c -match '(?m)^\s*#?\s*KbdInteractiveAuthentication\s+\w+') {
    $c = $c -replace '(?m)^\s*#?\s*KbdInteractiveAuthentication\s+\w+', 'KbdInteractiveAuthentication no'
} else {
    $c = $c -replace '(?m)^(Match\s)', "KbdInteractiveAuthentication no`r`n`r`n`$1"
}
[System.IO.File]::WriteAllText($cfg, $c, (New-Object System.Text.UTF8Encoding($false)))

Restart-Service sshd

驗證生效中的設定：

& 'C:\Program Files\OpenSSH\sshd.exe' -T |
    Select-String -Pattern '^(passwordauthentication|pubkeyauthentication|kbdinteractiveauthentication)\b'

預期輸出：

pubkeyauthentication yes
passwordauthentication no
kbdinteractiveauthentication no

選用：登入後預設進入 PowerShell​

Windows OpenSSH 預設登入後為 cmd。若想改為 PowerShell：

New-ItemProperty -Path 'HKLM:\SOFTWARE\OpenSSH' -Name DefaultShell `
    -Value 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe' `
    -PropertyType String -Force

6. 常見問題​

錯誤 0x800f0950（CBS_E_NO_OPTIONAL_CONTENT_FOUND_FOR_BUILD）​

安裝內建 OpenSSH Server（方法 A）時可能出現。原因是選用功能（FOD）的版本與目前系統組建不符：系統已透過累積更新升級，但 Windows Update 上找不到符合此組建的 OpenSSH FOD 內容。這是微軟端的內容比對問題，與本機權限、網路、WSUS 設定無關。

解法：改用方法 B的官方獨立安裝包，可完全繞過 FOD／Windows Update 機制。

診斷用：

Select-String -Path "$env:windir\Logs\CBS\CBS.log" -Pattern '800f0950|OpenSSH' | Select-Object -Last 20

選用功能清單裡沒有「OpenSSH 伺服器」可勾​

部分組建的清單只顯示 Client、抓不到 Server。純 GUI 無解，改用方法 B或方法 A 的 PowerShell 指令直接安裝。

用戶端連不上 / 22 埠不通​

依序檢查：

  1. sshd 服務是否 Running（Get-Service sshd）。
  2. 22 埠是否在監聽（Get-NetTCPConnection -LocalPort 22 -State Listen）。
  3. 網路設定檔是否為「私人」（公用網路預設擋 inbound）。
  4. 防火牆是否有放行 22 的輸入規則。
  5. 兩台是否在同一區網（用戶端 ping <SERVER_IP>；注意 Windows 預設擋 ICMP，ping 不通不代表主機沒開）。

金鑰登入仍要求輸入密碼 / 被拒​

Windows 系統管理員帳號最常見的原因：

  1. 公鑰放錯位置——管理員帳號必須放 C:\ProgramData\ssh\administrators_authorized_keys。
  2. administrators_authorized_keys 權限過寬——只能給 SYSTEM 與 Administrators（見步驟 2）。
  3. 金鑰檔含 BOM 或換行有誤——用 -Encoding ascii 重新寫入。

從用戶端用 verbose 排查：ssh -v <USERNAME>@<SERVER_IP>。

空白密碼帳號無法用密碼登入​

Windows 預設原則會阻擋空白密碼帳號的網路登入（含 SSH）。請改用金鑰登入（不需帳號密碼），或先為帳號設定密碼。

更新 OpenSSH（獨立安裝包）​

winget upgrade --id Microsoft.OpenSSH.Preview

重啟服務Restart-Service sshd
