從手機瀏覽器安全遠端操作「容器內的 Claude Code CLI」

把跑在 Docker 容器裡的 Claude Code CLI，從手機瀏覽器遠端操作。 滿足三條件：① 本機不開 inbound port、不裝對外 webserver ② 手機不裝任何 app（只用瀏覽器）③ 資安至上。 最後更新：2026-07。

目錄：§0 需求｜§1 架構｜§2 安全前提｜§3 需要準備｜§4 步驟（Step 1–6）｜ §5 安全檢查表｜§6 替代方案｜§7 一頁速查

0. 需求與限制​

  1. 本機不開 inbound port、不裝對外 webserver。
  2. 手機不裝任何 app，只用瀏覽器。
  3. 資安至上。

1. 為什麼是這個架構​

  • 手機只用瀏覽器 → 需要一個 web 終端機。
  • 不開 inbound port → 本機不能對外監聽，只能靠本機主動外撥的 tunnel；網頁 UI 由可信第三方（Cloudflare）邊緣托管。
  • VPN 類（Tailscale / WireGuard）最安全，但手機要裝 app，違反條件 → 排除。

結論：Cloudflare Tunnel（外撥）+ Cloudflare Access（邊緣身分 + MFA）+ 容器內 ttyd（不對外）+ tmux（連線持久化）。

手機瀏覽器
   │  HTTPS
   ▼
Cloudflare 邊緣  ── Access 認證 + MFA（不通過就到不了你的機器）
   │  tunnel（由你的機器外撥建立，無 inbound port）
   ▼
cloudflared（外撥連接器）
   │  localhost
   ▼
ttyd  ──  tmux  ──  claude   （都在容器內，ttyd 不對外發佈）

2. ⚠️ 安全前提（務必先讀）​

  • 若容器掛了 /var/run/docker.sock（DooD 模式），遠端進到這個 shell ≈ 拿到宿主 root，blast radius 很大 →
    • MFA 一定要開；
    • 不要用「祕密網址即密碼」型方案（如裸 Quick Tunnel / sshx）守這種容器；
    • 用完可關閉 connector。
  • ttyd 不對外發佈：不要在 docker 給它做 ports: 對外映射；唯一入口是經過 Access 認證的 Cloudflare 邊緣。
  • hostname 是公開的（Certificate Transparency log）→ 安全靠 Access，不靠名字保密；用中性名字。
  • CF_TUNNEL_TOKEN 視同密碼，且它以 env 注入 cloudflared 容器 → 同一台宿主上任何拿得到 docker socket 的人/容器，docker inspect <cloudflared 容器> 就能明文讀到 token（拿到 token ≈ 可以在任何機器冒充你的 connector）。因此：.env 不進版控（加 .gitignore）；同宿主還有其他 掛 socket 的專案/容器時，認知 token 對它們是可見的——docker socket 沒有租戶概念，要真正 隔離只能給每個專案獨立的 daemon（或以 socket 過濾代理縮小可用 API 面）； 疑似外洩就到 Zero Trust 把該 tunnel 的 token rotate／刪除重建。

3. 需要準備​

  • 一個掛在 Cloudflare 的網域（沒有的話可申請免費的 eu.org 網域：nic.eu.org 註冊 → NS 委派到 Cloudflare；審核需數天到數週）。
  • Cloudflare 帳號 + 開啟 Zero Trust（免費方案即可）。
    • ⚠️ 開通時可能要你選方案(Free) + 掛一張付款方式；Free 在 ≤50 seats 是 $0（seat 以「不重複的認證身分」計，個人自用＝1；把 Access policy 鎖死自己的 email 就不會超量、不會被扣）。
  • ⚠️ 網域要先在 Cloudflare 變 Active（NS 已委派）才能設 Public Hostname / Access。 若用的是剛申請、還在等審核委派的 eu.org 網域，這兩步要等 Active 後才做得了；其餘（裝 ttyd、建 tunnel 拿 token、跑 cloudflared）可以先做。
  • 你的 Claude Code 容器（本文以 compose 服務名 claude 代稱）。
  • 範例 hostname：cli.yourname.eu.org。

4. 步驟​

Step 1 — 容器內安裝 ttyd + tmux​

Debian/Ubuntu base 的 Dockerfile：

RUN apt-get update && apt-get install -y --no-install-recommends \
      ttyd tmux \
 && rm -rf /var/lib/apt/lists/*

（或進容器手動 apt-get install ttyd tmux。並確認 claude 指令可用。）

註：這些工具必須在容器內。

  • 改 Dockerfile 後要 rebuild 一次才生效；若該容器正在跑，rebuild 會重啟它。
  • 沒有 root / 不想 rebuild 時：ttyd 是單一靜態 binary，一般使用者就能下載到家目錄直接跑 （curl -fsSL https://github.com/tsl0922/ttyd/releases/latest/download/ttyd.$(uname -m) -o ~/ttyd && chmod +x ~/ttyd），tmux 也有靜態版。
  • 建 tunnel / 跑 cloudflared 不需要這步——只有「手機要真的看到終端機」才需要 ttyd+tmux；沒有它，tunnel 連上了也只會回 502。

Step 2 — 跑 ttyd，接上 tmux + claude​

在容器內：

ttyd -p 7681 -W tmux new -A -s claude claude
  • -p 7681：監聽埠（只在容器內；只要不對 host 做 ports: 映射，外部就碰不到）。
  • -W：允許輸入（可操作，不是唯讀）。
  • tmux new -A -s claude claude：附掛或建立名為 claude 的 tmux session，裡面跑 claude；手機斷線重連，session 還在。
  • 額外防護（可選）：
    • 若你的 ttyd 支援，加 -i 127.0.0.1 只綁回環介面。
    • 加一層 basic auth：-c user:pass（Access 已是主要關卡，這是 defense in depth）。

重點：安全來自「不對外發佈這個埠」+ Access 認證，不是來自 ttyd 本身。

💡 容器重啟後 ttyd 不會自己回來（它不是容器主行程）。可從宿主一行補起（重複執行也安全，已在跑就跳過）：

docker compose exec claude sh -c 'pgrep -x ttyd >/dev/null' \
  || docker compose exec -d claude ttyd -i 127.0.0.1 -p 7681 -W tmux new -A -s claude claude

Step 3 — 建 Cloudflare Tunnel（外撥連接器）​

用 Zero Trust 儀表板（最簡單）：

  1. Cloudflare Zero Trust → Networks → Tunnels → Create a tunnel → 選「cloudflared Tunnel」。
    • ⚠️ 不要選 WARP Connector（那是私網/裝置對裝置、要裝 client app，不符需求）。
  2. 命名（如 claude-cli）→ Save。畫面會給你一段含 token 的安裝指令（如 docker run ... --token eyJ...）。那段不用照跑——只要複製 --token 後面那串 token，填進 .env 的 CF_TUNNEL_TOKEN=（由下方 compose 使用；.env 記得加 .gitignore，token 保管注意事項見 §2）。
  3. 在與 ttyd 同一個 localhost 的地方跑這個 connector（最簡單就是跟 claude 同容器，或共用網路命名空間）： 
    cloudflared tunnel run --token <TOKEN>
  4. 回儀表板，在該 tunnel 的 Public Hostname 新增一筆：
    • Subdomain：cli，Domain：yourname.eu.org（→ cli.yourname.eu.org）
    • Type：HTTP，URL：localhost:7681
    • （WebSocket 預設支援，ttyd 需要它，不必額外設定）
    • ⚠️ 要找對地方：是 Public Hostname，不是「CIDR routes / Hostname routes (Beta)」也不是左側那個私網 Routes / WARP——那些是私有網路/裝置路由，與此無關。
    • ⚠️ 網域沒 Active 就設不了：若下拉選不到 yourname.eu.org，代表 zone 還沒 Active（如 eu.org 還在審核委派）→ 正常，等 Active 再回來加這筆。

docker-compose 範例（cloudflared 與 claude 容器共用網路命名空間，讓 localhost:7681 互通；ttyd 永不對外）：

services:
  claude:
    # ...你原本的 claude 容器...
    # 注意：不要對 7681 做 ports: 映射
    # 長駐遠端目標建議成對加：
    #   restart —— 主機重開後自己回來。cloudflared 雖有 restart，但 network_mode 的目標
    #              容器不在就起不來 → 主容器沒有 restart 的話，重開機後遠端路線死透等人救。
    #   init    —— PID1 掛 tini：ttyd/tmux 長駐會產孤兒行程，沒人收屍會愈積愈多。
    restart: unless-stopped
    init: true

  cloudflared:
    image: cloudflare/cloudflared:latest
    profiles: ["remote"]               # 平常不啟動，要遠端時才開
    command: tunnel run --token ${CF_TUNNEL_TOKEN}
    network_mode: "service:claude"     # 與 claude 共用 localhost
    restart: unless-stopped
    depends_on: [claude]

cloudflared 只對外撥號，本機完全不需要開任何 inbound port。 放在 remote profile → 隨用隨開：docker compose --profile remote up -d cloudflared，用完 docker compose stop cloudflared。

⚠️ 重開陷阱：network_mode: service:claude 在「建立當下」綁死的是 claude 的容器 ID——claude 一旦重建（改 compose 設定、rebuild image），ID 就變了，舊的 cloudflared 永遠接不回來（start 會直接失敗）。復原：

docker compose --profile remote up -d --force-recreate cloudflared

建議把「重開後復原」包成一支冪等腳本（起 claude → 比對 ID、必要時重建 cloudflared → 確保 ttyd 在跑），任何重開情境都跑同一支就好。

Step 4 — 用 Cloudflare Access 保護它（身分 + MFA）​

  1. Zero Trust → Access → Applications → Add an application → Self-hosted。
  2. Application domain：cli.yourname.eu.org。
  3. Identity provider / 登入方式：
    • 最簡單：One-time PIN（email 收一次性驗證碼）。
    • 更強：接 Google / GitHub，並在該帳號開 2FA → 等同 MFA（推薦）。
  4. Policy：Action = Allow，Include = Emails → 你的 email（只有你進得來）。
  5. 建議：Session Duration 設短（如 24h 或更短）；可加 Require → MFA。
  6. 儲存。

Step 5 — 手機使用​

  1. 手機瀏覽器開 https://cli.yourname.eu.org。
  2. 跳出 Cloudflare Access 登入 → 過 SSO / MFA。
  3. 進入 ttyd 網頁終端 → 就是容器內那個 tmux session 裡的 claude。
  4. 切 app、關瀏覽器、換網路都沒關係 → tmux 保住 session，下次連回繼續。

Step 6 — 用完關閉 / 隨用隨開 / 重開復原​

  • 關門：docker compose stop cloudflared → 外部立刻無法連入（tunnel 斷），容器內的 tmux + claude 照常活著。
  • 開門：docker compose --profile remote up -d cloudflared。
  • 主容器重開後復原：補起 ttyd（Step 2 的提示）；若 claude 是「重建」而非單純重啟，cloudflared 需 --force-recreate（Step 3 的重開陷阱）。

5. 安全檢查表​

  • ttyd 的埠沒有對 host 做 ports: 對外映射。
  • ttyd 以 -i 127.0.0.1 只綁回環介面（defense in depth）。
  • 本機沒有開 inbound port、沒有對外 webserver（只有 cloudflared 外撥）。
  • Cloudflare Access 已套在 cli.yourname.eu.org，且 只允許你的 email。
  • 登入用 MFA（接 Google/GitHub 2FA）或至少 One-time PIN。
  • 清楚 hostname 是公開的（CT log），安全靠 Access 而非名字保密。
  • [ ]（DooD 容器）認知遠端 shell ≈ 準宿主 root → 更要嚴管、用完關閉。
  • .env（CF_TUNNEL_TOKEN）已加 .gitignore；知悉同宿主任何掛 socket 的容器都能 docker inspect 讀到此 token，疑洩漏就 rotate。
  • 主容器有 restart: unless-stopped＋init: true（重開機後遠端路線自動復活； 復原重建情境用 Step 3/6 的冪等腳本）。

6. 替代方案（取捨速查）​

方案免網域認證加密適用
Cloudflare Tunnel + Access（本教學）❌ 需網域身分 + MFA（邊緣擋）TLS（經 CF）資安至上、要最強的把關
VS Code code tunnel✅GitHub/MS OAuth(+MFA)TLS（經 MS）不想弄網域、想順便有編輯器；瀏覽器開 vscode.dev 內含終端
sshx✅祕密 URL（bearer）端到端 E2E臨時、低風險；掛了 docker.sock 的容器不建議
Tailscale 等 VPN✅裝置授權WireGuard E2E最安全，但手機要裝 app（違反本需求）

想「免網域、免等審核、又要 MFA」最快的折衷：code tunnel。

7. 一頁速查（日常操作）​

# 開門（要遠端時）
docker compose --profile remote up -d cloudflared

# 關門（用完；tmux + claude 照常活著）
docker compose stop cloudflared

# 補起 ttyd（容器重啟後它不會自己回來；冪等，已在跑就跳過）
docker compose exec claude sh -c 'pgrep -x ttyd >/dev/null' \
  || docker compose exec -d claude ttyd -i 127.0.0.1 -p 7681 -W tmux new -A -s claude claude

# 主容器「重建」後（ID 變了）：cloudflared 必須強制重綁
docker compose --profile remote up -d --force-recreate cloudflared
症狀 → 原因速查：
  手機開網址 502           → ttyd 沒在跑（補起 ttyd）
  cloudflared 起不來/秒退  → 主容器重建過，network_mode 綁死舊 ID（--force-recreate）
  Access 登入後轉圈圈      → tunnel 沒連上（看 cloudflared logs）；或 Public Hostname 的
                             URL 不是 localhost:7681
  下拉選不到網域           → zone 還沒 Active（NS 委派未生效，等）

建議把前三項包成一支冪等腳本（起主容器 → 比對 ID、必要時重建 cloudflared → 確保 ttyd 在跑）， 任何重開情境都跑同一支（Step 3 的建議）。
