ngrok

把本機的某個 port 接到一個公開的 HTTPS 網址。註冊就有一個固定的網址（dev domain），只有一個服務要對外時最省事。 怎麼選、通道接哪個 port、怎麼驗有沒有通、接 LINE webhook，見總覽。 最後更新：2026-11，依官方文件整理。後台的選單名稱常改，下面一律附網址，找不到選單就直接開網址。

0. 跟舊教學不一樣的地方​

網路上很多教學是舊版的，照著做會卡住：

舊教學寫的現在
免費版每次開都是隨機網址每個帳號（含免費）自動配一個 dev domain，例如 <系統取的名字>.ngrok-free.dev（也有帳號是 .ngrok-free.app）。名字由 ngrok 決定、不能改，重開也不會變
要固定網址得加 --domain=...免費帳號 ngrok http 3000 就自動用 dev domain；要指定網址用 --url。--domain、--hostname、--subdomain 都已棄用
--basic-auth、--oauth、--host-header、加減 header 的參數都棄用了，改寫在 Traffic Policy（--traffic-policy-file policy.yml）
--region jp 選地區棄用，自動選延遲最低的
設定檔 version: "2"＋tunnels:version: 3＋agent:＋endpoints:。官方說 tunnels: 2025 年底移除；舊檔可以用 ngrok config upgrade 轉（會留備份）
免費版開一陣子會斷線官方寫免費的 endpoint 沒有時間限制，可以一直開著

1. 安裝、登入​

  1. 註冊：dashboard.ngrok.com/signup
  2. 安裝：
# macOS（官方用 Homebrew）
brew install ngrok

# Debian／Ubuntu（官方的 apt 套件庫）
curl -sSL https://ngrok-agent.s3.amazonaws.com/ngrok.asc \
  | sudo tee /etc/apt/trusted.gpg.d/ngrok.asc >/dev/null \
  && echo "deb https://ngrok-agent.s3.amazonaws.com buster main" \
  | sudo tee /etc/apt/sources.list.d/ngrok.list \
  && sudo apt update \
  && sudo apt install ngrok

# Windows：Microsoft Store 搜尋 ngrok；其他平台：https://ngrok.com/download
ngrok version

Windows 的防毒軟體可能把 ngrok 當成病毒。官方說：檔案有 ngrok 的數位簽章就是誤判。

  1. 拿 authtoken：dashboard.ngrok.com/get-started/your-authtoken，一台電腦設一次：
ngrok config add-authtoken <你的 authtoken>
ngrok config check      # 檢查設定檔，並印出它放在哪
  • 設定檔位置：macOS ~/Library/Application Support/ngrok/ngrok.yml、Linux ~/.config/ngrok/ngrok.yml、Windows %LocalAppData%\ngrok\ngrok.yml。
  • 容器、CI 裡不想寫檔：用環境變數 NGROK_AUTHTOKEN（會蓋過設定檔）。

authtoken 等於你的帳號：不要貼在公開的地方。不小心貼了，到同一頁重設一組。

2. 開一條​

ngrok http 3000
  • 免費帳號會自動用你的 dev domain。自己的 dev domain 在 dashboard.ngrok.com/domains 看得到。
  • 後台給的範例指令可能寫成 ngrok http 3000 --url https://<你的 dev domain>，效果一樣。
  • 畫面上 Forwarding 那一行就是公開網址。
  • Ctrl+C 關掉，網址就打不通了；dev domain 還是你的，下次開又是同一個。

3. 看請求、除錯​

ngrok 開著的時候，瀏覽器打開 localhost:4040：

  • 每一個請求、回應都看得到：時間、花多久、來源 IP、header、query、body。
  • Replay：同一個請求再送一次，不用回 LINE 或金流的後台重新觸發。
  • Replay with Modifications（Replay 按鈕旁的下拉）：先改 method、路徑、header、body 再送。
  • localhost:4040/status：endpoint 的設定、請求數、回應時間。
  • 只有 HTTP 的 endpoint 看得到（TCP、TLS 沒有）。

要保留久一點，用後台的 Traffic Inspector（dashboard.ngrok.com/traffic-inspector）：要先對 endpoint 開啟，能存多久依方案而定。

常見的錯誤頁：

  • ERR_NGROK_8012：通道有開，但本機那個 port 沒有程式在聽（或 port 打錯）。先 curl http://localhost:3000 看看。
  • ERR_NGROK_3200：這個網址現在沒有 endpoint 在線上，也就是 ngrok 沒在跑。

webhook 驗簽一直失敗：在 4040 看 LINE 送來的原始內容，改完程式按 Replay，不用一直回 LINE 後台按 Verify。 其他狀態碼怎麼看，見總覽 §3。

4. 限制​

官方的免費方案表（2026-11 整理；會變，以官方頁為準）：

項目免費
網域dev domain 1 個（自動配、不能改名）；不能用自己的網域
同時在線的 endpoint最多 3 個
同時跑的 agent3 個
流量每月 1 GB（往外送的）
HTTP 請求每月 20,000 個；每分鐘 4,000 個
開多久沒有限制

每月 2 萬個請求，webhook 用不完，開網頁就難講：開發伺服器（例如 Vite）的程式沒有打包，開一頁就可能送出幾百個請求。

瀏覽器警告頁（ERR_NGROK_6024）

  • 免費方案用瀏覽器打開網頁之前，會先跳一頁 ngrok 的警告；按 Visit 之後，同一個網域 7 天內不再跳。
  • webhook、API 這種程式打的請求不受影響。
  • 自己的程式要跳過：送 ngrok-skip-browser-warning header（值隨便填），或用非一般瀏覽器的 User-Agent。
  • 手機裡開網頁（LIFF、OAuth 回呼）每台手機第一次都會看到這頁。不想要就付費，或改用 cloudflared、自架中繼。

5. 好幾個服務​

免費只有一個 dev domain。好幾個 endpoint 掛在同一個網址上叫做 pooling：ngrok 會在它們之間輪流分配流量（給同一個服務開好幾份用），不是分給不同的服務。

要讓不同的服務共用 dev domain，官方的做法是 internal endpoint＋Traffic Policy 照路徑轉：

# 第二個服務：開成 internal endpoint（.internal 結尾）。外面打不到，只收 ngrok 內部轉過來的
ngrok http 4000 --url https://app2.internal

# 公開的那條（dev domain）：預設給 3000，/app2 開頭的轉去 app2.internal
ngrok http 3000 --traffic-policy-file policy.yml

policy.yml：

on_http_request:
  - expressions:
      - req.url.path.startsWith('/app2')
    actions:
      - type: forward-internal
        config:
          url: https://app2.internal
  • 路徑不會被拿掉：第二個服務收到的還是 /app2/...，它的路由要認得這個開頭。
  • 照路徑分的那一邊只適合 webhook、API；網頁會壞：網頁裡的檔案多半用根目錄起算的路徑（/assets/...），會被送到第一個服務去。
  • 這組寫法是照官方文件（Route Requests、forward-internal、internal endpoints）組起來的，還沒實測。官方的免費方案表沒有說 internal endpoint 要付費。
  • 不想弄這些：用 cloudflared 的臨時通道，一個服務開一條、各有自己的網址（見 Cloudflare Tunnel §5）。

6. 固定網址與設定檔​

dev domain 本身就是固定的：webhook 後台填一次就好。要用自己的網域、自己挑名字，要付費方案；不想付費可以自架中繼（自己開一台免費 VM，DNS 不用搬）。

開好幾條、帶 Traffic Policy 時，寫成設定檔比較好管（ngrok config edit 直接打開）。§5 那一組寫成設定檔：

version: 3
agent:
  authtoken: <你的 authtoken>
endpoints:
  - name: app1
    # 沒寫 url：用 dev domain
    upstream:
      url: 3000
    traffic_policy:
      on_http_request:
        - expressions:
            - req.url.path.startsWith('/app2')
          actions:
            - type: forward-internal
              config:
                url: https://app2.internal
  - name: app2
    url: https://app2.internal
    upstream:
      url: 4000
ngrok start --all       # 全部開
ngrok start app1        # 只開一條
  • 舊的 v2 設定檔：先 ngrok config upgrade --dry-run 看會改成什麼，再拿掉 --dry-run 真的轉（會留備份）。
  • 設定檔裡有 authtoken：不要放進 git。

7. 開機自動跑​

ngrok service install --config <設定檔路徑>
ngrok service start

裝好之後效果等於 ngrok start --all。停掉、拿掉：ngrok service stop、ngrok service uninstall。

8. ngrok 特有的坑​

  • 用 Homebrew、apt 裝的，就用它們更新（brew upgrade ngrok）。ngrok update 是給直接下載安裝的；官方說用套件管理工具裝的不要跑它。
  • 舊的設定檔（tunnels:）不能用了：用 ngrok config upgrade 轉成 v3。
  • 環境變數 NGROK_AUTHTOKEN 會蓋過設定檔：換了帳號卻一直登到舊的，先查這個變數是不是還設著。
  • 免費網域的警告頁、每月 2 萬個請求：只收 webhook 沒差；要開網頁先看 §4。
