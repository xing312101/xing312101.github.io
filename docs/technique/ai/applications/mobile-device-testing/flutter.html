Flutter：用 integration_test 讓測試自己截圖

如果 App 是 Flutter 寫的，有一條不需要 adb 或 WebDriverAgent 的路： 寫一支 integration_test，讓 App 在實機上自己點、自己截圖。 適合「每次改版都要重拍同一批畫面」這種固定流程 —— 例如上架商店的截圖。

1. 它能做什麼、不能做什麼​

integration_test 截圖adb／WebDriverAgent
可重複執行、放進 CI✅⚠️ 要另外寫腳本
用 widget 找元素（find.text、find.byKey）✅ 不怕座標跑掉❌ 靠 UI 樹或座標
截到系統畫面（來電、推播、權限框、通知列）❌ 只截得到 Flutter 畫的那一層✅
截到原生 view（地圖、WebView、相機預覽）⚠️ 常常是黑的或空的✅
兩支手機互動❌✅
臨時排查、探索性操作❌ 要先寫程式✅

結論：固定的 App 內畫面用它；系統畫面、跨裝置、臨時操作用 adb／WDA。

2. 寫法​

2.1 driver：把截圖寫成檔案​

test_driver/integration_test.dart
import 'dart:io';
import 'package:integration_test/integration_test_driver_extended.dart';

Future<void> main() async {
  await integrationDriver(
    onScreenshot: (String name, List<int> bytes, [Map<String, Object?>? args]) async {
      final dir = Directory(Platform.environment['SCREENSHOT_OUT_DIR'] ?? 'build/screenshots');
      if (!dir.existsSync()) dir.createSync(recursive: true);
      File('${dir.path}/$name.png').writeAsBytesSync(bytes);
      return true;
    },
  );
}

2.2 測試：走到畫面再截​

integration_test/screenshots_test.dart
import 'dart:io';

import 'package:flutter_test/flutter_test.dart';
import 'package:integration_test/integration_test.dart';
import 'package:your_app/main.dart' as app;

void main() {
  final binding = IntegrationTestWidgetsFlutterBinding.ensureInitialized();

  testWidgets('主要畫面截圖', (tester) async {
    app.main();
    await tester.pumpAndSettle();
    if (Platform.isAndroid) {
      await binding.convertFlutterSurfaceToImage(); // Android 必須先呼叫一次，否則截圖是空的；iOS 不需要
      await tester.pumpAndSettle();
    }

    await binding.takeScreenshot('01_home');

    await tester.tap(find.text('設定'));
    await tester.pumpAndSettle();
    await binding.takeScreenshot('02_settings');
  });
}

2.3 執行​

SCREENSHOT_OUT_DIR=build/screenshots/phone \
flutter drive \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/screenshots_test.dart \
  -d <裝置 ID>

2.4 判斷這次跑得成不成功​

截圖是「最後才一次寫出」的

integrationDriver 在整個測試結束時才把所有截圖一次傳回電腦。 中途 VM service 斷線（手機休眠、App 被系統殺掉）的話，前面截的全部都不會寫出來， 資料夾可能是空的，也可能留著上一次的舊檔。

所以不要用「資料夾裡有幾張圖」判斷成功。在測試最後印一行自己的標記（例如 SHOTS_DONE captured=12）， 有看到這一行才算數；並且每次跑之前先清空輸出資料夾。

另外三個容易出錯的地方：

  • pumpAndSettle() 等不到結束。畫面上有不會停的動畫（轉圈、循環播放）時，它會一直等到逾時失敗。 這類畫面改用 await tester.pump(const Duration(seconds: 2)); 固定等一段時間。

  • 找不到元素就跳過的寫法會默默少截。為了不讓一張失敗拖垮整批，常會把每一張包在 try/catch 裡， 結果 finder 寫錯（例如文字打錯一個字）時，那張永遠被當成「今天沒資料」跳過。定期打開實際的圖檢查。

  • 截出來的語系可能不對。測試環境不一定套用 App 設定的語系，先看一張確認文字是對的。

3. 實機的限制​

狀況現象處理
iPhone 一次跑多個測試檔只有第一個會跑，其他的報 Unable to start the app on the device，App 看起來卡在啟動畫面實機上一次只跑一個測試檔，用迴圈分別呼叫
iPhone 用無線連線flutter test 拒絕：Cannot start app on wirelessly tethered iOS device接線；或改用 flutter drive ... --publish-port
iPhone 第一次跑卡在 VM Service not discovered after 75s手機會跳「允許尋找區域網路上的裝置」，要按允許（每次重裝都可能再問）
用線接了還是走無線flutter devices 還顯示 (wireless)手機上要先按「信任這部電腦」，接線才會生效
部分 Android 實機測試還沒開始就 VmServiceDisappearedException廠牌省電機制殺掉 debug App 或螢幕鎖定斷線：開「不要鎖定螢幕」、關電池最佳化；或改用模擬器
跑完之後App 被移除了flutter drive 結束時會移除 App。之後還要手動操作的話，重新安裝

4. 平行在多台裝置上跑​

多台裝置同時 flutter drive 會同時建置到同一個 build/ 資料夾而互相破壞。 把建置和執行拆開：建一次，再讓每台裝置用同一份安裝檔跑。

flutter build apk --debug --target=integration_test/screenshots_test.dart
for d in emulator-5554 emulator-5556; do
  flutter drive --driver=test_driver/integration_test.dart \
    --target=integration_test/screenshots_test.dart \
    --use-application-binary=build/app/outputs/flutter-apk/app-debug.apk -d $d &
done
wait

檔名不要用 --dart-define 帶裝置名稱（那是編譯期常數，等於每台都要各建一次）； 改在執行時依螢幕尺寸判斷是手機還是平板，再加在檔名上。
