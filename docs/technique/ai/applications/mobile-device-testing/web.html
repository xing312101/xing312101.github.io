網頁後台：讓 AI 用 Playwright 登入與截圖

App 的測試或簡報常常也需要後台的畫面。網頁是三者裡最好自動化的， 但「登入就失敗」這種問題也最常讓 AI 白忙一場 —— 這一篇的重點在第 3 節。

1. 安裝：借用本機的 Chrome​

python3 -m venv ~/.venvs/pw && ~/.venvs/pw/bin/pip install playwright

指定 channel='chrome' 就會用電腦上已安裝的 Google Chrome，不用再執行 playwright install 下載瀏覽器。

2. 一次執行：登入 → 換頁 → 截圖​

單頁應用（SPA）的登入狀態常常只放在記憶體或 sessionStorage，每次重新開瀏覽器就要重新登入。 最省事的做法是「一次執行做完全部」：

web_tour.py
import asyncio, os, sys
from playwright.async_api import async_playwright

BASE = 'https://app.example.com'

async def main(routes):
    async with async_playwright() as p:
        browser = await p.chromium.launch(channel='chrome', headless=True)
        page = await browser.new_page(viewport={'width': 1440, 'height': 900},
                                      device_scale_factor=2,      # 2 倍解析度，放進簡報才清楚
                                      locale='zh-TW')
        await page.goto(f'{BASE}/#/login', wait_until='networkidle')
        await page.fill('input[type=text]', os.environ['TEST_USER'])        # 帳密從環境變數讀，不要寫死在腳本裡
        await page.fill('input[type=password]', os.environ['TEST_PASSWORD'])
        await page.click('button:has-text("登入")')
        await page.wait_for_timeout(4000)

        for r in routes:                                          # 例如 dashboard orders/list
            await page.goto(f'{BASE}/#/{r}')
            await page.wait_for_timeout(4000)
            await page.screenshot(path=f'web_{r.replace("/", "_")}.png')
            print(r, '->', page.url)                              # 印出實際網址：被導走的話看得出來
        await browser.close()

asyncio.run(main(sys.argv[1:]))
印出實際網址

有權限控管的後台，沒權限的頁面通常會默默導回上一頁或首頁，截出來的是別的畫面。 每張截圖都印出 page.url 跟目標比對，或是把幾張縮圖拼起來看一眼 —— 好幾張長得一模一樣，就是被導走了。

3. 「網路連線異常」：一分鐘找到原因​

登入按下去跳出「網路連線異常」「Network Error」，通常不是網路壞了。先把失敗的請求印出來：

page.on('requestfailed', lambda r: print('FAILED', r.method, r.url, r.failure))
page.on('response', lambda r: print('RESP', r.status, r.request.method, r.url)
        if 'api.' in r.url else None)
看到的結果代表
FAILED ... net::ERR_FAILED，但用 curl 打同一個網址是 200CORS：瀏覽器把回應擋掉了，見下方
FAILED ... net::ERR_NAME_NOT_RESOLVED網域打錯或 DNS 問題
RESP 401帳號密碼錯，或登入流程少了某一步
RESP 5xx伺服器端錯誤，看後端 log

3.1 確認是不是 CORS​

帶上網頁的來源（Origin）打一次 API，看回應有沒有 access-control-allow-origin：

for o in https://example.com https://www.example.com http://localhost:8080; do
  printf '%-28s ' "$o"
  curl -s -D - -o /dev/null -H "Origin: $o" https://api.example.com/token \
    | grep -i 'access-control-allow-origin' || echo '(沒有 → 瀏覽器會擋)'
done

一個很常見的結果：API 只允許 https://example.com，沒有允許 https://www.example.com。 兩個網址打開都是同一個網站，但從 www 進來的使用者永遠登不進去，而且畫面上只會看到「網路連線異常」。

  • 測試當下：改用被允許的那個網址。
  • 根本解法：後端把兩個來源都加進允許清單，或讓其中一個網域整個轉址到另一個。這是值得回報的真實問題。
note

回應裡有 access-control-allow-credentials: true 時，access-control-allow-origin 不能是 *， 必須逐一列出允許的來源 —— 所以「漏掉某個網域」這種錯誤在需要登入的 API 上特別常見。

4. 截圖的個資檢查​

後台的列表頁幾乎一定有姓名、電話、地址。放進文件前：

  • 優先截沒有個資的畫面（主畫面的統計數字、設定頁、空白表單）。
  • 列表頁一定要用時，在測試資料裡建假名字；或截圖後把那幾欄模糊掉。
