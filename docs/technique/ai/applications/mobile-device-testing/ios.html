iOS：讓 AI 用 WebDriverAgent 操作實機

iOS 沒有 adb 這種萬用工具。Apple 開放的自動化入口只有 XCUITest（Xcode 的 UI 測試框架）， 所以要從外部操作 iPhone，做法是在手機上跑一個 XCUITest 寫成的小伺服器 —— WebDriverAgent（WDA）， 再從電腦用 HTTP 叫它截圖、點擊。Appium 的 iOS 驅動底層就是它。

1. 先知道哪些舊方法不能用了​

方法iOS 17 以上說明
idevicescreenshot（libimobiledevice）❌報 Could not start screenshotr service: Invalid service。iOS 17 把開發者服務改走新的通道，舊工具連不上
flutter screenshot（對實機）❌Flutter 工具對新架構的 iOS 實機直接回報不支援截圖
pymobiledevice3 的截圖⚠️支援 iOS 17，但要先建立通道（tunnel），通常需要管理員權限；AI 的 shell 多半沒有 sudo
Xcode → Devices and Simulators → Take Screenshot✅能用，但要人去按，不能自動化
Flutter integration_test 的截圖⚠️能用，但只截得到 App 自己畫的畫面，見 Flutter 篇
WebDriverAgent✅全螢幕、含系統畫面（來電、推播、權限對話框），也能點擊與輸入

2. 裝置管理：devicectl​

Xcode 15 起內建的 devicectl 取代了大部分 libimobiledevice 的功能：

xcrun devicectl list devices
# Name          Identifier                             State                Model
# My iPhone     1A2B3C4D-0000-0000-0000-000000000000   available (paired)   iPhone 13

xcrun devicectl device info apps --device <裝置 Identifier>            # 已安裝的 App 與 bundle ID、版本
xcrun devicectl device install app --device <Identifier> Runner.app
xcrun devicectl device uninstall app --device <Identifier> com.example.app
xcrun devicectl device process launch --device <Identifier> com.example.app
兩種 ID

devicectl 用的是 CoreDevice 的 Identifier（UUID 格式）； xcodebuild -destination 和 iproxy -u 用的是 UDID（例如 00008110-0012345678901234）。 UDID 可以用 idevice_id -l 或 xcrun devicectl device info details --device <Identifier> 查。

3. 建置 WebDriverAgent​

3.1 前提​

  • Xcode 已登入 Apple 開發者帳號（Settings → Accounts），而且該團隊已同意最新版的開發者計畫授權條款（見第 6 節的錯誤對照）。
  • iPhone 已開啟開發者模式、已信任這台電腦，最好用線接。

3.2 下載與建置​

mkdir -p ~/tools && cd ~/tools
git clone --depth 1 https://github.com/appium/WebDriverAgent.git

xcodebuild build-for-testing \
  -project WebDriverAgent/WebDriverAgent.xcodeproj \
  -scheme WebDriverAgentRunner \
  -destination "id=<UDID>" \
  -derivedDataPath ~/tools/wda_build \
  -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration \
  DEVELOPMENT_TEAM=<你的 Team ID> \
  CODE_SIGN_STYLE=Automatic \
  PRODUCT_BUNDLE_IDENTIFIER=com.yourcompany.wda.runner
  • PRODUCT_BUNDLE_IDENTIFIER 換成你團隊底下沒被用過的 ID。預設的 com.facebook.WebDriverAgentRunner 已經被別人註冊，簽不過。
  • 實際裝到手機上的 App 會是 你的ID.xctrunner（Xcode 自動加上這個尾巴）。 所以不能借用某個 App 專用的描述檔，一定要讓 Xcode 用帳號自動產生，或準備萬用（wildcard）描述檔。
  • -allowProvisioningUpdates 讓 xcodebuild 自動註冊 App ID、產生描述檔；-allowProvisioningDeviceRegistration 讓它把還沒登記過的手機也加進團隊。
  • 用免費的個人 Apple ID 也簽得出來，但描述檔 7 天就過期，第一次執行還要在手機上手動信任開發者。團隊帳號比較省事。
  • 只要在模擬器上跑的話，完全不需要簽章，見第 7 節。

3.3 啟動​

xcodebuild test-without-building \
  -xctestrun ~/tools/wda_build/Build/Products/WebDriverAgentRunner_iphoneos*.xctestrun \
  -destination "id=<UDID>" > wda.log 2>&1 &

# 等這一行出現就代表伺服器起來了
grep -m1 ServerURLHere wda.log
# ServerURLHere->http://192.168.1.45:8100<-ServerURLHere

這個指令會一直掛著（測試「執行中」就是伺服器在跑），所以要放到背景。

手機一鎖定，WDA 就停了

測試期間把手機的「自動鎖定」改成「永不」（設定 → 螢幕顯示與亮度），結束後改回來。

3.4 轉接連接埠​

手機和電腦在同一個網路時可以直接連上面那個 IP，但用 USB 轉接比較穩：

iproxy 8100 8100 -u <UDID> &
curl -s localhost:8100/status
# {"value":{"ready":true, ... "os":{"version":"18.7", ...}}, "sessionId": ...}

4. HTTP API：截圖、點擊、輸入​

WDA 講的是 W3C WebDriver 協定，加上一些 /wda/ 開頭的擴充。最常用的幾個：

動作方法與路徑內容
狀態（含目前 sessionId）GET /status
開 App（同時建立 session）POST /session{"capabilities":{"alwaysMatch":{"bundleId":"com.example.app"}}}
截圖（全螢幕，含系統畫面）GET /screenshot回傳 base64 的 PNG
點擊、長按、滑動POST /session/ID/actionsW3C pointer actions（見下方範例）
輸入文字（含中文）POST /session/ID/wda/keys{"value":["中","文"]}；要先點一下輸入框讓它取得焦點
螢幕大小（點）GET /session/ID/window/size拿來算倍率：截圖寬度 ÷ 這裡的寬度
讀 UI 樹GET /source?format=description每個元素的類型、以點為單位的框、label
打開網址POST /session/ID/url{"url":"https://example.com"}
實體按鍵POST /wda/pressButton{"name":"home"}、volumeUp、volumeDown

一支小工具就夠 AI 用了：

ios.py
#!/usr/bin/env python3
"""ios.py launch <bundleId> | shot <out.png> | tap <x> <y> | type <文字> | tree"""
import base64, json, re, sys, urllib.request

B = 'http://localhost:8100'

def req(method, path, body=None):
    data = json.dumps(body).encode() if body is not None else None
    r = urllib.request.Request(B + path, data=data, method=method,
                               headers={'Content-Type': 'application/json'})
    return json.load(urllib.request.urlopen(r, timeout=60))

def sid():
    return req('GET', '/status').get('sessionId') or \
        req('POST', '/session', {'capabilities': {}})['sessionId']

cmd = sys.argv[1]
if cmd == 'launch':
    req('POST', '/session', {'capabilities': {'alwaysMatch': {
        'bundleId': sys.argv[2], 'shouldWaitForQuiescence': False}}})
elif cmd == 'shot':
    open(sys.argv[2], 'wb').write(base64.b64decode(req('GET', '/screenshot')['value']))
elif cmd == 'tap':                       # 座標單位是「點」，不是像素
    x, y = float(sys.argv[2]), float(sys.argv[3])
    req('POST', f'/session/{sid()}/actions', {'actions': [{
        'type': 'pointer', 'id': 'finger', 'parameters': {'pointerType': 'touch'},
        'actions': [{'type': 'pointerMove', 'duration': 0, 'x': x, 'y': y},
                    {'type': 'pointerDown', 'button': 0},
                    {'type': 'pause', 'duration': 80},
                    {'type': 'pointerUp', 'button': 0}]}]})
elif cmd == 'type':
    req('POST', f'/session/{sid()}/wda/keys', {'value': list(sys.argv[2])})
elif cmd == 'tree':
    for line in req('GET', '/source?format=description')['value'].splitlines():
        if re.search(r"label: '[^']+'", line):
            print(line.strip()[:160])
./ios.py launch com.example.app
./ios.py tree
# Button, 0x..., {{262.0, 286.0}, {48.0, 48.0}}, label: '語音通話'
./ios.py tap 286 310          # 框的中心：x = 262 + 48/2，y = 286 + 48/2
./ios.py shot now.png

shouldWaitForQuiescence: False 很重要：有持續動畫的 App（轉圈、跑馬燈）會讓 WDA 一直等「畫面靜止」而卡住。

5. 座標：點 vs 像素​

WDA 的點擊座標是「點」（point），截圖是「像素」，兩者差一個螢幕倍率：

機型截圖寬度（像素）寬度（點）倍率
iPhone 12／13／1411703903
iPhone 15／1611793933
iPhone Pro Max／Plus 系列1284～1320428～4403
iPad（10 代）16408202

從截圖量到的位置要先除以倍率。AI 看到的截圖如果又被縮小過，還要再換算一次（見操作守則第 2 節）。 最省事的做法是從 tree 拿框的中心，那已經是點了。 不確定是哪個機型時，用 GET /session/ID/window/size 取寬度自己算倍率。

實機沒有 Demo Mode，狀態列只能截圖後裁掉：瀏海與動態島機型大約是上方 47～59 點（乘上倍率換成像素）。 另外注意，從別的 App 跳過來時，狀態列左上角會出現「◀ 上一個 App 名稱」的返回連結，也會被截進去。

6. 簽章與建置的常見錯誤​

錯誤訊息原因處理
No Accounts: Add a new account in Accounts settingsXcode 沒有登入 Apple 帳號（帳號可能因為過期或改版被移除）Xcode → Settings → Accounts 重新登入
PLA Update available: ... agree to the latest Program License Agreement開發者計畫有新版條款還沒同意，整個團隊都不能產生新的描述檔由團隊的 Account Holder 登入 developer.apple.com 同意（Admin 也不行）
No profiles for '…xctrunner' were found帳號沒登入或沒權限自動產生描述檔；或你只有某個 App 專用的描述檔先解決上面兩個；不要嘗試借用別的 App 的描述檔，ID 對不上
手機上打不開，顯示「未受信任的開發者」用個人／企業帳號簽的 App 第一次執行手機：設定 → 一般 → VPN 與裝置管理 → 信任
ServerURLHere 一直沒出現手機鎖定、開發者模式沒開、或 test 啟動失敗看 wda.log 最後幾行；手機解鎖後重跑
curl localhost:8100 連不上iproxy 沒開或開錯 UDIDiproxy 8100 8100 -u <UDID>，UDID 不是 devicectl 的 Identifier
原本會動，過一陣子全部沒回應手機自動鎖定自動鎖定改「永不」，重新啟動 WDA

7. 模擬器的捷徑​

如果測的東西不需要實機（不需要相機、推播憑證、通話、真實網路環境），模擬器簡單得多：

xcrun simctl list devices booted
xcrun simctl io booted screenshot shot.png                     # 截圖
xcrun simctl openurl booted 'https://example.com/path'          # 深層連結
xcrun simctl status_bar booted override --time 9:41 --batteryLevel 100 --cellularBars 4   # 乾淨的狀態列（實機做不到）
xcrun simctl push booted com.example.app payload.apns           # 模擬推播
xcrun simctl privacy booted grant camera com.example.app        # 預先授權

點擊一樣要靠 WDA，但模擬器版不需要簽章：把建置指令的 -destination 換成 "platform=iOS Simulator,name=iPhone 16"，並拿掉 DEVELOPMENT_TEAM 等簽章參數即可。模擬器上的 WDA 直接聽 localhost:8100，不用 iproxy。

8. 收尾​

pkill -f 'test-without-building'          # 停掉 WDA
pkill -f 'iproxy 8100'
xcrun devicectl device uninstall app --device <Identifier> com.yourcompany.wda.runner.xctrunner

WDA 留在手機上不會有害，但它會出現在主畫面上，交還手機前移除比較乾淨。

讓人在旁邊看得到

Mac 的 QuickTime Player → 檔案 → 新增影片錄製 → 攝影機選 iPhone，就能把 iPhone 畫面即時鏡像到電腦上， 讓人看著 AI 操作。
