給 AI 的操作守則

工具都裝好之後，剩下的問題幾乎都出在「怎麼操作」。 這一篇整理 AI 操作手機時最常犯的錯，可以直接貼進給 AI 的指示（例如專案的 CLAUDE.md）， 也可以當作人工審核 AI 操作過程時的檢查清單。

1. 基本迴圈：看 → 動 → 再看​

每一個動作之後都要重新觀察一次，不要一次送出一串點擊。

1. 看：讀 UI 樹（優先）或截圖
2. 動：一個點擊 / 一段輸入 / 一次滑動
3. 等：畫面轉場、網路請求（通常 1～5 秒）
4. 再看：確認畫面真的變成預期的樣子，才做下一步

最常見的失敗：

情況會發生什麼
輸入框一點，軟體鍵盤彈出來，版面整個往上推接下來的座標全部點錯
對話框還在動畫中就點點到底下的元素
點了按鈕但 App 還在載入第一次點擊被吃掉，以為按鈕壞了
隱藏鍵盤用 KEYCODE_BACK鍵盤沒開時，BACK 會直接離開目前頁面

2. 座標從哪裡來​

2.1 優先順序​

  1. UI 樹的元素邊界（Android uiautomator dump、iOS WDA /source）→ 取中心點。最準。
  2. 截圖量測 → 換算成裝置座標。只在 UI 樹沒有該元素時使用。
  3. 憑記憶的座標 → 不要用。版面一改就全錯。

2.2 截圖縮放​

AI 看到的截圖常常被縮小過（為了省 token，圖片在送進模型前會被縮到某個上限）。 例如 1080×2340 的截圖，AI 看到的可能是 923×2000。從縮小的圖上量到的座標，要乘回去：

裝置座標 = 圖上座標 × (原始寬度 / 顯示寬度)
例：(460, 995) × 1080/923 ≈ (538, 1164)

有些工具會在圖片旁邊註明縮放比例（例如「Multiply coordinates by 1.17」），有的話直接用。

2.3 iOS 還要再換一次​

WebDriverAgent 的點擊用「點」，截圖是「像素」。iPhone 通常是 3 倍： 像素 ÷ 3 = 點。如果截圖又被縮小過，就是 圖上座標 × 縮放比例 ÷ 3。 詳見 iOS 篇第 5 節。

3. 抓住一閃即逝的畫面​

很多值得截的畫面只出現一兩秒：通話的「撥號中」、提示訊息（Toast 通常 2～4 秒）、「思考中」、轉場中的狀態。

做法：動作之後連拍，事後挑。

adb shell input tap 817 650
for i in 1 2 3 4 5; do sleep 1; adb exec-out screencap -p > burst_$i.png; done

連拍的圖不要一張張讀進來（很佔 context），拼成一張縮圖一起看：

from PIL import Image
ims = [Image.open(f'burst_{i}.png').convert('RGB').resize((300, 650)) for i in range(1, 6)]
sheet = Image.new('RGB', (310 * len(ims), 650), 'white')
for k, im in enumerate(ims):
    sheet.paste(im, (k * 310, 0))
sheet.save('burst_sheet.png')

確認哪一張是要的，再用原始解析度那一張。

4. 先確認「現在登入的是誰」​

AI 拿到一支手機時，App 裡通常已經有人登入了。動手之前：

  • 畫面上顯示的名稱不等於帳號 ID。 「管理員」「王小明」可能是任何一個帳號的顯示名稱。 要寫入資料前，用一個你知道的測試帳號登入比對顯示名稱，或到設定頁找帳號 ID。
  • 只在確認過的測試帳號上做寫入（建立、修改、刪除、送出）。其他帳號一律唯讀。
  • 看似唯讀的操作也可能寫入：打開一則未讀通知會把它標成已讀、進入某些頁面會記錄瀏覽。 只是要截圖的話，挑「已經讀過」的那一則。
  • 不要登出你不知道密碼的帳號。登出之後就登不回去了。需要換帳號時，先照 Android 篇 7.3 備份。

5. 兩支手機的互動情境​

通話、聊天、推播送達這類功能需要兩端。標準配置是一支 Android（adb）＋ 一支 iPhone（WDA），在同一個腳本裡交替操作：

./ios.py tap 286 310                     # iPhone：撥出
sleep 2
./ios.py shot caller.png                 # iPhone：撥號中
adb exec-out screencap -p > callee.png   # Android：來電中
要點說明
哪一端截什麼系統層的畫面（來電通知、鎖定畫面的接聽）只有 adb／WDA 截得到
群組撥號（一次打給多人）群組裡其他裝置可能自動接聽（例如智慧音箱），被叫的那端來不及響。測試時改成點對點撥打，或先讓其他成員離線
同一支手機上裝兩個 App 互打常常行不通：背景的 App 收不到、或音訊裝置互相搶。真的要測就用兩支手機
通話相關的權限麥克風、相機、通知要事先授權（Android 用 pm grant），否則第一通電話會卡在權限對話框

6. 需要聲音的測試​

語音助理、按住說話、語音留言：見語音功能測試。 重點只有兩個：AI 聽不到聲音，第一次要請人確認喇叭有出聲；用「產生檔案 → 播放」比直接用 say 可靠。

7. 換 App、換帳號之前先備份​

要做的事先做事後
把手機上的 App 換成另一個版本pm path + adb pull 備份原本的 APK裝回同一份 APK，比對 versionCode
簽章不同、必須先移除再加上 App 資料備份（debug 版才能做）還原資料，打開 App 確認是原本的帳號
在 App 裡登出換帳號確認知道原帳號的密碼，或先備份資料換回來、確認
改了系統設定（音量、Demo Mode、權限）記下原本的值改回去

把「改了什麼、怎麼還原」記在一份清單裡，結束時逐項打勾。

8. 截圖的整理與個資​

  • 狀態列：裁掉，或用 Demo Mode／模擬器的 status bar override。

  • 通知列、對話框背景、列表頁：會露出其他人的姓名、email、訊息內容。裁切或局部模糊：

    from PIL import Image, ImageFilter
    im = Image.open('dialog.png').convert('RGB')
    keep = (120, 600, 1050, 1700)                 # 要保持清楚的區域（例如對話框）
    out = im.filter(ImageFilter.GaussianBlur(28))
    out.paste(im.crop(keep), keep[:2])
    out.save('dialog_blurred.png')

  • 測試資料本身：用明顯是假的名字（「測試用戶A」），不要用同事的真名建測試帳號 —— 那些名字遲早會出現在截圖裡。

9. 什麼時候該停下來找人​

AI 應該先窮盡工具上的辦法 —— 例如專案裡是否已經有寫好的操作說明或知識庫、有沒有別的工具能做到 —— 真的做不到的時候才找人。下面這些一定要人：

事情原因
手機上的「信任這部電腦」「允許 USB 偵錯」安全設計，只能在手機上按
登入 Xcode 的 Apple 帳號、同意開發者條款帳號與法律條款
確認喇叭有沒有出聲AI 聽不到
要覆蓋或移除的 App 不是測試用的需要擁有者同意
要用的帳號不是確認過的測試帳號寫入會影響真實資料

找人的時候要講清楚：要對方做什麼、做完會怎樣、不做的替代方案是什麼。

10. 收尾清單​

交還裝置或結束工作前：

  • 背景程序都停了（WDA 的 xcodebuild、iproxy、錄影、播放器）
  • 手機上臨時裝的工具移除了（WebDriverAgent）
  • 換過的 App 裝回原本的版本，確認版本號
  • 換過的帳號登回原本的帳號，確認畫面上的名稱
  • 系統設定還原（音量、Demo Mode、螢幕常亮、系統動畫、螢幕方向、iPhone 的自動鎖定）
  • 測試中建立的資料已結案或刪除（或確認測試環境允許留著）
  • 截圖已檢查個資
  • 專案的工作目錄沒有被工具改到（例如 IDE 自動改寫的鎖定檔）—— git status 看一眼
  • 回報時列出：改了什麼、還原了什麼、有哪些沒能還原

11. 可以直接貼給 AI 的守則範本​

放進專案的 CLAUDE.md（或其他 agent 的指示檔），再依專案改寫括號裡的內容：

## 操作實機的規則

- 可寫入資料的帳號只有：（測試帳號清單）。其他帳號一律唯讀；寫入前先確認目前登入的是哪個帳號（顯示名稱不算）。
- 可以覆蓋或移除的 App：（清單）。覆蓋前先備份 APK 與 App 資料，事後裝回同一份並確認版本號與登入帳號。
- 不知道密碼的帳號不准登出。
- 每個動作之後重新讀 UI 樹或截圖確認，不要批次送出點擊。座標優先從 UI 樹取。
- 要截一閃即逝的畫面時連拍，拼成縮圖再挑。
- 播放聲音前先告知；第一次要請人確認有聽到。
- 截圖放進文件前檢查個資（通知列、列表頁、對話框背景）。
- 結束前照收尾清單還原，回報時列出改了什麼、還原了什麼、哪些沒能還原。
- 操作工具與帳號資訊放在：（專案內的文件路徑）。遇到問題先查那裡，再找人。
