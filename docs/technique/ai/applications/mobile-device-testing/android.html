Android：讓 AI 用 adb 操作實機

Android 是兩個平台裡容易的那個：adb 一個工具就涵蓋了連線、操作、截圖、log 與安裝。 這一篇的指令都假設只接一台裝置；接多台時每個指令都要加 -s 序號（序號從 adb devices 看）， 或先 export ANDROID_SERIAL=序號，之後的 adb 指令就都會指向那一台。

1. 連線​

1.1 USB​

adb devices -l
# List of devices attached
# ABC123456789   device usb:1-1 product:xxx model:XXXX device:xxx transport_id:1

狀態欄是 unauthorized 的話，手機上會跳出「允許 USB 偵錯嗎？」，要人按允許（勾「一律允許」以後就不用再按）。

1.2 無線（Android 11 以上）​

手機：開發人員選項 → 無線偵錯 → 使用配對碼配對裝置。

adb pair 192.168.1.23:37000      # 輸入手機上顯示的六位數配對碼
adb connect 192.168.1.23:41000   # 注意：連線用的連接埠跟配對用的不同，看「無線偵錯」頁面上方的那個
tip

無線連線在手機休眠或換網路後會斷。長時間的測試用 USB 比較穩， 而且 USB 同時能充電 —— 截圖、錄影、跑視訊通話都很耗電。

2. 點擊、輸入、滑動​

動作指令
點擊adb shell input tap 540 1200
滑動（捲動）adb shell input swipe 540 1800 540 600 300（最後一個數字是毫秒）
長按adb shell input swipe 540 2000 540 2000 5000（同一點滑動 5 秒，就是按住 5 秒）
輸入英數字adb shell input text 'abc123'（空白要寫成 %s；& ; ( ' 這類字元會被手機上的 shell 解讀，要再跳脫一次）
按鍵adb shell input keyevent KEYCODE_BACK（KEYCODE_HOME、KEYCODE_ENTER、KEYCODE_DEL、KEYCODE_MOVE_END）
啟動 Appadb shell monkey -p com.example.app -c android.intent.category.LAUNCHER 1
強制關閉 Appadb shell am force-stop com.example.app
打開網址／深層連結adb shell am start -a android.intent.action.VIEW -d 'https://example.com/path'

清空輸入框沒有現成指令，用「移到結尾 + 連按刪除」：

adb shell input keyevent KEYCODE_MOVE_END
for i in $(seq 1 30); do adb shell input keyevent KEYCODE_DEL; done

2.1 中文輸入​

input text 只能打 ASCII。要輸入中文有兩種做法：

  1. 安裝開源的 ADBKeyBoard 輸入法，用 broadcast 送 Unicode 字串進去。
  2. 避開輸入：例如清單有搜尋框時，改成捲動清單找目標（見第 3 節的迴圈寫法）。

2.2 畫連續筆跡（簽名板、手勢）​

input swipe 只能畫直線。要畫曲線用 input motionevent（較新的 Android 才有）， 按下、一連串移動、放開：

adb shell input motionevent DOWN 160 1000
adb shell input motionevent MOVE 200 900
adb shell input motionevent MOVE 260 1080
# …中間的點可以用程式產生（例如正弦曲線）
adb shell input motionevent UP 920 1000

3. 讀 UI 樹：不要猜座標​

截圖再憑肉眼估座標，很容易點歪 —— 尤其 AI 看到的截圖通常被縮小過（見操作守則第 2 節）。 能讀 UI 樹就讀 UI 樹，它直接給每個元素的文字和邊界：

adb shell uiautomator dump /sdcard/ui.xml >/dev/null
adb shell cat /sdcard/ui.xml \
  | grep -oE '(text|content-desc)="[^"]+"[^>]*bounds="[^"]+"' \
  | grep -oE '^(text|content-desc)="[^"]+"|bounds="[^"]+"' | paste - -
# "登入"           bounds="[74,1628][1006,1754]"
# "記住帳號"       bounds="[74,1450][1006,1576]"

點擊時取邊界的中心點：[74,1628][1006,1754] → (540, 1691)。

情況UI 樹看得到嗎
原生 View、Jetpack Compose✅ text 或 content-desc
Flutter✅ 大多數元件會出現在 content-desc（來自 Semantics）；純裝飾的自繪元件可能沒有
WebView 內容⚠️ 部分；網頁內容建議改用 Chrome 遠端偵錯
遊戲引擎、Canvas 繪製❌ 只能靠截圖
ERROR: could not get idle state

uiautomator dump 要等畫面「靜止」才讀得出來。App 裡有持續播放的動畫（轉圈、Lottie、跑馬燈）時會一直失敗。 先把系統動畫關掉（見第 9 節）；還是不行就等動畫停、或改用截圖量座標。 另外，同一時間只能有一個 UI 自動化程序：Appium 之類的工具開著時，uiautomator dump 也會失敗。

找清單裡的某一項時，寫成「找不到就往下捲」的迴圈：

for i in $(seq 1 8); do
  r=$(adb shell uiautomator dump /sdcard/ui.xml >/dev/null; adb shell cat /sdcard/ui.xml | grep -o '目標文字[^>]*bounds="[^"]*"')
  [ -n "$r" ] && break
  adb shell input swipe 540 1900 540 1300 400; sleep 0.8
done
echo "$r"
每次畫面變動後都要重新讀

軟體鍵盤彈出、對話框打開、清單捲動之後，座標全部會變。 不要把一串點擊一次批次送出，每一步之後重新讀 UI 樹或截圖。

4. 截圖與錄影​

adb exec-out screencap -p > shot.png          # 用 exec-out，不要用 shell（shell 會把換行轉碼，PNG 會壞掉）
adb shell screenrecord --time-limit 15 /sdcard/rec.mp4 && adb pull /sdcard/rec.mp4
adb shell wm size                              # 螢幕實際解析度，例如 Physical size: 1080x2340

4.1 乾淨的狀態列（Demo Mode）​

要放進文件的截圖，狀態列上的通知圖示、電量、警告符號都是雜訊。系統內建 Demo Mode 可以把狀態列固定住：

adb shell settings put global sysui_demo_allowed 1
adb shell am broadcast -a com.android.systemui.demo -e command enter
adb shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 0941
adb shell am broadcast -a com.android.systemui.demo -e command battery -e level 100 -e plugged false
adb shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false
# 結束：
adb shell am broadcast -a com.android.systemui.demo -e command exit
note

各廠牌支援程度不一。 有些廠牌只吃「隱藏通知圖示」，時鐘和電量照舊。 最保險的做法是截圖後直接把狀態列裁掉。狀態列高度可以這樣查：

adb shell dumpsys window | grep -m1 'type=statusBars frame'
# InsetsSource ... type=statusBars frame=[0,0][1080,95]   → 裁掉上方 95px

5. 先處理權限對話框​

第一次打開 App 時跳出的「允許使用相機？」「允許傳送通知？」會擋住畫面，AI 常常因此卡住。 在啟動 App 前先授權：

for p in CAMERA RECORD_AUDIO POST_NOTIFICATIONS BLUETOOTH_CONNECT READ_PHONE_STATE; do
  adb shell pm grant com.example.app android.permission.$p 2>/dev/null
done

pm grant 只對 App 在 manifest 宣告過的「危險權限」有效，其他的會報錯，可以忽略。

6. 推播與通知列​

# 讀目前所有通知的標題與內文（不用打開通知列）
adb shell dumpsys notification --noredact | grep -A40 'pkg=com.example.app' | grep -E 'android.title=|android.text='

# 打開／收起通知列（要截圖給人看的時候）
adb shell cmd statusbar expand-notifications
adb shell cmd statusbar collapse
通知列截圖要檢查個資

通知列會一起顯示其他 App 的通知 —— 帳號 email、訊息內容、簡訊驗證碼都可能出現。 放進文件前只裁出需要的那一則。

7. 安裝、移除與備份還原​

7.1 安裝與降版​

adb install -r app.apk        # -r：覆蓋安裝，保留資料
adb install -r -d app.apk     # -d：允許降版（版號比較舊）
adb uninstall com.example.app # 會連資料一起刪掉
錯誤原因處理
INSTALL_FAILED_UPDATE_INCOMPATIBLE簽章不同（例如手機上是 debug 版，你要裝 release 版）只能先移除再裝 —— 資料會不見，先做 7.2、7.3 的備份
INSTALL_FAILED_VERSION_DOWNGRADE版號比手機上的舊加 -d；非 debuggable 的 App 在新版 Android 上可能仍會被拒

7.2 備份手機上目前的 APK​

要暫時換成別的版本（例如 Demo 版）時，先把手機上那份原樣存下來，事後裝回同一份最保險 —— 你不一定知道手機上那份是從哪裡、用哪個版本建出來的：

for p in $(adb shell pm path com.example.app | sed 's/package://' | tr -d '\r'); do
  adb pull "$p" ./backup/
done
# 只有 base.apk：還原用 adb install；有多個 split_*.apk：用 adb install-multiple ./backup/*.apk

順便看一下它是什麼版本、從哪裡裝的：

adb shell dumpsys package com.example.app | grep -E 'versionName|versionCode|installerPackageName|pkgFlags'
# pkgFlags 有 DEBUGGABLE、installerPackageName=null → 是開發者直接裝的 debug 版，不是從商店裝的

7.3 備份與還原 App 資料（登入狀態）​

要在 App 裡換一個測試帳號，但又想事後恢復原本的登入狀態時： 如果 App 是 debuggable（debug 版），可以用 run-as 把整個資料夾打包下來。

# 備份
adb shell am force-stop com.example.app
adb exec-out "run-as com.example.app tar cf - shared_prefs files databases app_flutter no_backup 2>/dev/null" > app_data.tar
# 2>/dev/null 要放在手機端：exec-out 會把錯誤訊息混進輸出，弄壞 tar 檔（例如某個資料夾不存在時）
tar tf app_data.tar | head        # 確認備份檔讀得開

# 還原
adb shell am force-stop com.example.app
adb shell run-as com.example.app rm -rf shared_prefs files databases app_flutter no_backup
cat app_data.tar | adb shell "run-as com.example.app tar xf -"
限制
  • 只能用在 debuggable 的 App。商店版（release）不行。
  • 只能還原到同一次安裝。資料若用 Android Keystore 加密（例如 flutter_secure_storage、EncryptedSharedPreferences）， 金鑰綁在那次安裝上，移除重裝之後備份就解不開了。
  • 還原後重新開 App，確認畫面上真的是原本的帳號，不要只看指令的回傳值。

8. Log​

adb logcat -c                                   # 先清空，等一下只看這次操作產生的
# …執行操作…
adb logcat -d | grep -iE 'flutter|com.example' | tail -50
adb logcat -d -t 300                            # 只看最後 300 行

想知道「按了按鈕之後有沒有送出請求、送到哪」時，先 logcat -c、操作、再 logcat -d 篩關鍵字，比在一大串 log 裡找快得多。

9. 讓手機保持可操作​

問題處理
螢幕自動關閉adb shell svc power stayon usb（接 USB 時保持喚醒）
有螢幕鎖測試期間先關閉；或 adb shell input keyevent KEYCODE_WAKEUP 後滑開（有密碼就無法自動化）
廠牌的省電管理把 App 殺掉設定裡把該 App 的電池最佳化關掉
系統更新、帳號提示一直跳出來截圖前先把通知列清乾淨
動畫讓截圖時機不準、UI 樹讀不到關掉系統動畫（見下方），結束後改回 1
平板要固定橫向截圖adb shell settings put system accelerometer_rotation 0 再 adb shell settings put system user_rotation 1（0 直向、1 橫向；結束後把 accelerometer_rotation 改回 1）
for k in window_animation_scale transition_animation_scale animator_duration_scale; do
  adb shell settings put global $k 0      # 結束時改回 1
done

10. 一支小工具​

讓 AI 少打字、也少出錯：

ui.sh
#!/bin/bash
# ui.sh shot <out.png> | dump | tap <x> <y>
case $1 in
  shot) adb exec-out screencap -p > "$2" ;;
  dump) adb shell uiautomator dump /sdcard/ui.xml >/dev/null
        adb shell cat /sdcard/ui.xml \
          | grep -oE '(text|content-desc)="[^"]+"[^>]*bounds="[^"]+"' \
          | grep -oE '^(text|content-desc)="[^"]+"|bounds="[^"]+"' | paste - - ;;
  tap)  adb shell input tap "$2" "$3" ;;
esac

11. 讓人在旁邊看得到​

AI 操作時，人最好能即時看到手機畫面 —— 尤其是第一次跑、或要寫入資料的時候。 開源的 scrcpy 可以把 Android 畫面鏡像到電腦視窗（走 adb，不用裝任何 App）：

scrcpy --no-control      # 只看不操作，避免人和 AI 同時點
