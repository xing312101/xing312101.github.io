讓 AI 操作實機做測試：總覽

Claude Code 這類 AI agent 能執行 shell 指令、讀圖片，所以理論上它能做的事跟坐在電腦前的工程師一樣： 裝 App、點畫面、截圖、看 log。實際上卡住的地方幾乎都不是「AI 不會點」，而是工具鏈： iOS 17 之後舊的截圖工具失效、簽章帳號過期、沙盒裡的程序發不出聲音、 截圖被縮小後座標對不上、手機自己跳出的權限對話框擋住畫面。

這一系列文件把「從命令列操作一支手機」需要的東西整理成可以照著做的步驟， 並且標出每一個實際會踩到的坑。對象是要讓 AI 代為測試的工程師，也可以直接丟給 AI 當參考資料。

1. 整體架構​

AI 本身不碰手機，它只是在你的電腦上執行指令。所有操作都經過這幾個中介：

平台中介工具AI 怎麼用它
Androidadb（Android SDK Platform-Tools）直接下指令：點擊、輸入、截圖、讀 UI 樹、看 log、裝 App
iOSWebDriverAgent（跑在手機上的 XCUITest 小伺服器）＋ iproxy透過 HTTP 呼叫：截圖、點擊、輸入、讀 UI 樹、開 App
iOS（管理）xcrun devicectl（Xcode 內建）列裝置、裝／移除 App、列出已安裝的 App
Flutter App（兩平台）integration_test ＋ flutter drive跑寫好的測試腳本，由測試自己截圖
網頁後台Playwright ＋ 本機 Chrome寫小腳本登入、換頁、截圖、記錄網路請求

AI 的工作方式永遠是同一個迴圈：看（截圖或讀 UI 樹）→ 動（點擊／輸入）→ 再看一次確認結果。 這一系列的大部分篇幅，都在處理「怎麼可靠地看」和「怎麼精準地動」。

2. 各篇導覽​

文件內容
總覽（本篇）架構、工具選擇、開始前的準備
Android：用 adb 操作連線、點擊與輸入、讀 UI 樹、截圖、乾淨的狀態列、權限、安裝與備份還原、推播與 log
iOS：用 WebDriverAgent 操作為什麼舊工具失效、WebDriverAgent 的建置與簽章、HTTP API、座標換算、模擬器的捷徑
Flutter 的 integration_test 截圖用測試腳本自己截圖、實機的限制、它截不到什麼
網頁後台：Playwright用本機 Chrome 登入截圖、排查「網路連線異常」、CORS 與網域
語音功能測試讓電腦說話給手機聽：產生語音檔、播放、按住說話的時機、確認手機真的聽懂、沙盒裡沒聲音的陷阱
給 AI 的操作守則觀察→動作→驗證、座標換算、抓短暫畫面、確認登入的是誰、兩支手機對打、備份還原、個資、收尾清單
常見問題對照錯誤訊息 → 原因 → 解法

第一次設定的話，照這個順序讀：本篇第 3 節 → 你要用的平台 → 給 AI 的操作守則。 遇到錯誤直接查常見問題對照。

3. 開始前的準備清單​

3.1 電腦端​

項目用途確認方式
Android SDK Platform-Toolsadbadb version
Xcode（含命令列工具）xcodebuild、xcrun devicectlxcodebuild -version
Xcode 已登入 Apple 開發者帳號讓 WebDriverAgent 自動產生描述檔Xcode → Settings → Accounts 看得到帳號
libimobiledeviceiproxy（把手機的連接埠轉到本機）which iproxy
Python 3 或 Node.js寫操作用的小腳本、Playwrightpython3 --version
一般版 Google ChromePlaywright 直接借用，不用另外下載瀏覽器應用程式資料夾裡有 Chrome
scrcpy（選用）把 Android 畫面鏡像到電腦，讓人看著 AI 操作scrcpy --version
ffmpeg（選用）語音測試時錄音檢查、轉檔ffmpeg -version

3.2 手機端​

平台要開的東西
Android開發人員選項 → USB 偵錯；建議同時開「不要鎖定螢幕（充電時保持喚醒）」
iOS設定 → 隱私權與安全性 → 開發者模式；第一次接電腦要按「信任這部電腦」；測試期間「自動鎖定」設為「永不」
兩者螢幕鎖定先關掉或設長一點；測試帳號先準備好，不要用個人或正式帳號
先講好哪些東西 AI 不能動

讓 AI 操作實機之前，先跟它講清楚邊界，最少要有這三條：

  1. 哪些帳號可以寫入資料（建立、修改、刪除）。其他帳號一律唯讀。
  2. 哪些 App 可以被覆蓋或移除。覆蓋前必須先備份（做法見 Android 篇第 7 節）。
  3. 登出前要先確認登得回去。不知道密碼的登入狀態，登出就救不回來了。

細節在給 AI 的操作守則。

4. 該用哪一種方式？​

想做的事建議
截某個畫面放進文件或簡報Android 用 adb；iOS 用 WebDriverAgent；網頁用 Playwright
要截到系統畫面（來電畫面、推播、權限對話框）只能用 adb（Android）或 WebDriverAgent（iOS）。Flutter 的測試截圖截不到
一套固定流程要每次改版都重跑寫成 Flutter integration_test，見 Flutter 篇
兩支手機互動（通話、聊天、推播送達）一支用 adb、一支用 WebDriverAgent，同一個腳本裡交替操作，見操作守則第 5 節
語音功能（按住說話）讓電腦播放語音檔給手機麥克風聽，見語音功能測試
臨時排查一個畫面為什麼不對adb／WebDriverAgent 手動操作，配合 log
tip

現成的整合方案（Appium、Maestro、各家的「手機 MCP 伺服器」）底層用的也是 adb 和 WebDriverAgent。 先把這兩個摸熟，遇到整合方案出問題時才知道是哪一層壞掉。
