自架 LLM 語意搜尋（跨站）

用自己的 LLM / embedding 做「語意搜尋」，取代 client 端關鍵字搜尋（如 easyops）。核心：把 RAG 的檢索層獨立成一個 API 服務，讓任何網站（Docusaurus、其他文章站）都能呼叫 → 一套後端、多站共用。

vs client 端搜尋​

client 端（easyops / lunr）自架語意搜尋
匹配字面關鍵字語意（懂同義、跨語言中英日）
基礎建設無（純靜態）要常駐 server + 向量庫
跨站共用每站各自建索引一套 API 全站共用
進階—可加「AI 直接回答 + 出處」

架構​

[各網站前端]  ── fetch ──▶  [搜尋 API]  ──▶  [向量庫]
  Docusaurus/其他                │
                                 ├─▶ embedding 模型（文字→向量）
                                 └─▶ LLM（可選：生成答案）← 你的 llama-server

1. 建索引（離線 / 定時 / build 時）​

  • 收集各站內容（讀 markdown 原始檔，或爬 build 後 HTML）。
  • 切塊（chunking）→ 每塊算 embedding → 存進向量庫（含 url / title / 內文）。
  • embedding 模型選多語（中英日）：bge-m3、multilingual-e5。可用 llama.cpp 服務：llama-server -m bge-m3.gguf --embedding（開 /embedding 端點）。

2. 搜尋 API（一支小服務，FastAPI / Node）​

  • GET /search?q= → query 也算 embedding → 向量庫找 top-k →（可選 rerank，如 bge-reranker）→ 回傳 title / url / snippet。
  • POST /ask（可選，完整 RAG）→ top-k + query 丟給 llama-server → 生成答案 + 出處。
  • CORS 要放行各站 origin。

3. 各站前端接（框架無關）​

  • 就是一個搜尋框 fetch('https://search.你的域名/search?q=' + q) 再渲染結果 —— 所以不限 Docusaurus，任何站一段 JS 就能接。
  • Docusaurus：swizzle SearchBar 元件指向你的 API（取代 easyops）。

元件選型​

  • 向量庫：Qdrant（Docker 好架）、pgvector（已有 Postgres 就用它）、或 Meilisearch / Typesense（附向量搜尋）。
  • embedding：bge-m3（多語強）/ multilingual-e5。
  • LLM（/ask 用）：現有的 llama-server（量化見 quantization）。
  • 對外：nginx / ngrok / tailscale 暴露 API（見 web_server），記得 HTTPS + CORS。

⚠️ 現實考量​

  • 靜態站（GitHub Pages）本體仍靜態，但搜尋依賴你家那台 server 開著 → server 關機搜尋就掛。要嘛常駐（省電小主機），要嘛做「離線時退回 easyops」雙軌。
  • 維護成本高於 easyops。值不值得看你多想要「語意 / 跨站 / AI 回答」；純找字 easyops 就夠。

底層概念見 RAG；模型 / embedding 服務見 offline-model；對外服務見 web_server。
