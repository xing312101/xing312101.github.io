發佈流程與檢查清單（Runbook）

把前面的設定變成「平常怎麼操作」的實務流程。

A. 日常開發流程​

開 feature 分支 → 寫 code → push → 開 MR
        │
        ▼
   雲端快檢自動跑（format / analyze / test）
        │
     綠燈？──否──▶ 修到綠
        │是
        ▼
   review → merge 進 main（Pipelines must succeed 擋著，紅的進不來）
  • 完全不需要碰自架 Mac，開發回饋只靠雲端快檢，永遠 always-on。
  • 整合 / e2e / screenshot 測試由 nightly schedule 或 merge 後跑，不拖慢 MR。

B. 出一個版本（release）​

1. 更新版本號（pubspec.yaml 的 version: x.y.z+build）
2. 確認自架 Mac 開著、gitlab-runner online、caffeinate 防睡
3. git tag vX.Y.Z && git push origin vX.Y.Z
        │
        ▼
4. GitLab pipeline 出現這些手動按鈕：
   ├─ android_bundle（自動 build 出 .aab）
   ├─ android_play_internal  ← 手動按：上 Play 內部測試
   ├─ ios_testflight         ← 手動按：build + 上 TestFlight（跑在 Mac）
   └─ ios_appstore_submit    ← 手動按：送 App Store 審核
        │
        ▼
5. 測試者在 TestFlight / Play 內測驗證
        │
        ▼
6. 一切 OK → 按 ios_appstore_submit / Play production → 送審
        │
        ▼
7. 審核通過 → 到 App Store Connect / Play Console 手動釋出正式版

正式釋出永遠是人工最後一按，CI 不自動把 app 推給正式用戶。

上傳成功 ≠ 上架

第 6～7 步是 CI 幫不上忙的地方。技術上完全正常的 build 也會被審核擋下來——散布方式選錯、 Age Rating 勾了沒做的功能、需要硬體卻沒交 demo 影片，都是常見駁回。見 App Store 審核駁回。

C. 版本號與 build number​

pubspec.yaml：

version: 1.4.0+42     #  1.4.0 = 顯示版本(versionName / CFBundleShortVersionString)
                      #  42    = build number(versionCode / CFBundleVersion)
  • 每次上傳 TestFlight / Play 的 build number 必須遞增（同號會被拒）。
  • 可用 pipeline 序號自動遞增：flutter build ipa --build-number=$CI_PIPELINE_IID。

D. 出版本前檢查清單​

  • pubspec.yaml 版本號已更新，build number 高於上一版
  • 自架 Mac：開機、gitlab-runner status = running、已防睡眠
  • 憑證：fastlane match appstore --readonly 能同步（憑證未過期）
  • CI/CD Variables 都在（keystore、Play JSON、ASC API key、MATCH_PASSWORD…）
  • Release notes / 更新說明準備好
  • main 為綠、要發的 commit 已 merge

送審才會用到、但常常漏掉的（詳見 App Store 審核駁回）：

  • Release 的 entitlements 正確（推播的 aps-environment 要是 production）
  • 散布方式選對（通過審核後就不能改）
  • Age Rating 問卷沒有勾到「其實沒做」的功能
  • 所有宣稱支援的裝置尺寸都有截圖
  • 測試帳號與密碼填在 App Review Information，且現在還能登入
  • 需要硬體的話，demo 影片已備好，並用無痕視窗驗過連結打得開

E. 疑難排解速查​

症狀可能原因處置
按了 iOS job 卻一直 pending自架 Mac 沒開 / runner 沒 online開機、gitlab-runner start
job 一直 pending，但 runner 明明 onlinetag 對不上（tag 存在 GitLab 伺服器端，config.toml 裡查不到），或該 runner 沒開放給這個專案回 GitLab 該 runner 的設定頁核對 tag、把它開放給此專案
取原始碼階段就紅：Directory not empty自架 Mac 重用 workspace，Spotlight 或 Gradle daemon 鎖住檔案見自架 Runner（Spotlight 隱私清單 + after_script 清重產物）
Android build No space left on device雲端 runner 磁碟不足（NDK/SDK/多 ABI 原生庫）移到自架機器；調 --target-platform 通常沒用
兩個簽章 job 同時跑就隨機失敗共用 build.keychain／描述檔檔名等全域狀態分到 limit = 1 的專用 runner，見並發與跨專案共用
上架後推播收不到、後端卻顯示成功Release entitlements 的 aps-environment 是 development，拿到 sandbox token見 iOS 上架：Release 要用獨立的 entitlements 檔
runner 連不上 GitLab公司 proxy / TLS 檢查 / 白名單設 proxy env、信任公司 CA、請 IT 放行網域
dart format 沒擋到爛格式少了旗標用 dart format --set-exit-if-changed .
iOS 簽章失敗憑證只在別台機器改用 fastlane match 集中管理
TestFlight 拒絕上傳build number 沒遞增提高 build number
MR 一直卡著不能 merge把自架 job 設成必過了build/release 改 tag + manual，移出 merge gate
雲端快檢常常沒額度compute minutes 用完把快檢搬到自架 Linux runner（0 分鐘）
