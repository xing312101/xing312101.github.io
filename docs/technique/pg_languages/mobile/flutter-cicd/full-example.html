完整 Flutter .gitlab-ci.yml

把通用骨架填成 Flutter 版本。這是教學範例，請依你的專案調整（版本、tag、變數名）。

設計摘要​

  • 快檢（format / analyze / test）：雲端 Linux，只在 MR 與 merge 進 main 時跑，進入 merge gate。
  • Android build：tag 觸發，雲端或自架皆可。
  • iOS build + TestFlight：tag 觸發 + tags: [macos] 指名自架 Mac。
  • 正式上架：when: manual 手動關卡，排除在 merge 判斷之外。
這個範例假設自架 Mac 一次只跑一個 job

也就是 runner 的 concurrent = 1（預設值）。若你之後把並發調大、或讓第二個專案共用同一台 Mac， 簽章相關的 job 不能再共用一個 tag —— 臨時鑰匙圈、描述檔檔名等全域狀態會跨 job（甚至跨專案） 互相破壞。那時候要把它們分到一條 limit = 1 的專用 runner，見 並發與跨專案共用。

stages:
  - check
  - build
  - release

variables:
  FLUTTER_VERSION: "<FLUTTER_VERSION>"   # 對齊 .fvmrc

# ---------- 1) 雲端快檢：進 merge gate ----------
fast_check:
  stage: check
  image: ghcr.io/cirruslabs/flutter:$FLUTTER_VERSION
  interruptible: true
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  variables:
    PUB_CACHE: "$CI_PROJECT_DIR/.pub-cache"
  cache:
    key:
      files: [ pubspec.lock ]
    paths: [ .pub-cache/ ]
  before_script:
    - flutter pub get
  script:
    - dart format --set-exit-if-changed .
    - flutter analyze
    - flutter test

# ---------- 2) Android：tag 觸發 ----------
android_bundle:
  stage: build
  image: ghcr.io/cirruslabs/flutter:$FLUTTER_VERSION
  rules:
    - if: $CI_COMMIT_TAG =~ /^v/
  before_script:
    - echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > android/app/upload-keystore.jks
    - flutter pub get
  script:
    - flutter build appbundle --release
  artifacts:
    paths: [ build/app/outputs/bundle/release/app-release.aab ]
    expire_in: 1 week

android_play_internal:
  stage: release
  image: ghcr.io/cirruslabs/flutter:$FLUTTER_VERSION
  needs: [ android_bundle ]
  rules:
    - if: $CI_COMMIT_TAG =~ /^v/
      when: manual
      allow_failure: true
  script:
    - cd android && bundle exec fastlane internal

# ---------- 3) iOS：tag 觸發，指名自架 Mac ----------
ios_testflight:
  stage: build
  tags: [ macos ]                          # ← 只有自架 macOS runner 會接
  rules:
    - if: $CI_COMMIT_TAG =~ /^v/
      when: manual
      allow_failure: true
  before_script:
    - fvm install
    - fvm flutter pub get
  script:
    - cd ios && bundle exec fastlane beta   # build + 上 TestFlight

# ---------- 4) 正式上架：最終手動關卡 ----------
ios_appstore_submit:
  stage: release
  tags: [ macos ]
  needs: [ ios_testflight ]
  rules:
    - if: $CI_COMMIT_TAG =~ /^v/
      when: manual
      allow_failure: true
  script:
    - cd ios && bundle exec fastlane release

逐段重點​

Job觸發跑在哪進 merge gate？
fast_checkMR / push 到 main雲端 Linux是（唯一的閘門）
android_bundle推 v* tag（自動）雲端或自架否
android_play_internalv* tag + 手動雲端或自架否
ios_testflightv* tag + 手動自架 Mac（macos tag）否
ios_appstore_submitv* tag + 手動自架 Mac否

關鍵：只有 fast_check 是 always-on 的雲端，才適合當 MR 的必過條件。所有 build/release 都用 tag + manual，不會因為你的 Mac 沒開機而卡住 MR。

搭配的 GitLab 設定​

  1. Settings → Merge requests → 勾 "Pipelines must succeed"。
  2. Settings → Repository → Protected branches → 保護 main。
  3. Settings → CI/CD → Variables → 填入 android-publish / ios-publish 列的機密（見機密管理通則）。 4.（可選）Settings → CI/CD → Schedules → 建 nightly，跑整合測試。

同一條 pipeline：GitHub Actions 版​

觀念一模一樣，只是換語法——最大差別：iOS 跑在 GitHub 官方 hosted macos-14（不必自架 Mac），手動關卡用 Environments（required reviewers） 取代 when: manual。build/簽章/上傳仍是同一份 fastlane Fastfile。

# .github/workflows/ci.yml
name: ci
on:
  pull_request:
  push:
    branches: [ main ]
    tags: [ 'v*' ]

jobs:
  # ---------- 1) 雲端快檢：設為 required check ----------
  fast_check:
    if: github.event_name == 'pull_request' || github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>', cache: true }
      - run: flutter pub get
      - run: dart format --set-exit-if-changed .
      - run: flutter analyze
      - run: flutter test

  # ---------- 2) Android：tag 觸發 ----------
  android_bundle:
    if: startsWith(github.ref, 'refs/tags/v')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>' }
      - run: echo "${{ secrets.ANDROID_KEYSTORE_BASE64 }}" | base64 --decode > android/app/upload-keystore.jks
      - run: flutter build appbundle --release
      - uses: actions/upload-artifact@v4
        with: { name: aab, path: build/app/outputs/bundle/release/app-release.aab }

  android_play_internal:
    if: startsWith(github.ref, 'refs/tags/v')
    needs: android_bundle
    runs-on: ubuntu-latest
    environment: play_internal           # required reviewers ＝手動關卡
    steps:
      - uses: actions/checkout@v4
      # 還原 keystore + cd android && bundle exec fastlane internal（見 android-publish）

  # ---------- 3) iOS：tag 觸發，hosted macOS（免自架）----------
  ios_testflight:
    if: startsWith(github.ref, 'refs/tags/v')
    runs-on: macos-14                    # ← GitHub 有 hosted macOS
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>' }
      - run: flutter pub get
      - run: cd ios && bundle exec fastlane beta        # 同一份 Fastfile
        env:
          MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
          MATCH_GIT_URL:  ${{ secrets.MATCH_GIT_URL }}
          ASC_KEY_ID:     ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID:  ${{ secrets.ASC_ISSUER_ID }}
          ASC_API_KEY_P8: ${{ secrets.ASC_API_KEY_P8 }}

  # ---------- 4) 正式上架：Environment 手動核准 ----------
  ios_appstore_submit:
    if: startsWith(github.ref, 'refs/tags/v')
    needs: ios_testflight
    runs-on: macos-14
    environment: appstore_release        # required reviewers ＝人工核准（= GitLab when:manual）
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>' }
      - run: cd ios && bundle exec fastlane release

搭配的 GitHub 設定​

  1. Settings → Branches → Branch protection rules → 保護 main，把 fast_check 加進 required status checks（= GitLab 的 "Pipelines must succeed"）。
  2. Settings → Secrets and variables → Actions → 填 android-publish / ios-publish 列的機密。
  3. Settings → Environments → 建 play_internal / appstore_release，各加 required reviewers＝上架前的人工關卡。 4.（可選）nightly 用 on: schedule: - cron: '0 18 * * *' 跑整合測試。
