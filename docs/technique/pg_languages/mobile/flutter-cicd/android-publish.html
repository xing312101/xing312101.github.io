Android 打包與上架

Android 相對單純：build 出 App Bundle → 用簽章金鑰簽 → 送到發佈通路（內測用 Firebase App Distribution，正式用 Play Console）。Android build 在 Linux 或 macOS runner 都能跑。

機密處理的通則見機密管理，本篇只列 Android 專屬部分。

1. 產生簽章金鑰（keystore）​

只做一次，妥善保存，遺失就無法更新已上架的 app。

keytool -genkey -v -keystore upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
danger

不要把 keystore 或密碼 commit 進 git。 用 CI/CD Variables 注入（見文末）。

2. 專案簽章設定​

android/key.properties（加進 .gitignore，不進 git）：

storePassword=<從 CI 變數注入>
keyPassword=<從 CI 變數注入>
keyAlias=upload
storeFile=<keystore 路徑>

android/app/build.gradle（概念，實際依你的 Gradle 版本）：

def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    signingConfigs {
        release {
            storeFile file(keystoreProperties['storeFile'])
            storePassword keystoreProperties['storePassword']
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
        }
    }
    buildTypes {
        release { signingConfig signingConfigs.release }
    }
}

3. 打包​

flutter build appbundle --release   # 上架用 App Bundle（Play 要求）
flutter build apk --release         # 內測直接發 APK 也可以

產物：

  • build/app/outputs/bundle/release/app-release.aab
  • build/app/outputs/flutter-apk/app-release.apk

4. 發佈通路​

A) Firebase App Distribution（內測最快）​

firebase appdistribution:distribute \
  build/app/outputs/flutter-apk/app-release.apk \
  --app "<FIREBASE_ANDROID_APP_ID>" \
  --groups "testers" \
  --release-notes "此版重點…"

B) Play Console（正式 / 內部測試軌道）​

用 fastlane supply 上傳 AAB 到指定軌道（internal / alpha / beta / production）。前置：Play Console 建 service account，下載 JSON 金鑰，授權上傳權限。

android/fastlane/Fastfile：

platform :android do
  lane :internal do
    upload_to_play_store(
      track: 'internal',
      aab: '../build/app/outputs/bundle/release/app-release.aab',
      json_key: ENV['PLAY_JSON_KEY'],         # 檔案路徑：GitLab 的 File 型變數就是路徑，GitHub 見 §5
      skip_upload_apk: true
    )
  end
end
cd android && bundle exec fastlane internal

正式 production 軌道建議搭配 when: manual 手動關卡，別讓 push 自動上到正式。

5. 需要的 CI/CD Variables​

（設定方式與 base64 手法見機密管理）

變數型別用途
ANDROID_KEYSTORE_BASE64base64 字串keystore 檔（base64 編碼後放入）
ANDROID_STORE_PASSWORDMaskedkeystore 密碼
ANDROID_KEY_PASSWORDMaskedkey 密碼
PLAY_JSON_KEYFilePlay service account JSON

GitHub 沒有 File 型的 secret：PLAY_JSON_KEY 存 JSON 的內容，job 裡先寫成檔案，再把路徑放進同名的環境變數（寫法見下面 GitHub 的範例）。

job 裡還原 keystore：

echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > android/app/upload-keystore.jks

在 CI 上 build​

免祕密的 build（每次 MR / 主分支）​

驗證 Android 編得過，不需簽章金鑰（debug 簽章即可）：

  • GitLab CI/CD
  • GitHub Actions
# .gitlab-ci.yml
android_build:
  stage: build
  image: ghcr.io/cirruslabs/flutter:<FLUTTER_VERSION>   # 或自架 Linux runner
  script:
    - flutter build appbundle --release                   # 沒 keystore 時多半會退回 debug 簽章
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
# .github/workflows/android.yml
jobs:
  android_build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>' }
      - run: flutter pub get
      - run: flutter build appbundle --release
漸進式 build：沒祕密當編譯檢查，有祕密就順便驗簽章

很多 Flutter 專案的 build.gradle 會「key.properties 不存在時 release 退回 debug 簽章」（讓沒 keystore 的環境也能 flutter run --release）。利用這點，android_build 可寫成一個 job 兩用——不擋 MR，又能在你備好 keystore 後自動升級成簽章驗證：

android_build:
  stage: build
  script:
    - |
      if [ -n "$ANDROID_KEYSTORE_BASE64" ]; then
        echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > android/app/upload-keystore.jks
        printf 'storeFile=upload-keystore.jks\nstorePassword=%s\nkeyPassword=%s\nkeyAlias=upload\n' \
          "$ANDROID_STORE_PASSWORD" "$ANDROID_KEY_PASSWORD" > android/key.properties
        echo "→ 用 release keystore 簽章（驗簽章）"
      else
        echo "→ 沒 keystore 變數，退回 debug 簽章（純編譯檢查）"
      fi
    - flutter build appbundle --release
  after_script:
    - rm -f android/app/upload-keystore.jks android/key.properties

簽章 build + 上傳（release tag 觸發）​

簽章與上傳邏輯放 fastlane（見上面 §4 發佈通路，GitLab/GitHub 通用），CI 只是換觸發語法：

  • GitLab CI/CD
  • GitHub Actions
android_release:
  stage: release
  image: ghcr.io/cirruslabs/flutter:<FLUTTER_VERSION>
  script:
    - echo "$ANDROID_KEYSTORE_BASE64" | base64 --decode > android/app/upload-keystore.jks
    - printf 'storeFile=upload-keystore.jks\nstorePassword=%s\nkeyPassword=%s\nkeyAlias=upload\n' "$ANDROID_STORE_PASSWORD" "$ANDROID_KEY_PASSWORD" > android/key.properties
    - flutter build appbundle --release
    - cd android && bundle install && bundle exec fastlane internal   # 同一份 Fastfile
  rules:
    - if: $CI_COMMIT_TAG =~ /^v/
      when: manual                                          # 正式軌道保留人工關卡
jobs:
  android_release:
    runs-on: ubuntu-latest
    if: startsWith(github.ref, 'refs/tags/v')
    environment: production            # Environments 的 required reviewers ＝手動關卡
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: subosito/flutter-action@v2
        with: { flutter-version: '<FLUTTER_VERSION>' }
      - uses: ruby/setup-ruby@v1
        with: { ruby-version: '<RUBY_VERSION>', bundler-cache: true, working-directory: android }
      - run: echo "${{ secrets.ANDROID_KEYSTORE_BASE64 }}" | base64 --decode > android/app/upload-keystore.jks
      - run: |
          printf 'storeFile=upload-keystore.jks\nstorePassword=%s\nkeyPassword=%s\nkeyAlias=upload\n' \
            "$STORE_PW" "$KEY_PW" > android/key.properties
          echo "$PLAY_JSON" > "$RUNNER_TEMP/play.json"     # secret 是內容，Fastfile 要路徑
        env:                                 # 密碼走 env：含特殊字元也不會弄壞指令
          STORE_PW:  ${{ secrets.ANDROID_STORE_PASSWORD }}
          KEY_PW:    ${{ secrets.ANDROID_KEY_PASSWORD }}
          PLAY_JSON: ${{ secrets.PLAY_JSON_KEY }}
      - run: flutter build appbundle --release
      - run: cd android && bundle exec fastlane internal
        env:
          PLAY_JSON_KEY: ${{ runner.temp }}/play.json
雲端每次都是新機器，fastlane 要在 job 裡裝

bundle install 照 android/Gemfile.lock 裝：GitLab 用的 ghcr.io/cirruslabs/flutter 有 Ruby 與 Bundler、沒有 fastlane；GitHub 由 ruby/setup-ruby 裝（bundler-cache 會把裝好的 gem 快取起來）。 Gemfile.lock 是在 Mac 上產生的話，Linux 的 job 可能報 Your bundle only supports platforms … —— 在本機跑一次 bundle lock --add-platform x86_64-linux 再 commit。

自架 runner 上跑的話

重用 workspace 的自架 runner 要關掉 Gradle daemon，否則下一個 job 的 git clean 會以「Directory not empty」失敗；寫法見跑在哪台機器 → 自架 runner 上關掉 Gradle daemon。

跑在雲端還是自架​

Android build 在 Linux 就能跑，GitLab／GitHub 的免費雲端 Linux runner 多半夠用。原生依賴多的 App 例外：在雲端可能一次 10–15 分鐘，甚至磁碟不足（No space left on device）。 什麼時候改自架、自架 Linux 的 shell 道要裝什麼、記憶體與 limit，見跑在哪台機器。

Play 軌道（track）與升版​

  • track：internal（最快、給自己測）→ alpha → beta（封測）→ production（正式）。CI 建議固定推 internal / beta，正式 production 保留人工在 Play Console 放量。
  • versionCode 必須遞增：pubspec.yaml 的 +N 每次上傳要比上次大，否則 Play 退件。可用 $CI_PIPELINE_IID（GitLab）/ github.run_number（GitHub）當 versionCode。
  • Play App Signing：Play 預設幫你保管「正式簽章金鑰」，你 CI 上傳用的是 upload key。upload key 弄丟可申請重設；但務必仍離線備份。

Android e2e（emulator）​

flutter test integration_test 需要 emulator（Linux 上要 KVM 硬體加速）。GitHub hosted Linux 有 KVM、社群 action 一步到位；GitLab 自架 Linux 要確認 /dev/kvm。細節見裝置測試。
