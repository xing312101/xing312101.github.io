FCM 一般通知（公告 / 訊息 / 系統提醒）

一般通知與通話完全無關，可獨立完成、獨立上線。共用前置（Firebase 專案、Firebase↔Flutter 接線、iOS 推播憑證、背景 handler）見 推播基礎設定。

套件​

firebase_messaging 已在前置共用套件。這裡另加前景顯示用的：

dependencies:
  flutter_local_notifications: ^x.y.z   # 前景一般通知

Android​

Firebase / google-services 已在前置接好。這裡補通知權限與預設 channel / icon。

android/app/src/main/AndroidManifest.xml：

<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>

<application ...>
    <!-- FCM 預設通知 channel（要與 Dart 端建立的 channel id 一致）-->
    <meta-data
        android:name="com.google.firebase.messaging.default_notification_channel_id"
        android:value="high_importance_channel" />
    <!-- FCM 預設通知小圖示（白色去背 PNG，放在 res/drawable）-->
    <meta-data
        android:name="com.google.firebase.messaging.default_notification_icon"
        android:resource="@drawable/ic_stat_notification" />
</application>
note

FirebaseMessagingService 由 firebase_messaging 外掛自動註冊，不用自己寫。

iOS​

憑證、Push Notifications capability、AppDelegate FCM 基礎都在前置 → iOS 推播憑證與 capability。一般通知 iOS 端無額外原生設定，顯示邏輯與 Android 共用下方 Dart。

Dart：FcmService​

新建 lib/core/notifications/fcm_service.dart。背景 handler 在前置 → 背景分派器，這裡只管前景顯示、token、點擊導頁：

import 'package:firebase_messaging/firebase_messaging.dart';
import 'package:flutter_local_notifications/flutter_local_notifications.dart';

class FcmService {
  final _fln = FlutterLocalNotificationsPlugin();

  Future<void> init() async {
    // 1) 權限（Android 13+/iOS 都要）
    await FirebaseMessaging.instance.requestPermission();

    // 2) 建立與 manifest 一致的 Android channel（前景通知用）
    const channel = AndroidNotificationChannel(
      'high_importance_channel', '重要通知',
      importance: Importance.high,
    );
    await _fln
        .resolvePlatformSpecificImplementation<
            AndroidFlutterLocalNotificationsPlugin>()
        ?.createNotificationChannel(channel);
    await _fln.initialize(const InitializationSettings(
      // ⚠️ 只給資源名稱，不要加 `@drawable/` 前綴（見下方 caution）
      android: AndroidInitializationSettings('ic_stat_notification'),
      iOS: DarwinInitializationSettings(),
    ));

    // 3) 取得 token → 上傳後端（綁定使用者/裝置，見前置 token 表）
    final token = await FirebaseMessaging.instance.getToken();
    await _sendTokenToServer(token);
    FirebaseMessaging.instance.onTokenRefresh.listen(_sendTokenToServer);

    // 4) 前景：自己用 local notification 顯示
    FirebaseMessaging.onMessage.listen((m) {
      final n = m.notification;
      if (n != null) {
        _fln.show(n.hashCode, n.title, n.body, const NotificationDetails(
          android: AndroidNotificationDetails(
            'high_importance_channel', '重要通知', importance: Importance.high),
        ));
      }
    });

    // 5) 點通知開 App
    FirebaseMessaging.onMessageOpenedApp.listen(_handleOpen);
    final initial = await FirebaseMessaging.instance.getInitialMessage();
    if (initial != null) _handleOpen(initial);
  }

  Future<void> _sendTokenToServer(String? token) async { /* POST 給後端 */ }
  void _handleOpen(RemoteMessage m) { /* 導頁 */ }
}

在前置的最小啟動骨架 main() 上疊加初始化（不是另寫一份 main()）：

// main()：Firebase.initializeApp(...) 與 onBackgroundMessage 已在前置骨架，這裡只加：
await FcmService().init();

背景 / 被殺時的通知（背景分支）​

前置的背景分派器 把非來電訊息導到這裡。一般通知在背景 / 被殺時，只要後端送的是 notification message，就由系統托盤自動顯示，你的 handler 不需特別處理。

caution

想在背景 / 被殺時自己跑邏輯（而非交系統顯示），後端要改送 data message——但那會關掉系統自動顯示、要你自己補。一般公告 / 訊息建議維持 notification message 最省事；來電才用 data-only（見 VoIP → Android 喚醒）。

測試​

  1. 取 token（Dart getToken()，iOS 要真機）。
  2. Firebase Console → Messaging → 送測試訊息到該 token；前景 / 背景 / 殺掉三種狀態都測。

設定檢查清單​

  • google-services.json / GoogleService-Info.plist 已就位（iOS 要拖進 Xcode Target；或用 flutterfire configure）→ 前置
  • Android：google-services plugin、POST_NOTIFICATIONS、預設 channel / icon meta-data
  • iOS：Push Notifications capability、APNs .p8 已上傳 Firebase Console → 前置
  • Dart：要權限、取 token、token 上傳後端、前景 / 背景 / 開啟 handler

常見坑​

  1. GoogleService-Info.plist 只丟資料夾沒拖進 Xcode → 打包不進去，iOS Firebase 初始化失敗。
  2. 前景收到卻不顯示 → 前景不會自動跳系統通知，要自己用 flutter_local_notifications（上面 onMessage）。
  3. iOS 模擬器收不到 → APNs / FCM 推播要真機。

iOS 端完整的「收不到」排查（APNs / .p8 / swizzling / token NULL）見 推播基礎設定 → 疑難排解：iOS 收不到。

疑難排解：Android 收不到 / 不彈 heads-up 橫幅​

完全收不到​

  • google-services.json 放對了嗎（android/app/）、套件名一致嗎？
  • 通知 channel 建了嗎（Android 8+）、Android 13+ 的 POST_NOTIFICATIONS 權限給了嗎？
  • 小圖示是不是全白/透明造成看不到？（先確認圖示名稱格式對，見下方 caution）
同一個圖示，在 XML 和 Dart 要寫成不同格式

這是很容易一路錯到底、而且不會有錯誤訊息的一個坑：

位置正確寫法
AndroidManifest.xml 的 meta-dataandroid:resource="@drawable/ic_stat_notification" ✅ 要前綴
Dart 的 AndroidInitializationSettings / AndroidNotificationDetails(icon:)'ic_stat_notification' ✅ 裸名，不要前綴

@drawable/... 是 XML 專用語法。Dart 這一側的字串會原封不動傳到原生層，由 Resources.getIdentifier(name, "drawable", packageName) 解析——@ 開頭不是合法的資源名稱格式， 查不到就回 0，然後 setSmallIcon(0) 靜靜地什麼也沒設。症狀是「通知有出現但沒有小圖示」或 乾脆不顯示，而你會以為是圖檔本身的問題（全白／透明），往錯的方向查。

兩個延伸陷阱：

  • '@mipmap/ic_launcher' 是很常見的複製貼上，而它錯兩次：多了 @，而且套件解析時的資源類型 寫死是 drawable，所以 mipmap 底下的資源本來就找不到。要用 launcher 圖示就在 drawable 底下放一份，或寫成 'mipmap/ic_launcher'（明確給類型、不加 @）。
  • 官方 README 與 example 用的都是裸名（'app_icon'），可以當基準對照。

順帶提醒通知小圖示的設計限制：Android 5.0+ 只取 alpha 通道，所以要準備白色去背的圖， 彩色圖會變成一團白色方塊。

channel importance 只能降不能升

channel 的 importance 一旦建立就「只能降、不能升」：之後在 code 把 importance 改高，對已安裝過的裝置無效（系統記住第一次建立這個 channel id 時的值）。要移除重裝或改用新的 channel id 才生效。這常造成「明明 code 設 high 卻還是不彈橫幅」的困惑。

有進通知欄、只是不彈 heads-up 橫幅​

先分清是「完全沒收到」還是「有進通知欄、只是沒彈橫幅」——下拉通知欄看得到那則通知嗎？ 看得到＝推播其實正常、onMessage 也有觸發，問題只在 heads-up 被系統抑制，別往「收不到」白查。

heads-up 要彈需同時滿足：channel importance ≥ HIGH、通知 priority high、裝置不在勿擾模式、螢幕已解鎖。照順序刷（<序號> 為 adb devices 列出的裝置序號）：

  1. 勿擾模式（DND）開著 ← 頭號原因。平板／特定情境很容易誤開： 
    adb -s <序號> shell settings get global zen_mode   # 0=關；非 0 就是開著
    adb -s <序號> shell cmd notification set_dnd off    # 直接關掉驗證
  2. channel importance 不是 HIGH（或被降級，見上方 caution）： 
    adb -s <序號> shell dumpsys notification | grep -A5 <你的channel_id>
    # mImportance：4=HIGH（會彈）、3=DEFAULT（只進欄不彈）
  3. 系統實際決策看 logcat： 
    adb -s <序號> logcat | grep -iE "InterruptionStateProvider|Heads"
    # No heads up: suppressed by DND        → 勿擾擋掉（回第 1 點）
    # No heads up: unimportant notification → importance 太低（回第 2 點）
  4. 通知權限沒給（Android 13+）：adb -s <序號> shell dumpsys package <你的套件名> | grep POST_NOTIFICATIONS（granted=true 才有）。
  5. OEM / ROM 前景策略：少數廠牌（平板尤甚）預設不對使用中的 App 彈 heads-up。前四項都排除後才懷疑，換他牌／原生裝置對照確認。

典型案例：「平板前景收到推播但不彈橫幅、手機卻正常」，逐項刷下來往往是平板開了勿擾（zen_mode 非 0、logcat 出現 suppressed by DND），根本不是程式問題。
