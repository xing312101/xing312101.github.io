SIP 通話引擎（通話本體）

這是 VoIP 來電 那個 CallEngine 的 SIP 實作。Push 只「叫醒 + 顯示來電」；真正通話是 SIP。共用前置見 推播基礎設定。

套件選擇​

方案說明適用
sip_ua（純 Dart）SIP over WebSocket(WSS) + WebRTC 媒體，像瀏覽器軟電話PBX 支援 SIP-over-WS（Asterisk res_http_websocket / FreeSWITCH WS / Kamailio）。最容易整合 Flutter
原生 SIP SDK（Linphone / PJSIP）經 platform channel傳統 SIP over UDP/TCP/TLS + RTP既有 PBX 只支援傳統 SIP、或要更完整 codec / NAT 處理

下面以 sip_ua 示範（最常見的 Flutter 路線）。套件：

dependencies:
  sip_ua: ^x.y.z
  flutter_webrtc: ^x.y.z    # 媒體（sip_ua 依賴）

SIP 註冊（CallEngine 的 SIP 實作）​

把 SipService 實作成 VoIP 層的 CallEngine——VoIP 層的 answer() / hangup() / connectAndAnswer() 在這裡對應到 SIP 的註冊與 INVITE 接受：

版本相依

sip_ua 的 UaSettings / CallStateEnum API 跨版本有變動，下面是代表性用法；請對照你 pubspec.yaml 鎖定的版本核對欄位名與列舉值。

import 'package:flutter/foundation.dart';                 // ValueNotifier
import 'package:flutter_webrtc/flutter_webrtc.dart';      // Helper.setSpeakerphoneOn
import 'package:sip_ua/sip_ua.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

class SipService implements SipUaHelperListener, CallEngine {
  final SIPUAHelper _ua = SIPUAHelper();
  Call? _incoming;
  String? _pendingAnswerId;   // 早註冊後要自動接聽的 callId（被殺/背景接聽用）

  // 通話狀態：用 ValueNotifier，CallPage 晚訂閱也能讀到目前值
  final ValueNotifier<CallStatus> _status = ValueNotifier(CallStatus.connecting);
  @override
  ValueListenable<CallStatus> get status => _status;

  void connect() {
    final settings = UaSettings()
      ..webSocketUrl = 'wss://sip.example.com:7443'     // ← 請替換：PBX 的 SIP-over-WSS
      ..uri = 'sip:1001@sip.example.com'                // ← 帳號
      ..authorizationUser = '1001'
      ..password = 'secret'
      ..displayName = '管理室'
      ..transportType = TransportType.WS
      ..register = true
      // TURN/STUN：跨 NAT 一定要設，否則「接通沒聲音」
      ..iceServers = [
        {'urls': 'stun:stun.example.com:3478'},
        {
          'urls': 'turn:turn.example.com:3478',
          'username': 'user', 'credential': 'pass',
        },
      ];
    _ua.addSipUaHelperListener(this);
    _ua.start(settings);
  }

  // CallEngine：被殺/背景接聽用——從零連線並註冊 → 等對應 INVITE → 自動接聽
  @override
  Future<void> connectAndAnswer(String callId) async {
    _pendingAnswerId = callId;   // 記住要接的這通（push callId 與 SIP call-id 一致）
    connect();                   // 註冊；INVITE 到達後在 callStateChanged 自動接
  }

  @override
  void callStateChanged(Call call, CallState state) {
    switch (state.state) {
      case CallStateEnum.CALL_INITIATION:                 // 來電進來（INVITE；若 App 也會撥出，需再查 call.direction == 'INCOMING'）
        _incoming = call;
        _status.value = CallStatus.connecting;
        if (_pendingAnswerId != null) {                   // 早註冊 → 自動接聽
          _pendingAnswerId = null;                        // 只接一次（idempotent）
          answer();
        }
        break;
      case CallStateEnum.PROGRESS:   _status.value = CallStatus.ringing; break;  // 多用於撥出
      case CallStateEnum.CONFIRMED:  _status.value = CallStatus.active;  break;  // 通話建立
      case CallStateEnum.ENDED:
        _status.value = CallStatus.ended;
        _incoming = null; _pendingAnswerId = null;
        break;
      case CallStateEnum.FAILED:
        _status.value = CallStatus.failed;
        _incoming = null; _pendingAnswerId = null;
        break;
      default: break;
    }
  }

  @override
  Future<void> answer() async =>
      _incoming?.answer(_ua.buildCallOptions(true /* voiceOnly */));
  @override
  Future<void> hangup() async => _incoming?.hangup();

  @override
  Future<void> setMuted(bool muted) async {
    if (muted) {
      _incoming?.mute(true, false);     // 只靜音音訊（mute([audio, video])）
    } else {
      _incoming?.unmute(true, false);
    }
  }

  @override
  Future<void> setSpeaker(bool on) async {
    await Helper.setSpeakerphoneOn(on); // flutter_webrtc；iOS 上 CallKit 也會管路由
  }

  void dispose() => _status.dispose();

  @override void registrationStateChanged(RegistrationState s) {}
  @override void transportStateChanged(TransportState s) {}
  @override void onNewMessage(SIPMessageRequest m) {}
  @override void onNewNotify(Notify n) {}
  @override void onNewReinvite(ReInvite r) {}
}

// 提供給 VoIP 層的 callEngineProvider（VoIP 的 main() 會 read 它）
final callEngineProvider = Provider<CallEngine>((ref) {
  final service = SipService();
  ref.onDispose(service.dispose);   // 別漏：否則上面那個 ValueNotifier 不會被釋放
  return service;
});

串接時序：push → 喚醒 → CallKit → 接聽 → SIP​

1. 來電方撥 1001
2. PBX 發現 1001 裝置背景/離線 → 觸發 push（見 VoIP → 後端觸發）
       iOS：APNs VoIP push（topic = bundleId.voip）
       Android：FCM 高優先級 data
3. 裝置喚醒 → flutter_callkit_incoming 顯示來電（iOS 同步 report CallKit）
   ★ 同時就 connect()/註冊 SIP（早註冊）
4. 使用者按「接聽」→ Event.actionCallAccept
5. SIP 已（或正在）註冊 → PBX 把 INVITE 真正送達 → 收到來電 Call
6. answer() 接受 INVITE → WebRTC/RTP 建立 → 開始通話

對應與等待（最容易踩雷）：

  • push 與 INVITE 對應：push payload 帶 callId（與 SIP call-id 一致），App 才知道接的是哪一通。
  • PBX 要「等」：push 發出到 App 註冊上線需 1–3 秒，PBX / Gateway 要讓 INVITE 維持 ringing（或重送），等註冊後才送達，否則使用者按了接聽卻沒 INVITE 可接。

註冊策略（早 / 延遲 / 常駐）​

「什麼時候連 SIP / 註冊」的取捨，引擎無關版見 VoIP → 早 / 延遲 / 常駐連線。SIP 的具體就是 REGISTER：

  • 早註冊（推薦）：收到 push、顯示來電的同時就背景 connect() / REGISTER，按接聽時 INVITE 多半已到。本文 connectAndAnswer() 即此策略。
  • 延遲註冊：接聽才 REGISTER，省電但接通慢、易競態。
  • 常駐註冊：App 啟動就長連線。iOS 背景 / 被殺後 SIP-over-WS 長連線必斷，行動端不可靠；只適合不被殺的固定裝置（壁掛機 / 桌面）。

SIP / WSS 連線注意​

  • TLS：WSS 用有效憑證（自簽要在裝置信任）。
  • NAT / 媒體：WebRTC 需 STUN/TURN（沒有 TURN，跨 NAT 常「接通但沒聲音」）。在 UaSettings.iceServers 設好（上面已示範）。
  • Codec：確認 PBX 與 App 支援同一組（常見 OPUS / PCMU / PCMA）。

端到端流程（SIP 訊令版）​

撥打 1001
   │
   ▼
SIP 伺服器/PBX ──(1001 背景/離線)──► Push Gateway
   │                                ├─ iOS ：POST APNs（apns-push-type: voip, topic = bundleId.voip, .p8 JWT）
   │                                └─ Android：POST FCM v1（priority HIGH, data-only）
   │                                         │
   │                                裝置喚醒 App
   │            ┌───────────────────────────┼───────────────────────────┐
   │            ▼                           ▼                           │
   │ callkit 顯示來電           App 立即 connect()/REGISTER（早註冊）
   │（iOS reportNewIncomingCall）            │
   │            │                           │
   │      使用者按「接聽」◄──────────────────┘（此時多半已註冊完成）
   │            │
   ◄──── INVITE ──► App   App ── 200 OK ──► PBX   PBX ── ACK ──► App
   │
   ▼
RTP / WebRTC 媒體（經 STUN/TURN，CallKit didActivate 啟用音訊）── 通話中 ── BYE 結束

測試​

  1. 先單獨測 SIP 軟電話（不經 push）能註冊、互打、有雙向聲音（驗 TURN）。
  2. 再串 push → 接聽 → SIP 全流程。

設定檢查清單​

  • SIP 帳號可註冊、互打、有雙向聲音（TURN 設好）
  • push payload 帶 callId，與 INVITE 對應
  • PBX 在 push 期間維持 ringing 等 App 上線
  • 已決定註冊策略（早 / 延遲 / 常駐）
  • SipService 實作 CallEngine，由 callEngineProvider 提供給 VoIP 層

常見坑​

  1. 接通但沒聲音（NAT） → 多半缺 TURN（穿透失敗）或 codec 不一致。
  2. 按了接聽卻沒 INVITE → push 與 SIP 註冊的時序沒接好；採早註冊 + PBX 等 App 上線。
  3. 常駐註冊在行動端不可靠 → iOS 被殺後 SIP-over-WS 長連線必斷，改 push 喚醒 + 早註冊。
  4. WSS 自簽憑證連不上 → 裝置不信任，用有效憑證或在裝置安裝信任。
