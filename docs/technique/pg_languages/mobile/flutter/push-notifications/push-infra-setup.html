推播基礎設定（Firebase / APNs / Token / 背景 Handler）

這份是 「一般通知」與「VoIP 來電」共用的推播基礎。先把這裡做好，FCM 一般通知 與 VoIP 來電 只需補各自差異。

文中 com.example.myapp 等皆為佔位符，請替換成你自己的值；套件版本用當下最新穩定版。

帳號 / 服務（共用）​

項目用途備註
Firebase 專案FCM（一般通知 + Android 來電 data）免費即可
Apple Developer 帳號iOS 推播憑證、capability、APNs 金鑰付費帳號
APNs Auth Key (.p8)後端打 APNs（一般 + VoIP 共用一把）一把金鑰同時可發 alert 與 voip
Firebase 服務帳號金鑰 (.json)後端用 FCM HTTP v1 取 OAuth tokenConsole → 專案設定 → 服務帳戶 → 產生新的私密金鑰

SIP 伺服器 / PBX 與 STUN/TURN 屬通話本體，見 SIP 通話引擎；來電時觸發推播的 Push Gateway 見 VoIP → 後端觸發。

建立 Flutter 專案​

從零建立，用 --org 一次定好 bundle id / package（後面所有設定都依賴這個 id）：

flutter create --org com.example --project-name myapp myapp
cd myapp

--org com.example + 專案名 myapp → Android applicationId 與 iOS bundle id 都是 com.example.myapp。

接上 Firebase​

推薦用官方 CLI 自動接線（取代手動下載設定檔）：

dart pub global activate flutterfire_cli
flutterfire configure

它會建立 / 選擇 Firebase App、把 google-services.json 放進 android/app/、把 GoogleService-Info.plist 加進 iOS Target，並產生 lib/firebase_options.dart。

  • Android：android/app/build.gradle.kts 的 plugins {} 需有 id("com.google.gms.google-services")（flutterfire configure 通常已加；若無則手動補，並在 project 層 build 檔加上對應 classpath / plugin）。
  • iOS（手動處理時）：下載 GoogleService-Info.plist 後務必用 Xcode 拖入並勾選 Runner Target，不要只丟資料夾，否則打包不進去、Firebase 初始化失敗。

共用套件（各功能自己的套件列在各自文件）：

dependencies:
  firebase_core: ^x.y.z
  firebase_messaging: ^x.y.z   # 推播訊息：一般通知 + Android 來電 data 都靠它

其餘為各功能專屬，列在各自文件：通知顯示 flutter_local_notifications（FCM 通知）、來電 UI flutter_callkit_incoming（VoIP 來電）、麥克風權限 permission_handler 與 SIP sip_ua / flutter_webrtc（SIP 引擎）。

平台最低版本​

只有要做通話才需要拉高

純做一般通知不需要動最低版本。要做 VoIP / SIP 才需要：

  • iOS：ios/Podfile 設 platform :ios, '13.0'（flutter_webrtc 與 iOS 13+ 的 VoIP 規定都需要）。
  • Android：android/app/build.gradle(.kts) 設 minSdk = 23。

細節見 VoIP 來電 與 SIP 引擎。

iOS 推播憑證與 capability​

  1. Xcode → Runner Target → Signing & Capabilities：
    • + Capability 加 Push Notifications（自動產生 Runner.entitlements，內含 aps-environment）。← 沒這個真機收不到推播。
    • + Capability 加 Background Modes → 勾 Remote notifications。
  2. APNs 金鑰：Apple Developer → Keys → 建立 APNs Auth Key (.p8)，記下 Key ID 與 Team ID，下載 .p8。
  3. Firebase Console → 專案設定 → Cloud Messaging → Apple app：上傳 .p8（填 Key ID / Team ID）。← 沒上傳，FCM 無法送到 iOS。
.p8 只能下載一次

APNs Auth Key 下載後無法再下載，務必保管好。這把金鑰同時用於一般通知與 iOS VoIP 推播。

ios/Runner/AppDelegate.swift — FCM 基礎（VoIP 的 PushKit 擴充見 VoIP → iOS VoIP）：

import Flutter
import UIKit
import FirebaseCore
import FirebaseMessaging

@main
@objc class AppDelegate: FlutterAppDelegate {
  override func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {
    FirebaseApp.configure()
    Messaging.messaging().delegate = self
    application.registerForRemoteNotifications()
    GeneratedPluginRegistrant.register(with: self)
    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }

  // 只有在 FirebaseAppDelegateProxyEnabled = false 時才「必須」自己接這個，
  // 把 APNs token 交給 Firebase；否則 Messaging.getToken() 會回 nil、iOS 收不到 FCM。
  override func application(
    _ application: UIApplication,
    didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data
  ) {
    Messaging.messaging().apnsToken = deviceToken
  }
}

extension AppDelegate: MessagingDelegate {
  func messaging(_ messaging: Messaging, didReceiveRegistrationToken fcmToken: String?) {
    // 把 fcmToken 經 MethodChannel 丟回 Dart → 上傳後端
  }
}

FirebaseAppDelegateProxyEnabled（重要、常踩）​

兩種模式擇一，VoIP 不在此列
  • 預設（不設或 true）：Firebase 自動 swizzling，幫你攔 APNs token 與一般推播 callback，上面 didRegisterForRemoteNotificationsWithDeviceToken 可省略。新手建議維持預設。
  • 設為 false：代表你要自己把 APNs token 餵給 Firebase，就一定要保留 Messaging.messaging().apnsToken = deviceToken，否則 iOS 拿不到 FCM token。
  • 不論 true/false，VoIP / PushKit 永遠要自己做（見 VoIP → iOS VoIP），proxy 不會幫你處理 VoIP。

裝置 token 表​

每個裝置至少存以下欄位。FCM token 與 iOS VoIP token 一定要分開存：

欄位說明
sip_account例如 1001，PBX / 後端用它找裝置
platformios / android
fcm_tokenAndroid 來電 + 兩平台一般通知
voip_token僅 iOS，PushKit 的 VoIP token（見 VoIP → iOS VoIP）
為什麼要分開

iOS 的一般推播走 FCM token、VoIP 推播走 voip_token，兩者來源不同、發送端點也不同（FCM v1 vs 直連 APNs），混用會送錯。

背景 / 被殺時的背景 Handler（分派器）​

這個 top-level handler 處理經 FCM 來的訊息——兩平台的一般通知、以及 Android 的來電 data——再依類型分派：

iOS 來電不走這裡

iOS 的 VoIP 來電由 PushKit 在原生層喚醒（即使 App 被殺），不經過這個 Dart handler、也不經 FCM。所以這個分派器的 incoming_call 分支只對 Android 有意義。iOS 喚醒見 VoIP → iOS VoIP。

import 'package:firebase_messaging/firebase_messaging.dart';

// 背景/被殺時的 handler「必須」是 top-level 函式，並標註 vm:entry-point
@pragma('vm:entry-point')
Future<void> firebaseBackgroundHandler(RemoteMessage message) async {
  // 背景 isolate：若要用 Firebase 其他服務需先 Firebase.initializeApp()
  if (message.data['type'] == 'incoming_call') {
    // → 來電：顯示原生來電 UI（Android）。見 VoIP → Android 喚醒
    //   await showIncoming(message.data['callId']!, message.data['caller'] ?? '來電');
  } else {
    // → 一般通知：交給系統顯示即可。見 FCM 通知 → 背景分支
  }
}

最小啟動骨架（lib/main.dart）——各功能在此之後再 init：

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
  FirebaseMessaging.onBackgroundMessage(firebaseBackgroundHandler);

  // 一般通知：見 FCM 通知（FcmService().init()）
  // 來電：見 VoIP 來電（callkit 事件 + 被殺/背景接聽冷啟）

  runApp(const MyApp());
}

分派去向：

  • type == 'incoming_call' → VoIP → Android 喚醒
  • 其他（一般通知）→ FCM 通知 → 背景分支
Android 來電一定要 data-only

能在背景 / 被殺時走到上面這個 handler 的前提是後端送 data-only、priority: high 的訊息；若帶了 notification 欄位，背景時會被系統托盤接管、你的 handler 不執行。送法見 VoIP → 後端觸發。

疑難排解：iOS 收不到​

「Android 收得到、iOS 收不到」是最常見症狀，幾乎都卡在 APNs 這關。照順序一項項刷掉：

  1. 是不是用實機？ 模擬器收不到遠端推播，先換實體 iPhone。
  2. AppDelegate 有呼叫 registerForRemoteNotifications() 嗎？ 見上方 AppDelegate。少了它、又剛好沒觸發自動註冊 → APNs token 永遠 NULL，且毫無錯誤訊息（詳見下方 warning）。這是「設定都對卻收不到」的隱形頭號原因。
  3. .p8 有沒有上傳 Firebase？ 見 iOS 推播憑證與 capability。沒上傳，一切免談。
  4. Bundle ID 一致嗎？ Xcode 的 Bundle ID ＝ GoogleService-Info.plist 的 BUNDLE_ID ＝ Firebase 上註冊的 iOS App，三者要完全相同。
  5. Push Notifications capability 有加嗎？ 要透過 Xcode 的 Signing & Capabilities 加——手動只塞 aps-environment 進 entitlements 檔不夠。
  6. 使用者按了「允許通知」嗎？ iOS 設定 → 通知 → 你的 App 確認。
  7. swizzling 關了卻沒手動轉 token？ 見 FirebaseAppDelegateProxyEnabled：關閉時一定要保留 Messaging.messaging().apnsToken = deviceToken。
  8. token 有送到後端嗎？ 確認 onTokenRefresh 有重送最新 token。
  9. 後端發給 iOS 的 payload 有 notification 區塊嗎？ 純 data 訊息 iOS 在背景/關閉時不會顯示（Android 卻會）——這是「Android 有、iOS 沒有」的頭號後端原因。
  10. dev/prod 環境對嗎？ Debug 直裝是 development；TestFlight/上架走 production。用 .p8 的話 Firebase 兩者通吃。 但如果 build 是 CI 產的，這一項要另外查——見下方 danger。
CI 用 Manual 簽章時，aps-environment 不會被自動修正

上面第 10 項在本機永遠是對的，因為 Xcode 在 Automatic 簽章下會默默把 aps-environment 改寫成跟 描述檔一致。多數人因此從沒注意過這個 key 的存在。

CI 通常用 Manual 簽章（headless 沒辦法互動登入 Apple ID），那層改寫就不存在——entitlements 檔裡 寫什麼就原封不動簽進二進位。於是 Release build 可能帶著 development 上架。

為什麼特別難查：.p8 金鑰「兩者通吃」（上面第 10 項也提到），所以不會有憑證錯誤。後端往正式 APNs 送，Apple 依 token 判斷環境，回的是 BadDeviceToken——但如果後端沒有把這個回應當錯誤處理， 它看起來就只是「送出成功、裝置沒收到」，兩端都不會報錯。用憑證（.cer）反而會更早失敗。

做法：Debug/Profile 與 Release 用兩份不同的 entitlements 檔，在 Xcode 專案裡讓各 build configuration 的 CODE_SIGN_ENTITLEMENTS 指向對應的那份：

<!-- Debug / Profile 用 -->
<key>aps-environment</key><string>development</string>

<!-- Release 用（CI 走這份） -->
<key>aps-environment</key><string>production</string>

驗收要看「實際簽進去的值」，不是原始碼：

unzip -p <你的>.ipa "Payload/*.app/embedded.mobileprovision" \
  | security cms -D | plutil -p - | grep -i aps-environment

同一類問題適用於 Manual 簽章下的所有 entitlement：entitlements 必須是描述檔所授權範圍的子集， 多寫或寫錯會在 archive 或上傳階段失敗（那種至少有錯誤訊息，比上面的無聲失敗好處理）。

CI 端怎麼設定 Manual 簽章，見 iOS 上架。

swizzling 開著也建議明確註冊一次

即使 FirebaseAppDelegateProxyEnabled 維持開啟，仍建議在 AppDelegate 明確呼叫一次 application.registerForRemoteNotifications()（上方 AppDelegate 已含）。實務上（特別是較新的 Flutter iOS embedding）自動註冊有時不會觸發，導致 getAPNSToken() 永遠 null、iOS 完全收不到、且沒有任何錯誤。重複註冊無害，少了它卻可能整條 APNs 拿不到。

iOS 取 token：NULL 常是假警報

APNs token 是非同步回來的，App 剛啟動就 getAPNSToken() 很可能回 null——這常是假警報。用短暫重試分辨「還沒到」與「真的失敗」：

String? apns;
for (var i = 0; i < 10; i++) {
  apns = await FirebaseMessaging.instance.getAPNSToken();
  if (apns != null) break;
  await Future.delayed(const Duration(milliseconds: 500));
}
// 重試 ~5 秒仍為 null → 才是真的註冊失敗

名詞澄清（很多人搞混）：Team ID ＝ App ID Prefix（10 碼）✅；Key ID ＝ .p8 金鑰的 ID，不是 Bundle ID ❌；Bundle ID 是 App 識別碼，用在建立 App ID／Firebase App。

診斷 log：分不清卡哪關時，Dart 端印 requestPermission() 的 authorizationStatus、APNs token（用上面重試版）、FCM token；原生端補 didFailToRegisterForRemoteNotificationsWithError 讓 Apple 直接說明失敗原因。

  • APNs 重試後仍 NULL 且原生印出 FAILED → 多半描述檔沒帶 Push（回 capability）或沒呼叫 registerForRemoteNotifications()。
  • APNs 有值、FCM 有值卻收不到 → 不是 App 端問題，改用 Console 直發那顆 FCM token：Console 收得到 → 後端 payload 問題（多半缺 notification）；Console 也收不到 → 回查 .p8／Bundle ID。
