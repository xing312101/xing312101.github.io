Crashlytics：閃退與非致命錯誤回報

Firebase Crashlytics 收兩種事件：App 閃退（當機），以及程式自己主動送出的錯誤（非致命）。本篇是 Flutter 的接法、決定要送什麼、事件什麼時候才會出現在後台，以及怎麼在手機上確認真的有記到。

Firebase 專案、google-services.json／GoogleService-Info.plist 的設定見推播基礎設定 → 接上 Firebase。

1. 安裝​

dependencies:
  firebase_core: ^x.y.z
  firebase_crashlytics: ^x.y.z
主版本要跟 firebase_core 配對

FlutterFire 各套件的主版本是一起升的：firebase_crashlytics 4.x 配 firebase_core 3.x，5.x 要 core 4.x。專案已經鎖了某一版 firebase_core 時，加套件要指定相容的那一版，相容關係看 pub.dev 上該版本的 Dependencies。

Android 要加 Crashlytics 的 Gradle plugin（flutterfire configure 會自動加；手動設定的寫法如下）：

// android/settings.gradle.kts 的 plugins 區塊
id("com.google.firebase.crashlytics") version "<版本>" apply false

// android/app/build.gradle.kts
plugins {
    // ...
    id("com.google.gms.google-services")
    id("com.google.firebase.crashlytics")
}

還在用 buildscript 寫法的專案，改加 classpath("com.google.firebase:firebase-crashlytics-gradle:<版本>")。實測 AGP 9.0 搭 plugin 3.0.8 可以編。

iOS 的 SDK 由 CocoaPods／Swift Package Manager 自動帶進來，不用改原生程式；但上架時要另外上傳 dSYM，不然後台什麼都看不到，見 iOS 上架 → 用了 Crashlytics：dSYM 要另外上傳。

2. 接上閃退回報​

import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_crashlytics/firebase_crashlytics.dart';
import 'package:flutter/foundation.dart';
import 'package:flutter/material.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();
  // 只在 release 接：debug 時照樣顯示紅畫面，開發中的錯誤不會送上去
  if (kReleaseMode) {
    FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;
    // FlutterError 接不到的非同步例外
    PlatformDispatcher.instance.onError = (error, stack) {
      FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
      return true;
    };
  }
  runApp(const MyApp());
}

3. 送非致命錯誤​

App 沒閃退、但你想知道的錯誤，用 recordError 主動送：

FirebaseCrashlytics.instance.recordError(error, stack, reason: '加入頻道失敗', fatal: false);

實際寫進程式時，建議包成可以注入的函式，外面再包一層 try/catch：

import 'dart:async';

typedef ErrorReporter = void Function(Object error, StackTrace? stack, String reason);

/// 正式版的回報。回報本身失敗時吞掉：不能因為回報失敗，拖垮原本要收尾的流程。
void reportToCrashlytics(Object error, StackTrace? stack, String reason) {
  try {
    unawaited(FirebaseCrashlytics.instance
        .recordError(error, stack, reason: reason, fatal: false)
        .catchError((_) {}));
  } catch (_) {}
}

class CallController {
  CallController({ErrorReporter? reportError})
      : _reportError = reportError ?? reportToCrashlytics;

  final ErrorReporter _reportError;

  Future<void> join() async {
    try {
      // ...
    } catch (e, s) {
      _reportError(e, s, '加入頻道失敗');
      rethrow; // 照原本的流程收尾、顯示錯誤
    }
  }
}
  • 為什麼要 try/catch：單元測試沒有初始化 Firebase，FirebaseCrashlytics.instance 一取就丟例外。沒包的話，任何走到錯誤路徑的測試都會因為「回報」而失敗，正式環境裡回報出錯也會打斷原本的收尾。
  • 為什麼要可以注入：測試換成一個把呼叫記下來的假函式，就能驗證「該送的有送、不該送的沒送」；另外再寫一個測試，確認正式版的函式在沒有 Firebase 時不會丟例外。
  • 決定送什麼：只送「沒辦法從別處知道」的錯誤，例如第三方 SDK 本身丟的例外、連線被拒。網路斷線、後端回 4xx／5xx 這類每天大量發生、又有別的地方可以查的，送了只會把後台淹沒。

4. 什麼時候會出現在後台​

  • iOS 的非致命錯誤不是當下送出：先寫進 App 自己的資料夾，下次開 App 才上傳。測試時送完要把 App 關掉再開一次。
  • iOS 還要有 dSYM：沒上傳的話，後台只會顯示「這個應用程式發生了 N 次未處理的當機情況，請上傳 N 個 dSYM 檔案」，連非致命錯誤也算在裡面，問題清單裡看不到，見 iOS 上架。
  • 後台的「事件類型」：中文介面是「當機」和「一般」，「一般」就是非致命；Android 另外還有 ANR。找自己送的錯誤要切到「一般」。

5. 在手機上確認有沒有記到​

後台還沒出現時，先看手機上的檔案，分得出是「沒記到」還是「記到了、還沒傳／傳了但缺 dSYM」。iOS 的紀錄在 App 資料夾的 Library/Caches/com.crashlytics.data/<bundle id>/v5/ 底下：

位置意思
reports/active/<報告 ID>/這次執行的紀錄；非致命錯誤存成 custom_exception_*.clsrecord
reports/prepared/、reports/processing/下次啟動時拿來處理的上一次紀錄，處理完就清掉
settings/settings.json從後台下載的設定；app.status 是 activated 代表這個 App 的 Crashlytics 已經開通

用 devicectl 列出、拉回 Mac（開發簽章的 build 實測可以；用法見 iOS：讓 AI 用 WebDriverAgent 操作實機 → 裝置管理）：

B=com.example.app
xcrun devicectl device info files --device <Identifier> \
  --domain-type appDataContainer --domain-identifier $B \
  --subdirectory Library/Caches/com.crashlytics.data/$B/v5
xcrun devicectl device copy from --device <Identifier> \
  --domain-type appDataContainer --domain-identifier $B \
  --source Library/Caches/com.crashlytics.data/$B/v5/reports/active/<報告 ID>/custom_exception_a.clsrecord \
  --destination ./custom_exception_a.clsrecord

.clsrecord 一行一個 JSON，字串欄位是 hex 編碼，解開來看：

python3 - custom_exception_a.clsrecord <<'EOF'
import json, sys
for line in open(sys.argv[1]):
    e = json.loads(line).get("exception")
    if e:
        print(bytes.fromhex(e["name"]).decode(), "|", bytes.fromhex(e["reason"]).decode())
EOF
一次性的串接測試

想確認整條路都通（套件、後台開通、iOS 的 dSYM），可以在 main() 暫時加一行，啟動就送一筆認得出來的錯誤：

FirebaseCrashlytics.instance.recordError(
    StateError('串接測試'), StackTrace.current, reason: '[測試] 串接確認');

裝到手機開一次、再開第二次（iOS 這時才上傳），在後台「一般」裡看到之後，記得拿掉這行，也把手機上那一版換掉，不然每次開 App 都會送一筆。
