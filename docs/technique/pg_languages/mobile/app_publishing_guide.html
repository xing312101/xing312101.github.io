App 上架教學（Google Play + Apple App Store）

對象：第一次操作 Flutter App 上架的人。前置：你已能在本機用 flutter run 跑起一個 App。 通用約定：

  • 以下 Bundle ID / 套件名一律以 com.yourcompany.yourapp 當範例，請換成你自己的。
  • 指令用 flutter 開頭；若用 FVM 管理版本，全部改成 fvm flutter。
  • App 版本定義在 pubspec.yaml 的 version:（版本名+建置號）。
  • Android 設定檔可能是 build.gradle(Groovy) 或 build.gradle.kts(Kotlin DSL)，本文以 Kotlin DSL 示範，Groovy 語法略有差異會標註。

0. 先搞懂大方向​

Google Play（Android）Apple App Store（iOS）
開發者帳號Google Play Console，一次性 US$25Apple Developer Program，每年 US$99
需要的機器Windows/Mac 皆可一定要有 Mac + Xcode
產出檔案.aab（App Bundle，上架用）.ipa（Archive 上傳用）
簽章自己產生 keystore（上傳金鑰）Apple 憑證 + 描述檔（Xcode 可自動管理）
審核時間數小時 ~ 數天約 1 ~ 3 天

iOS 沒有 Mac 幾乎做不了（Xcode 只有 macOS）。Android 在 Windows 就能完成。

1. 共同前置準備（兩個平台都要先做）​

1-1. 決定版本號​

每次要送審的新版本，都要更新 pubspec.yaml：

version: 1.0.0+1
#        ^^^^^ 版本名(給使用者看的)  ^ 建置號(每次上傳都要+1，不可重覆)
  • 第一次上架就用 1.0.0+1。
  • 之後每次上傳（即使版本名沒變）建置號一定要往上加，否則商店會拒絕（重覆的 build number）。

1-2. App 圖示​

推薦用 flutter_launcher_icons 套件一鍵產生各尺寸圖示。在 pubspec.yaml 設定來源圖後：

flutter pub get
dart run flutter_launcher_icons

也可以手動在 android/app/src/main/res/mipmap-* 與 iOS 的 Assets.xcassets/AppIcon 放圖，但用套件最省事。

1-3. 權限與隱私（審核會看）​

盤點你的 App 有用到的權限（相機、相簿、麥克風、定位、藍牙、NFC、推播…），兩個商店都會要求「說明用途」並提供隱私權政策：

  • 一定要準備一個可公開的隱私權政策網址（URL），Google 與 Apple 都會要。
  • iOS 的用途說明字串放在 ios/Runner/Info.plist（如 NSCameraUsageDescription、NSPhotoLibraryUsageDescription…）。送審前確認每個有用到的權限都有清楚、具體的說明句子。
  • Android 權限宣告在 android/app/src/main/AndroidManifest.xml。

若 App 有推播通知，iOS 端另需設定：在 Apple Developer 的 App ID 開啟 Push Notifications 能力、在 Xcode 的 Signing & Capabilities 加入 Push Notifications（用 FCM 者通常再加 Background Modes → Remote notifications），並到 Apple Developer → Keys 建立 **APNs 驗證金鑰（.p8）**上傳到你的推播服務（如 Firebase Cloud Messaging）。詳細設定以 Apple 與所用推播服務（如 Firebase）的官方文件為準。

2. Android / Google Play 上架​

步驟 A：註冊 Google Play Console​

  1. 到 https://play.google.com/console 用 Google 帳號登入。
  2. 選「建立開發者帳號」，付 US$25（一次性）。
  3. 若是公司帳號，需通過身分/組織驗證（可能要等 1~2 天）。

步驟 B：產生「上傳金鑰」keystore（只做一次，務必備份）​

在專案根目錄開終端機執行（keytool 隨 JDK 附帶；找不到就用 Android Studio 內附的 JDK 路徑）：

keytool -genkey -v -keystore $env:USERPROFILE\upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
  • 會問你密碼、姓名、單位等，記下來。
  • 產生的 upload-keystore.jks 與密碼請異地備份。掉了會無法再更新這個 App（除非申請金鑰重設，很麻煩）。

名詞：Google Play 用「Play App Signing」。你上傳用的是上傳金鑰；Google 端另外保管應用程式簽署金鑰。第一次建立 App 時 Play Console 會引導你啟用（建議直接讓 Google 代管）。

步驟 C：把簽章接進專案​

  1. 在 android/ 底下建立 key.properties（不要進 git，加到 .gitignore）：

    storePassword=你的store密碼
    keyPassword=你的key密碼
    keyAlias=upload
    storeFile=C:/Users/你的帳號/upload-keystore.jks

  2. 編輯 android/app/build.gradle.kts：

    最上方（plugins 區塊之前）載入設定：

    import java.util.Properties
    import java.io.FileInputStream

    val keystoreProperties = Properties()
    val keystorePropertiesFile = rootProject.file("key.properties")
    if (keystorePropertiesFile.exists()) {
        keystoreProperties.load(FileInputStream(keystorePropertiesFile))
    }

    android { ... } 內加入簽章設定，並讓 release 用它：

    android {
        // ...namespace / defaultConfig 等維持原樣...

        signingConfigs {
            create("release") {
                keyAlias = keystoreProperties["keyAlias"] as String
                keyPassword = keystoreProperties["keyPassword"] as String
                storeFile = (keystoreProperties["storeFile"] as String?)?.let { file(it) }
                storePassword = keystoreProperties["storePassword"] as String
            }
        }

        buildTypes {
            getByName("release") {
                signingConfig = signingConfigs.getByName("release")
                // 若之後要縮小體積可再開 minify/shrinkResources
            }
        }
    }

    Groovy(build.gradle) 語法略有不同（signingConfigs { release { ... } }、def keystoreProperties = ...），原理相同。 沒接簽章直接 build release，Flutter 會用 debug 金鑰簽，商店會拒絕。

步驟 D：Build 上架檔（AAB）​

flutter clean
flutter pub get
flutter build appbundle --release
  • 產出：build/app/outputs/bundle/release/app-release.aab ← 這個檔案拿去上傳。
  • （.aab 是給商店的；你平常裝在手機測的 .apk 不是上架用的。）

步驟 E：在 Play Console 建立 App 並填資料​

  1. Play Console →「建立應用程式」，填名稱、預設語言、免費/付費。
  2. 左側逐項完成「設定/內容」（有打勾清單）：
    • 應用程式內容：隱私權政策網址、廣告聲明、資料安全（Data safety）（要誠實勾選你蒐集/使用哪些資料，例如相機、通知）。
    • 內容分級（填問卷自動產生分級）。
    • 目標對象與內容、政府 App/新聞 等聲明（依實際情況）。
  3. 商店設定（Store listing）：
    • App 名稱、簡短說明、完整說明。
    • 圖示 512x512 PNG、主題圖（Feature graphic） 1024x500。
    • 手機截圖至少 2~8 張。

步驟 F：用測試軌道先跑一輪，再上正式​

建議順序：內部測試 → 封閉測試 → 開放測試 → 正式版。

  1. 左側「測試 → 內部測試」→ 建立版本 → 上傳 app-release.aab。
  2. 加測試人員（Email 清單），拿到測試連結安裝驗證。
  3. 沒問題後，到「正式版」建立版本、上傳同一個或新的 .aab、送審。
  4. 審核通過後可選擇「分階段推出」（先放量給部分使用者）。

3. iOS / Apple App Store 上架（需要 Mac）​

步驟 A：加入 Apple Developer Program​

  1. 到 https://developer.apple.com/programs/ 用 Apple ID 加入，付 US$99/年。
  2. 公司帳號需要 D-U-N-S 編號與驗證（個人帳號較快）。

步驟 B：在 App Store Connect 建立 App 記錄​

  1. 到 https://appstoreconnect.apple.com →「我的 App → +」。
  2. 平台選 iOS、填名稱、語言，Bundle ID 選 com.yourcompany.yourapp。
    • 若清單裡沒有這個 Bundle ID：先到 https://developer.apple.com/account → Identifiers → 新增一個 App ID（com.yourcompany.yourapp），依需求勾選 Push Notifications、NFC 等能力。
  3. 設定 SKU（自訂唯一字串，例如 yourapp001）。

步驟 C：憑證與描述檔（最省事＝讓 Xcode 自動管理）​

  1. 用 Xcode 開專案：open ios/Runner.xcworkspace（是 .xcworkspace，不是 .xcodeproj）。
  2. 左側點 Runner → Signing & Capabilities：
    • 勾 Automatically manage signing。
    • Team 選你的 Apple Developer 團隊。
    • 確認 Bundle Identifier = com.yourcompany.yourapp。
    • Xcode 會自動幫你建立/下載 Distribution 憑證與 Provisioning Profile。
  3. Capabilities 依實際需要加，例如：Push Notifications（有推播時）、Near Field Communication Tag Reading（有 NFC 時）等。

手動作法（進階，通常不需要）：到 Developer 網站建立 Distribution Certificate + App Store Provisioning Profile 再匯入 Xcode。第一次建議直接用自動管理。

步驟 D：確認 iOS 權限說明字串​

ios/Runner/Info.plist 內每個有用到的權限都要有面向使用者的說明，否則審核會退件。常見的有：

  • NSCameraUsageDescription（相機）
  • NSPhotoLibraryUsageDescription（相簿）
  • NSMicrophoneUsageDescription（麥克風）
  • NSLocationWhenInUseUsageDescription（定位）
  • NFCReaderUsageDescription（NFC）

只需保留你實際有用到的，並把說明寫具體（籠統的說明會被退件）。

步驟 D-2：出口合規宣告（省去 TestFlight 每次問加密）​

上傳 TestFlight/App Store 時，Apple 會問「是否使用加密」。若你的 App 只用標準加密 （HTTPS/TLS、系統 Keychain/Keystore、標準演算法），屬於豁免範圍，在 ios/Runner/Info.plist 加這個 key 就不會每個 build 都被問：

<key>ITSAppUsesNonExemptEncryption</key>
<false/>

這是宣告「沒有用非豁免的加密」，不是「沒有用加密」。幾乎所有 App 都用 HTTPS， 但那是豁免的，填 false 正確。只有自研/非標準加密演算法才要填 true（並另備出口 合規文件 CCATS）。

步驟 E：Build 並上傳​

兩種方式擇一：

方式 1：Flutter 指令 + Transporter（較簡單）

flutter build ipa --release
  • 產出：build/ios/ipa/*.ipa（這個 .ipa 就是要上傳的檔案）。

接著用 Transporter 上傳（Transporter 只有 macOS 版）：

  1. 安裝 Transporter：Mac App Store 搜尋「Transporter」（Apple 官方、免費）並安裝。
  2. 登入：開啟 Transporter → 用你的 Apple ID 登入（就是加入 Apple Developer Program 的那組帳號）。若帳號有開雙重驗證（2FA），會要你輸入傳到其他 Apple 裝置的 6 位數驗證碼。

    若一直登入失敗，到 Apple ID 網站 → 登入與安全性 → App 專用密碼，產生一組後改用它登入。

  3. 加入 build：把 build/ios/ipa/xxx.ipa 直接拖進 Transporter 視窗（或按左下角 ＋ → Add App，選那個 .ipa）。
  4. 等上傳前檢查：Transporter 會自動做一次驗證（憑證、描述檔、Info.plist、建置號等）。若出現紅色錯誤，先照它的說明修正（常見錯誤見下）；沒問題就會顯示可以遞送。
  5. 上傳：按右下角 Deliver（遞送）。跑完出現綠色勾勾＝上傳成功。
  6. 等處理：到 https://appstoreconnect.apple.com → 你的 App → TestFlight / 版本，等 10~30 分鐘，build 會從「處理中（Processing）」變成可選取；就緒後即可指派 TestFlight 測試員或加入送審（接續步驟 F）。

Transporter 上傳常見錯誤：

  • 建置號重複（The bundle version has already been used）：pubspec.yaml 的建置號（+N）跟先前上傳過的重覆了 → +N 加一、重新 flutter build ipa --release 再上傳。
  • 缺加密合規宣告：先做步驟 D-2，在 Info.plist 加 ITSAppUsesNonExemptEncryption=false，即可免每次被問。
  • 簽章無效（Invalid Code Signing / no valid provisioning profile）：憑證/描述檔沒設好 → 回步驟 C 用「Automatically manage signing」讓 Xcode 產生憑證與描述檔，再重新 flutter build ipa --release。
  • Invalid entitlement / NDEF is disallowed（用到 NFC 時）：見步驟 D 與 §6，Runner.entitlements 的 NFC formats 只保留 TAG。

Transporter 只負責「把 .ipa 送到 App Store Connect」；送達之後的 TestFlight 測試與送審，一律在 App Store Connect 網站上操作（步驟 F）。

方式 2：Xcode Archive（可即時看錯誤）

  1. 用 Xcode 開 ios/Runner.xcworkspace（不是 .xcodeproj）。
  2. 上方裝置選單選 「Any iOS Device (arm64)」——選模擬器的話 Product → Archive 會是灰色不能點。
  3. 選單 Product → Archive，等它跑完 release 建置。
  4. 完成後 Organizer 視窗（沒跳就 Window → Organizer）→ 選該 archive → Distribute App：
    • 選 App Store Connect（新版 Xcode 寫 TestFlight & App Store）→ Upload
    • 簽章保持 Automatically manage signing → 檢視摘要 → Upload

上傳後要等 10~30 分鐘，App Store Connect 的「TestFlight/版本」才會出現這個 build（先顯示「處理中 Processing」）。就緒後到 TestFlight 分頁指派測試員：內部測試員立即可用；外部測試員需先過一次輕量審核。

步驟 F：TestFlight 測試 → 送審​

  1. App Store Connect → 你的 App → TestFlight：邀請內部/外部測試員先裝來測。
    • 外部測試需先過一次輕量審核。
  2. 確認沒問題後，到 App 的「App Store」分頁建立版本：
    • 上傳截圖（每種必要尺寸：6.7"、6.5"、5.5" iPhone，若支援 iPad 也要 iPad 截圖）。
    • 填說明、關鍵字、支援網址、隱私權政策網址。
    • App 隱私（App Privacy）：申報蒐集的資料類型。
    • 選剛上傳的 build → 加入審核 → 送出。
  3. 審核通過後可選「自動發佈」或「手動發佈」。

4. 之後每次「改版更新」的最短流程​

  1. 改 pubspec.yaml 的版本：1.0.1+2（建置號一定要 +1）。
  2. Android： 
    flutter build appbundle --release
    → Play Console 正式版建立新版本 → 上傳新的 .aab → 送審。
  3. iOS： 
    flutter build ipa --release
    → Transporter 上傳（或 Xcode Archive）→ App Store Connect 選新 build → 送審。

5. 送審前檢查清單（Checklist）​

共同：

  • 版本建置號有 +1（沒重覆）
  • 隱私權政策 URL 可公開開啟
  • App 圖示、截圖備妥
  • flutter analyze 零問題、正式機實測過主要流程

Android：

  • key.properties 與 upload-keystore.jks 已備份、未進 git
  • build.gradle(.kts) 的 release 有接 signingConfig
  • 產出 app-release.aab（不是 apk）
  • Play Console：資料安全、內容分級、商店設定都打勾完成

iOS：

  • Mac + Xcode，開的是 .xcworkspace
  • Signing 團隊正確、Bundle ID 對
  • 需要的 Capabilities 已加（如 Push / NFC）
  • Info.plist 權限說明字串齊全且具體
  • （選）Info.plist 加 ITSAppUsesNonExemptEncryption=false 免每次問加密合規
  • 用 NFC 者：entitlements 的 nfc.readersession.formats 未含被禁的 NDEF（只留 TAG）
  • 若已啟用 SPM：Runner.xcodeproj/project.pbxproj 與 ios/**/swiftpm/（含 Package.resolved）已 commit 進 git（否則換機 / CI 會重現 Missing package product 錯誤）
  • Archive 上傳後 build 有出現在 App Store Connect

6. 常見問題​

  • build 失敗且提到 integration_test / GeneratedPluginRegistrant：先 flutter clean 再 build（產生檔被殘留污染時會這樣）。
  • iOS build 報「XXX-Swift.h couldn't be opened / no such file」：多半是（a）開成 .xcodeproj 而非 .xcworkspace（CocoaPods 沒整合進來），或（b）flutter clean 後沒重跑 pod install。解法：開 .xcworkspace；或在 Mac 跑 flutter clean && flutter pub get && cd ios && pod install --repo-update、刪 ~/Library/Developer/Xcode/DerivedData 再 build；最省事是直接用 flutter build ipa --release（會自動 pod install＋產生插件標頭）。
  • iOS build 報「missing package product 'FlutterFramework'」：較新版 Flutter 以 Swift Package Manager（SPM）整合 iOS，Xcode 專案會引用一個叫 FlutterFramework 的 Swift Package product；當 Flutter 的 SPM 產生檔（ios/Flutter/ephemeral/）還沒生出來、或 Xcode 的套件快取壞掉時就會找不到而報這個錯。常見觸發：剛跑完 flutter clean、切換 Flutter / FVM 版本、或沒經 Flutter 工具就直接在 Xcode build。依序排除：(a) 先在專案根目錄跑 flutter pub get（會重新產生 Flutter 的 SPM 檔）；(b) 確認開的是 ios/Runner.xcworkspace 而不是 .xcodeproj；(c) Xcode 選單 File → Packages → Reset Package Caches，再 Resolve Package Versions；(d) 刪 ~/Library/Developer/Xcode/DerivedData 後重新 build；(e) 最省事：直接用 flutter build ipa --release，Flutter 工具會自動重建 ephemeral 並解析 SPM。
  • 上面都試了還是一整排 Missing package product（FlutterFramework、FirebaseMessaging、DKImagePickerController… 一次噴很多）：一次噴一整排代表是「整個 SPM 套件圖解析失敗」，而非單一套件缺檔，最常見的真兇是 Xcode 沒有「完全結束」。要點：
    • 「關視窗」不等於「關 App」：關掉專案視窗後，Xcode 本體常仍在背景解析套件。務必 Cmd+Q 完全結束（或 osascript -e 'tell application "Xcode" to quit'）。
    • 若你在 Xcode 開著的同時又在命令列跑解析／build，兩邊會搶同一份套件檔而衝突，典型錯誤是 input file '.../[某套件]/Package.swift' was modified during the build，甚至連 DerivedData 都因被鎖住而刪不掉。
    • 乾淨修復步驟：完全結束 Xcode → rm -rf ~/Library/Developer/Xcode/DerivedData/* → rm -rf ~/Library/Caches/org.swift.swiftpm（SPM 全域快取）→ 單獨跑一次 cd ios && xcodebuild -resolvePackageDependencies -workspace Runner.xcworkspace -scheme Runner（初次會下載全部套件，需等一下）→ 全部顯示 resolved 後再開 Runner.xcworkspace build。
    • 原則：Xcode 正在解析套件（左上有進度）時，不要同時跑 flutter build 或其他命令列建置，即可避免這種競爭。
  • 啟用 SPM 後 ios/Podfile.lock 突然少了很多套件：這是正常現象，不是套件被刪。改用 SPM 後，多數插件（Firebase、相機、影像選取等）改由 SPM 管理並記錄在 Package.resolved，CocoaPods 只會保留少數「尚未支援 SPM」的插件，所以 Podfile.lock 會從數十個 Pod 縮到剩幾個。這是 SPM + CocoaPods 的混合模式，功能不變。（flutter pub get 時若看到「The following plugins do not support Swift Package Manager」的警告，指的就是這些仍走 CocoaPods 的插件，屬正常。）
  • iOS 上傳被拒「Invalid entitlement / NDEF is disallowed」（用到 NFC 時）：新版 iOS SDK 下 com.apple.developer.nfc.readersession.formats 不再接受 NDEF 值。把 ios/Runner/Runner.entitlements 的該陣列改成只留 <string>TAG</string>（移除 NDEF）；TAG 已涵蓋讀取卡片 UID/序號。
  • 上傳被拒「build number 已存在」：pubspec.yaml 的建置號重覆了，+N 往上加一再重 build。
  • Play 拒絕「未簽章」或「用 debug 金鑰」：build.gradle(.kts) 沒接 release signingConfig。
  • Apple 退件「權限用途不清」：Info.plist 對應的 UsageDescription 寫得太籠統，改成具體說明用途。
  • iOS 上傳成功但 build 沒出現：等 10~30 分鐘；仍沒有就看 App Store Connect 是否寄了「缺少合規資訊/加密宣告」的信要你補。
  • 忘記/遺失 Android 上傳金鑰：到 Play Console 申請「重設上傳金鑰」（需 Google 協助，會有等待期）。故務必備份。

本檔為操作參考，實際商店介面文字/步驟 Google、Apple 會不定期調整，以官方畫面為準。
