Quartz 5 + Obsidian 數位花園架設指南

本教學適用於希望建立個人知識庫（Digital Garden）或日文筆記網站的創作者。這套架構將 Obsidian 的本地純文字寫作體驗與 Quartz 5 的靜態網站生成能力相結合，既能維護資料的 100% 掌控權，又能免費發布至網路上。

[!NOTE] 版本說明 本文以 Quartz v5.0.0 為準（2026 年 10 月整理）。Quartz 5 是一次全面改寫，設定檔、外掛與部署方式都和 Quartz 4 不同。若你手上已有 Quartz 4 網站，請直接看 從 Quartz 4 升級。

核心架構說明​

┌──────────────────┐   Git Push    ┌──────────────────┐   Auto Build   ┌────────────────────┐
│  Obsidian        ├──────────────►│  GitHub Repo     ├───────────────►│  Cloudflare Pages  │
│  (本機 Markdown) │               │  (私有/公開)     │                │  (或 GitHub Pages) │
└──────────────────┘               └──────────────────┘                └─────────┬──────────┘
                                                                                 │
                                                                          公開訪客瀏覽網站
  • Obsidian：本地端 Markdown 編輯器，負責資料儲存與日常寫作。
  • Quartz 5：專為 Obsidian 設計的靜態網站生成器（SSG），自動將雙向連結、標籤、Callout、Canvas、Bases 渲染成網站。
  • GitHub：託管網站原始碼與筆記檔案。
  • Cloudflare Pages / GitHub Pages：提供免費的全球 CDN 託管與自動化建置。

Quartz 5 的主要變化（相較於 Quartz 4）​

項目Quartz 4Quartz 5
設定檔quartz.config.ts + quartz.layout.ts（TypeScript）quartz.config.yaml（YAML），進階覆寫才用 quartz.ts
外掛內建在 Quartz 原始碼中獨立的社群外掛（quartz-community），以 npx quartz plugin 管理，版本鎖定於 quartz.lock.json
版面配置在 quartz.layout.ts 中排列元件每個外掛在 YAML 中宣告自己的 layout.position 與 priority
初始化選擇 Empty Quartz 等選項選擇範本：default、obsidian、ttrpg、blog
預設分支v4v5
網址大小寫保留原檔名大小寫一律轉小寫並以連字號取代空白（如 My Notes/Hello World.md → /my-notes/hello-world）
Node.js 需求v18.14+v22 以上（npm v10.9.2 以上）

前置準備​

在開始前，請確保電腦已安裝以下軟體：

  1. Node.js v22 或以上版本（可用 node -v 確認）
  2. Git 版本控制工具
  3. Obsidian 本地筆記軟體
  4. GitHub 帳號

第一步：建立與初始化 Quartz 專案​

1. 取得 Quartz​

方法 A：使用 GitHub 範本（推薦）

這個方法會直接在你的帳號下建立儲存庫，之後不必再手動修改 Git remote。

  1. 前往 Quartz 官方儲存庫，點選 Use this template → Create a new repository。
  2. 填入儲存庫名稱（例如 japanese-notes），選擇 Private（私有） 或 Public（公開），按下 Create repository。
  3. 將新的儲存庫 Clone 到本機：
git clone https://github.com/YOUR_USERNAME/japanese-notes.git
cd japanese-notes

方法 B：直接 Clone 官方儲存庫

git clone https://github.com/jackyzha0/quartz.git japanese-notes
cd japanese-notes

使用方法 B 時，推送前需要把 origin 改指向你自己的儲存庫，請參考 第五步。

2. 安裝依賴套件​

npm i

之後在其他電腦 Clone 自己的儲存庫時，改用 npm ci，會依照 lockfile 安裝，速度較快也較穩定。

3. 初始化 Quartz 設定​

執行 Quartz 提供的互動式初始化工具：

npx quartz create

畫面上會依序詢問：

  • Template（範本）：Obsidian 使用者請選 obsidian，它會啟用完整的 Obsidian Flavored Markdown（Wikilinks、Callout、Mermaid 等），並自動把連結解析設為 shortest（與 Obsidian 預設一致）。
  • Content strategy（內容匯入方式）：
    • new：建立空的 content/ 資料夾。
    • copy：從既有資料夾（如 Obsidian Vault）複製筆記進來，最安全，不會動到原始檔案。
    • symlink：建立符號連結到既有 Vault，在 Obsidian 的修改會即時反映到 Quartz。
  • Base URL：網站部署後的網址，例如 japanese-notes.pages.dev。不要加 https://，結尾也不要加 /。
  • Link resolution（連結解析方式）：選擇 obsidian 範本時會自動跳過。

也可以一行指令完成（以 symlink 連結既有 Vault 為例）：

npx quartz create --template obsidian --strategy symlink --source ~/Documents/MyVault

4. 安裝外掛​

Quartz 5 的功能（搜尋、關聯圖、目錄、Explorer 等）都拆成獨立外掛，範本裡引用的外掛需要先安裝：

npx quartz plugin install --from-config

外掛會被下載到 .quartz/plugins/（已列在 .gitignore，不會被提交），版本則鎖定在 quartz.lock.json。

若有外掛安裝或建置失敗，執行 npx quartz plugin install --latest 將所有外掛更新到最新版通常就能解決。

第二步：配置 Obsidian 與內容管理​

Quartz 預設會讀取專案內 content/ 資料夾下的所有 Markdown 檔案。若初始化時選擇 symlink，content/ 會直接指向你的 Obsidian Vault；否則可以直接用 Obsidian 開啟 content/ 資料夾作為 Vault。

推薦的專案目錄結構​

japanese-notes/
├── content/               <--- 所有 Markdown 筆記放在這裡（Obsidian Vault）
│   ├── index.md           <--- 網站首頁（必須保留）
│   ├── 文法/
│   │   └── N3-動詞變形.md
│   └── 單字/
│       └── 常用副詞.md
├── quartz.config.yaml     <--- 網站核心設定檔（標題、語系、主題、外掛、版面）
├── quartz.lock.json       <--- 外掛版本鎖定檔（請提交到 Git）
├── quartz.ts              <--- 進階 TypeScript 覆寫（一般不需修改）
├── .quartz/plugins/       <--- 已安裝的外掛（自動產生，不提交）
└── package.json

必備的首頁檔（content/index.md）​

建立 content/index.md 作為網站入口點：

---
title: 我的日文學習數位花園
---

# 歡迎來到我的日文筆記本 🌸

這裡記錄了我學習日文文法、單字與閱讀的個人筆記。

## 熱門主題
* [[文法/N3-動詞變形|N3 動詞變形總整理]]
* [[單字/常用副詞|必背 N3 副詞]]

基本網站設定（quartz.config.yaml）​

npx quartz create 產生的 quartz.config.yaml 開頭是 configuration 區塊，日文筆記網站建議至少調整以下欄位：

configuration:
  pageTitle: 我的日文學習數位花園
  locale: zh-TW                     # 介面文字（搜尋、目錄、日期格式）改為繁體中文；也可用 ja-JP
  baseUrl: japanese-notes.pages.dev # 不含 https://
  analytics: null                   # 範本預設為 plausible，不使用可設為 null
  ignorePatterns:                   # 不發布的資料夾／檔案
    - private
    - templates
    - .obsidian
  theme:
    typography:
      header: Noto Sans TC
      body: Noto Sans JP
      code: IBM Plex Mono

[!TIP] 中日文字型 Quartz 預設的 Schibsted Grotesk / Source Sans Pro 沒有中日文字形，中日文會退回系統字型。改用 Google Fonts 的 Noto Sans JP（日文字形）或 Noto Sans TC（繁中字形）可讓各平台顯示一致。日文漢字與繁中漢字字形略有不同，以日文為主的筆記建議內文用 Noto Sans JP。

不想公開的筆記​

  • 在筆記 frontmatter 加上 draft: true，該篇就不會被發布。
  • 想反過來「只發布特定筆記」，可在 quartz.config.yaml 啟用 explicit-publish 外掛，之後只有 publish: true 的筆記才會發布。
  • 放在 ignorePatterns 中的路徑完全不會被處理。

[!WARNING] 上述機制只會讓頁面不出現在網站上。圖片、PDF 等非 Markdown 檔案一律會被發布；若 GitHub 儲存庫是公開的，私人內容也要一併加入 .gitignore。

第三步：安裝與推薦 Obsidian 外掛（Community Plugins）​

外掛安裝步驟指引​

  1. 開啟 Obsidian，點擊左下角的齒輪圖示開啟 設定（Settings）（快捷鍵 Cmd + ,）。
  2. 在左側選單點選 社群外掛（Community plugins）。
  3. 點擊 關閉限制模式（Turn off Restricted mode） 以解鎖第三方外掛安裝權限。
  4. 點擊 瀏覽（Browse），在搜尋欄輸入目標外掛名稱。
  5. 點選搜尋結果後，依序按下 安裝（Install） 與 啟用（Enable）。

推薦外掛清單​

  1. Obsidian Git
    • 用途：免開啟終端機，直接在 Obsidian 介面內按快捷鍵或設定自動 Commit/Push 至 GitHub，觸發雲端自動部署。
  2. Furigana
    • 用途：以 {漢字|かんじ} 的簡寫語法輸入振假名。
    • 注意：這是 Obsidian 端的渲染，Quartz 網站不認得這個語法，會原樣顯示。要發布的筆記請改用 HTML <ruby> 標籤（見 日文筆記專用技巧）。
  3. Excalidraw
    • 用途：在筆記中插入手繪畫布，適合用 Apple Pencil 或滑鼠繪製句型結構圖與心智圖。
    • Quartz 端：需另外安裝 Quartz 社群外掛 npx quartz plugin add github:quartz-community/obsidian-plugin-excalidraw。
  4. Dataview
    • 用途：利用類 SQL 語法將散落的單字或文法筆記自動彙整成清單。
    • Quartz 端：Quartz 無法直接執行 Dataview 查詢，需搭配 Obsidian 外掛 Quartz Syncer，在同步時把查詢結果轉為靜態內容。
    • 替代方案：Obsidian 內建的 Bases（.base 檔）在 Quartz 5 中已原生支援，可直接渲染為表格頁面，簡單的彙整需求可優先考慮。
  5. Linter
    • 用途：儲存筆記時自動格式化 Markdown（如修正標頭、標籤格式），確保推送到 GitHub 的內容格式一致。

第四步：本地預覽與測試​

在終端機中執行本地開發伺服器：

npx quartz build --serve

開啟瀏覽器造訪 http://localhost:8080，即可預覽你的 Quartz 筆記網站。修改筆記或設定後，頁面會自動重新載入（Quartz 5 只會重新處理有變動的檔案）。

8080 port 被占用時，Quartz 會提示錯誤；可改用 npx quartz build --serve --port 8081。

第五步：推送至 GitHub​

為了維護個人筆記的隱私與安全性，建議將 GitHub 儲存庫設定為 Private（私有）。

使用方法 A（GitHub 範本）建立的專案​

origin 已經指向你的儲存庫，直接推送即可：

npx quartz sync --no-pull

使用方法 B（直接 Clone）建立的專案​

  1. 前往 GitHub 點選 New repository，填入名稱（例如 japanese-notes），選擇 Private 或 Public。
  2. 請勿勾選 README、License 或 .gitignore，Quartz 已內建這些檔案，重複建立會在第一次推送時造成衝突。
  3. 回到終端機：
# 確認目前的 remote
git remote -v

# 將 origin 指向你自己的 GitHub 儲存庫
git remote set-url origin https://github.com/YOUR_USERNAME/japanese-notes.git

# 第一次推送（尚無遠端內容可拉取）
npx quartz sync --no-pull

不需要自己新增 upstream remote，npx quartz create 已經設定好，之後 npx quartz upgrade 會從那裡拉取 Quartz 更新。

[!IMPORTANT] 分支名稱 Quartz 5 的工作分支是 v5，以下部署設定也以 v5 為準。請不要再像 Quartz 4 教學那樣執行 git branch -M main；若你堅持改用 main，記得把 Cloudflare 的 Production branch 或 GitHub Actions 的觸發分支一起改掉。

第六步：部署網站（Cloudflare Pages 推薦）​

若你的 GitHub 儲存庫設為 Private，使用 Cloudflare Pages 部署是完全免費且最方便的選擇。

部署前請確認 quartz.config.yaml 中的 baseUrl 已設定正確，RSS 與 Sitemap 都依賴這個值。

使用 Cloudflare Pages 部署步驟​

  1. 登入 Cloudflare Dashboard。
  2. 進入 Compute (Workers) > Workers & Pages > Create application > Pages > Connect to Git。
  3. 授權存取你的 GitHub，並選擇剛剛建立的 japanese-notes 儲存庫。
  4. 於 Set up builds and deployments 設定如下：
設定項目值
Production branchv5
Framework presetNone
Build commandgit fetch --unshallow && npx quartz plugin install && npx quartz build
Build output directorypublic
Environment variablesNODE_VERSION = 22（確保建置環境符合 Node 22 以上的需求）
  1. 點擊 Save and Deploy，約一分鐘後即可取得 *.pages.dev 網址。
  • Build command 必須先執行 npx quartz plugin install，否則建置時找不到外掛。
  • Cloudflare 預設只做淺層 Clone（shallow clone），而 Quartz 會用 Git 紀錄判斷筆記的建立／修改日期，所以要加上 git fetch --unshallow &&。

此後，只要你推送新的 Markdown 筆記到 GitHub，Cloudflare Pages 都會自動觸發建置並更新網站。

替代方案：GitHub Pages​

若儲存庫是 Public，也可以用 GitHub Pages。在專案根目錄建立 .github/workflows/deploy.yml：

name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v5

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0 # 取得完整 Git 歷史，供日期判斷使用
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - name: Cache dependencies
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      - name: Cache Quartz plugins
        uses: actions/cache@v5
        with:
          path: .quartz/plugins
          key: ${{ runner.os }}-plugins-${{ hashFiles('quartz.lock.json') }}
          restore-keys: |
            ${{ runner.os }}-plugins-
      - name: Install Dependencies
        run: npm ci
      - name: Install Quartz plugins
        run: npx quartz plugin install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

接著到儲存庫的 Settings > Pages，將 Source 設為 GitHub Actions，再執行 npx quartz sync 即可。網址為 <github-username>.github.io/<repository-name>，此時 baseUrl 要包含子路徑，例如 yourname.github.io/japanese-notes。

日文筆記專用技巧（Furigana 與別名）​

1. 振假名（Furigana）標註​

Quartz 支援原生 HTML <ruby> 標籤，在 Obsidian 與發布後的網站都能正確渲染日文漢字讀音：

<ruby>漢<rt>かん</rt>字<rt>じ</rt></ruby>

更多日文排版語法（重音標記、逐字對照表格等）請參考 Obsidian 日文筆記排版與語法指南。

2. YAML 別名（Aliases）設定​

在 Markdown 頂部標頭加入 aliases 後，[[かんじ]]、[[kanji]] 這類連結都會指向同一篇筆記，Quartz 也會為每個別名產生轉址頁（如 /kanji → /漢字）：

---
title: 漢字（かんじ）
aliases:
  - かんじ
  - kanji
tags:
  - kanji
---

# 漢字（かんじ）
這裡記錄關於日文漢字的學習筆記...

[!TIP] 讓讀音也能被搜尋到 Quartz 內建搜尋只索引標題、內文與標籤，不會索引 aliases。想用平假名或羅馬拼音搜到筆記，請把讀音寫進 title、內文或 tags（如上例）。搜尋本身已支援中日韓文斷詞。

3. 中日文檔名與網址​

Quartz 5 會把網址統一轉為小寫、空白換成連字號。中日文檔名會保留在網址中（瀏覽器會自動編碼），例如 文法/N3 動詞變形.md → /文法/n3-動詞變形。若想要較短、好分享的網址，可在 frontmatter 指定 permalink：

---
title: N3 動詞變形
permalink: grammar/n3-verb-forms
---

日常寫作與發布工作流​

配置完成後，未來的日常寫作流程非常簡單：

  1. 開啟 Obsidian，在 Vault 中直接新增或修改 .md 筆記。

  2. 完成寫作後，可透過 Obsidian Git 外掛 一鍵發布，或開啟終端機執行 Quartz 內建同步指令：

    npx quartz sync
    • Quartz 會先拉取遠端更新，再自動 Commit 並推送到 GitHub，雲端託管平台會自動完成部署。
    • 自訂 Commit 訊息：npx quartz sync --message "新增 N3 文法筆記"。
    • 在另一台電腦只想取得最新內容：npx quartz sync --no-commit --no-push。

維護指令速查​

指令說明
npx quartz build --serve本地預覽（自動重新載入）
npx quartz sync拉取、提交並推送到 GitHub
npx quartz upgrade更新 Quartz 本體（會自動備份內容並重新安裝外掛）
npx quartz plugin install --latest將所有外掛更新至最新版
npx quartz plugin add github:<org>/<repo>新增外掛
npx quartz plugin list列出已安裝外掛
npx quartz plugin enable / disable <name>啟用／停用外掛
npx quartz plugin prune移除設定檔中已不再使用的外掛
npx quartz restore升級或同步出錯時，從快取還原內容

從 Quartz 4 升級​

Quartz 5 無法用 npx quartz upgrade 從 v4 直接升上來，需要切換到新的 v5 分支。

1. 先備份筆記​

切換分支後工作目錄會換成 v5 的程式碼，content/ 會暫時看不到，請先複製到專案外：

cp -r content /tmp/quartz-content

原本的 v4 分支不會被刪除，隨時可以 git checkout v4 回去查看舊設定。

2. 取得 v5 分支​

# 加入官方儲存庫為 upstream（已設定過可略過）
git remote add upstream https://github.com/jackyzha0/quartz.git

# 取得官方 v5 分支並建立本地分支
git fetch upstream v5
git checkout -b v5 upstream/v5

# 安裝依賴並推送到自己的儲存庫
npm i
git push -u origin v5

若你之前照舊版教學把分支改名為 main，upstream 拉取時可能需要自行處理；最乾淨的做法是照上面的步驟另外建立 v5 分支。

3. 重新初始化並匯入筆記​

npx quartz create                       # 範本選 obsidian，內容匯入方式選 copy，來源指向 /tmp/quartz-content
npx quartz plugin install --from-config
npx quartz build --serve                # 確認本地預覽正常

4. 搬移舊設定​

quartz.config.ts 與 quartz.layout.ts 已不再使用，請將原本的設定手動搬到 quartz.config.yaml：

Quartz 4（quartz.config.ts）Quartz 5（quartz.config.yaml）
configuration.pageTitle、locale、baseUrl、ignorePatternsconfiguration 下同名欄位
theme.typographyconfiguration.theme.typography
theme.colors.lightMode / darkModeconfiguration.theme.colors.lightMode / darkMode
plugins.transformers / filters / emitters 裡的 Plugin.X()plugins 清單中的 source: "@quartz-community/..." 項目，用 enabled、options 設定
quartz.layout.ts 中元件的位置各外掛的 layout.position（left、right、beforeBody、afterBody、header、footer）與 priority

5. 更新部署設定​

  • Cloudflare Pages：Settings > Builds & deployments 中，將 Production branch 改為 v5，Build command 改為 git fetch --unshallow && npx quartz plugin install && npx quartz build，NODE_VERSION 改為 22。
  • GitHub Actions：觸發分支改為 v5，並加入 npx quartz plugin install 步驟（參考上方 workflow）。
  • 確認部署成功後，到 GitHub Settings > General > Default branch 將預設分支改為 v5。

6. 注意網址變更​

Quartz 5 的網址一律轉小寫並以連字號取代空白，舊網址（如 /文法/N3 動詞變形）會改變。預設啟用的 alias-redirects 外掛會自動為含大寫字母的舊路徑產生轉址頁，並附上 canonical 標記，搜尋引擎排名可以轉移到新網址，一般不需要額外處理。

常見問題排解（FAQ）​

Q1：為什麼點擊內部連結會出現 404？​

  • 確認 Markdown 中的連結格式為 [[筆記名稱]] 或相對路徑 [連結文字](./filename.md)，且目標檔案確實存在於 content/ 目錄內。
  • 確認 obsidian-flavored-markdown 外掛有啟用。
  • 若是從 Quartz 4 升級的網站，舊網址可能因大小寫轉換而改變，請參考 注意網址變更。

Q2：筆記沒有出現在網站上？​

  • frontmatter 中是否有 draft: true？
  • 是否啟用了 explicit-publish 外掛卻沒有設定 publish: true？
  • 檔案路徑是否被 ignorePatterns 排除？

Q3：建置時出現 Could not resolve ... 或外掛相關錯誤？​

  • 確認有執行 npx quartz plugin install（雲端建置的 Build command 也要包含）。
  • 外掛建置失敗時執行 npx quartz plugin install --latest。
  • 電腦記憶體較小導致安裝卡住，可加上 -c 1 限制並行數：npx quartz plugin install --latest -c 1。

Q4：想要修改網站主題顏色或字型？​

編輯專案根目錄下的 quartz.config.yaml，在 configuration.theme.typography 修改字型、在 configuration.theme.colors.lightMode / darkMode 修改淺色與深色模式的顏色。想直接套用 Obsidian 主題，可啟用設定檔中的 @quartz-themes/core 外掛。

Q5：推送時出現 fatal: The remote end hung up unexpectedly？​

通常是筆記（尤其圖片）太多，超過 Git 預設的緩衝區大小：

git config http.postBuffer 524288000
