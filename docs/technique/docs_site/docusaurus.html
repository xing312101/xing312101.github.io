本地搜尋（中英日，免服務）​

方案 A：Pagefind​

利用 Rust 編寫的現代化靜態搜尋引擎，直接呼叫瀏覽器原生 Intl.Segmenter API 進行 CJK 分詞，不論是中文、英文，還是日文漢字、平假名、片假名外來語，搜尋精準度都極高。

1. 安裝整合套件​

npm install @getcanary/docusaurus-theme-search-pagefind

2. 修改 docusaurus.config.js​

將原有的搜尋外掛替換為 Pagefind 主題（與 presets、themeConfig 同層）：

themes: ['@getcanary/docusaurus-theme-search-pagefind'],

3. 修改 package.json (關鍵步驟)​

由於 Pagefind 是在靜態網頁產生後進行索引編譯，我們需要修改 build 指令，讓它在 Docusaurus 打包完後自動執行 pagefind 掃描：

"scripts": {
  "build": "docusaurus build && npx pagefind --site build",
  "serve": "docusaurus serve"
}

💡 GitHub Pages 部署注意： 不論你是用 npm run deploy 還是 GitHub Actions，只要確保編譯時會執行到 npm run build，Pagefind 就會自動將搜尋索引打包進靜態資料夾，GitHub Pages 部署上去後直接就能完美使用離線搜尋！

方案 B：@easyops-cn/docusaurus-search-local​

基於 Lunr.js 的本地搜尋。適合中英、或「只有日文漢字」的網站。缺點是遇到日文平假名與片假名（外來語）時，分詞極差，經常搜不到結果。

npm install @easyops-cn/docusaurus-search-local

docusaurus.config.js 加 themes（與 presets、themeConfig 同層）：

themes: [
  [
    require.resolve('@easyops-cn/docusaurus-search-local'),
    {
      hashed: true,
      language: ['en', 'zh', 'ja'],    // 中 / 英 / 日 斷詞（CJK tokenizer）
      indexDocs: true,
      indexBlog: false,                // 要連 blog（首頁文章）一起搜：改 true 並加 blogRouteBasePath: '/'
      highlightSearchTermsOnTargetPage: true,
    },
  ],
],
  • ⚠️ 索引只在 production build 產生 → 測搜尋要 npm run build && npm run serve；npm run start（dev）搜尋框會有、但搜不到結果。
  • 裝好 build 後，navbar 右上自動出現搜尋框。

常見坑：broken links 會擋 build​

onBrokenLinks: 'throw'（Docusaurus 預設）下，只要有死連結，build / deploy 就整個失敗。

  • 指向資料夾的連結（例如連到 ./concepts/ 這類資料夾路徑）需該資料夾內有 index 頁（README.md） 才算有效，否則被判 broken link。
  • 純 .md 檔連結則檢查該檔是否存在。
  • 想暫時放行可在 config 設 onBrokenLinks: 'warn'（不建議長期）。
