Sign in with Apple

三家裡面最麻煩的一家。它的每一個環節都跟另外兩家不一樣：要付費、client_id 有兩種、 client_secret 要自己簽而且會過期、callback 是 POST、使用者姓名只給一次、 email 可能是轉寄用的信箱、刪帳號還得呼叫 API。

建議三家裡面最後接這一家，先用 Google 把整套流程跑順。

先讀：Google 篇。這一篇的程式碼只寫跟 Google 不一樣的地方， 共用的函式（SignIn、session、錯誤處理）對照表在 Google 篇第 3 節開頭。

note

Apple 在 2024 年起把「Apple ID」改稱「Apple 帳號（Apple Account）」。 舊文章、舊截圖裡的「Apple ID」指的是同一個東西。

1. 先確認你需不需要​

App Store 審核規則 4.8 Login Services 的現行條文（2024 年改過）是： App 用第三方或社群登入（Google、Facebook、LINE…）來建立或登入使用者的主要帳號時， 必須另外提供一個等價的登入選項，而且那個登入服務要同時做到：

  1. 只收集使用者的姓名與 email；
  2. 讓使用者在建立帳號時可以不公開自己的 email；
  3. 未經同意，不為了廣告目的收集使用者在你 App 裡的互動。

條文沒有指定一定要是 Sign in with Apple —— 改版前是，現在是「符合這三項的登入服務」。 Sign in with Apple 符合這三項，所以仍然是最省事、最常見的選擇。

情況需要 Sign in with Apple 嗎
純網站，沒有 iOS App不用（審核規則管的是 App）
iOS App 提供了 Google、LINE 等第三方登入要多提供一個符合上面三項的登入選項；最常見的做法就是 Sign in with Apple
iOS App 只有自己的帳密登入不用
企業／教育 App 要求用既有的組織帳號登入、用政府或產業的電子身分登入、App 本身就是某個第三方服務的用戶端不用（4.8 列出的例外）

成本：Apple Developer Program 每年 US$99，個人與公司都一樣。 公司帳號還需要 D-U-N-S 編號，申請本身可能就要好幾天，提早辦。

2. 申請步驟​

全部在 Apple Developer 的 Certificates, Identifiers & Profiles 裡面做。順序不能顛倒：先 App ID，再 Services ID，最後金鑰。

2.1 建立 App ID（即使你只有網站也要建）​

Identifiers → ＋ → App IDs → App

  • Bundle ID：反向網域格式，例如 com.example.myapp。
  • Capabilities 勾選 Sign in with Apple，選 Enable as a primary App ID。

這個 App ID 會成為 primary App ID —— 網站用的 Services ID、Sign in with Apple 的金鑰、 伺服器通知的端點，全部都掛在它底下。

只有網站的話先確認走得通。 Apple 的設定文件 寫的是「要讓使用者從你的網站登入，必須已經有一個在 App Store、使用 Sign in with Apple 的 App」。 只有網站、沒有上架 App 的話，請在排時程之前先實際走一次登入流程確認可行，不要等到上線前才發現。

2.2 建立 Services ID（網站的 client_id）​

Identifiers → ＋ → Services IDs

  • Identifier：也是反向網域格式，但不能跟 App ID 相同， 習慣寫成 com.example.myapp.web。
  • 建好之後在清單裡點它 → 勾 Sign in with Apple → Configure：
欄位填什麼
Primary App ID選 2.1 建的那個
Website URLs：Domains and Subdomainsapp.example.com（不含 https://、不含路徑）
Website URLs：Return URLshttps://app.example.com/auth/apple/callback（完整網址，含 scheme、主機、路徑）

填完按 Done → Continue → Save。組織帳號最多可登記 100 個網址，個人帳號 10 個。

Return URL 的限制比另外兩家嚴格得多：

  • 主機必須是網域名稱 —— 不能是 IP、不能是 localhost（Apple 文件明寫）
  • 不能帶 #fragment
  • 要用 https
  • 程式送出的 redirect_uri 必須跟這裡登記的逐字相同

所以你沒辦法用 localhost 直接測 Apple 登入。做法是用隧道服務拿一個固定的 https 網址、 準備一個 dev.example.com 子網域指到開發機，或在本機的 /etc/hosts 把登記過的測試網域指向自己 （本機要有那個網域的 https 憑證）。這件事會拖慢開發，提早準備。 （自動化測試不受影響，見測試與 CI/CD。）

2.3 網域驗證​

現在不用做了。 舊的教學會要你下載 apple-developer-domain-association.txt、 放到 /.well-known/ 底下再按 Verify —— Apple 已經拿掉這個步驟， 現行的設定說明 明寫「不需要在伺服器上放檔案」。登記網域與 Return URL 之後按 Save 就生效。

如果你照著舊教學卡在「找不到 Download／Verify 按鈕」，原因就是這個。

2.4 建立私密金鑰（.p8）​

Keys → ＋

  • 取個名字，勾 Sign in with Apple，Configure 選 2.1 的 primary App ID。
  • 建立後下載 AuthKey_XXXXXXXXXX.p8。

這個檔案只能下載一次。 關掉頁面就再也拿不到，只能作廢重建。 下載後立刻放進你的密鑰管理工具（環境變數、Secret Manager），絕對不要進版控。

每個 primary App ID 最多只能有兩把 Sign in with Apple 金鑰。 要換金鑰（例如懷疑外洩）時， 先建新的、把程式切過去，再 Revoke 舊的 —— 兩把的額度就是留給這種交接用的， 不要拿來給不同環境各用一把。

你需要記下四個值，缺一不可：

名稱哪裡看長什麼樣
Team ID開發者帳號的 Membership details 頁ABCDE12345（10 碼）
Key IDKeys 清單裡那把金鑰XYZ9876543（10 碼）
Services ID2.2 建的那個com.example.myapp.web
私密金鑰.p8 檔案內容-----BEGIN PRIVATE KEY-----…

2.5 若要寄信給使用者：設定私密電子郵件轉寄​

Certificates, Identifiers & Profiles → Services → Sign in with Apple for Email Communication → Configure

在 Email Sources 按 ＋，把你的寄件網域（例如 example.com）或寄件地址（例如 noreply@example.com）登記進去。

  • 沒登記的來源寄到 @privaterelay.appleid.com 的信會被退回， 使用者永遠收不到你的驗證信、通知信。
  • 登記的網域要通過 SPF 或 DKIM 驗證（兩個都做最好）：SPF 看的是信封寄件者（envelope sender）的網域， DKIM 看的是簽章裡 d= 的網域要跟 From: 一致。登記後表格會顯示 SPF 檢查有沒有過。
  • 用寄信服務商（交易信件、行銷信件平台）寄的話，要登記的是信件實際帶的那個網域或地址， 不一定是你的主網域 —— 退信時先看信頭。
  • 上限：組織帳號 100 個來源，個人帳號 32 個。

4. form_post 會弄丟你的 cookie​

這是 Apple 登入最常見、也最難查的問題。

因為帶了 name email scope 時 response_mode 必須是 form_post， Apple 會用 HTML 表單自動 POST 把結果送回你的 Return URL （application/x-www-form-urlencoded）。這是一個跨站的 POST 請求，於是：

warning

SameSite=Lax（也是瀏覽器的預設值）的 cookie 不會被送出。

結果就是：你在第一步存進 session 的 state、nonce， 在 callback 裡全部讀不到，程式會判定「state 不符」而拒絕登入 —— 但你的程式邏輯完全正確。

同一個原因，callback 裡也讀不到「目前是誰登入」。使用者已經登入、想在設定頁 「綁定 Apple」時，callback 會以為他沒登入，於是走成一次全新的登入 （結果是撞到 email、或多建一個帳號）。

解法是為 OAuth 流程用一個獨立的短命 cookie，設 SameSite=None; Secure; Max-Age=600， 裡面放 state、nonce，以及發起時登入中的使用者 id（綁定流程要用），登入完成就刪掉； 真正的登入 session 維持 SameSite=Lax。這個 cookie 要簽章或加密，不能讓使用者改內容。

不要因此把整站的 session cookie 都改成 SameSite=None —— 那等於放寬整站的 CSRF 防護。

另外，callback 端點要吃 POST + application/x-www-form-urlencoded，不是 GET； 而且框架內建的 CSRF 檢查要對這一支關掉（Apple 的表單不會帶你的 CSRF token），改靠 state 防護。

5. 使用者的姓名只會給你一次​

Apple 不把姓名放在 ID token 裡，而是在第一次授權時，用 form_post 的 body 額外送一個 user 欄位（JSON 字串）：

{ "name": { "firstName": "小明", "lastName": "王" }, "email": "abc@example.com" }
warning

這個 user 欄位只有「使用者第一次同意你的 App」那一次會出現。 之後每一次登入都不會再有，而且沒有任何 API 可以補查。 （email 不受影響 —— 只要當初同意了 email，之後每次的 ID token 裡都有。）

如果你在第一次登入時沒有把名字存下來（例如那次剛好程式出錯、或你當時還沒寫這段）， 那位使用者的姓名你就永遠拿不到了，只能請他自己在你的網站上重填。

測試時要重來的方法：使用者要先對你的 App 停止使用 Sign in with Apple， 下次登入才會重新當成第一次。iPhone 上是「設定 → 點最上面自己的名字 → 使用 Apple 登入（Sign in with Apple）→ 選你的 App → 刪除」； 網頁上是 account.apple.com 的「登入與安全性 → 使用 Apple 登入」。 （iOS 版本不同，選單位置與按鈕名稱會略有差異。）

處理方式：callback 一拿到就先解析存住，不要等到驗完 token 才處理。 但 user 欄位沒有簽章，它只是表單裡的一個字串：拿它當顯示名稱的初始值沒問題， email 一律以驗過的 ID token 為準，不要用 user 裡的 email。

6. client_secret 是自己簽的而且會過期​

Apple 不給你一個固定的 secret 字串，而是要你用 .p8 私鑰簽一段 ES256 的 JWT 當作 client_secret。

internal/authapple/secret.go
package authapple

import (
	"crypto/ecdsa"
	"crypto/x509"
	"encoding/pem"
	"errors"
	"os"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

var (
	teamID   = os.Getenv("APPLE_TEAM_ID")
	keyID    = os.Getenv("APPLE_KEY_ID")
	clientID = os.Getenv("APPLE_SERVICES_ID")
	// .p8 檔案的完整內容，含 BEGIN/END 那兩行
	privateKeyPEM = os.Getenv("APPLE_PRIVATE_KEY")
)

// ClientSecret 每次呼叫都簽一個新的、五分鐘後過期的 JWT。
// 這樣就不會有「六個月後突然全站登不進去」的問題。
func ClientSecret() (string, error) {
	block, _ := pem.Decode([]byte(privateKeyPEM))
	if block == nil {
		return "", errors.New("無法解析 .p8 內容")
	}
	parsed, err := x509.ParsePKCS8PrivateKey(block.Bytes)
	if err != nil {
		return "", err
	}
	key, ok := parsed.(*ecdsa.PrivateKey)
	if !ok {
		return "", errors.New(".p8 不是 ECDSA 私鑰")
	}

	now := time.Now()
	// 用 MapClaims 而不是 RegisteredClaims：後者的 Audience 預設會被序列化成
	// 陣列 ["https://appleid.apple.com"]，Apple 文件的範例是單一字串
	token := jwt.NewWithClaims(jwt.SigningMethodES256, jwt.MapClaims{
		"iss": teamID,
		"iat": now.Unix(),
		"exp": now.Add(5 * time.Minute).Unix(),
		"aud": "https://appleid.apple.com",
		"sub": clientID,
	})
	token.Header["kid"] = keyID
	return token.SignedString(key)
}

require "openssl"
require "jwt"

module AppleClientSecret
  TEAM_ID   = ENV.fetch("APPLE_TEAM_ID")
  KEY_ID    = ENV.fetch("APPLE_KEY_ID")
  CLIENT_ID = ENV.fetch("APPLE_SERVICES_ID")
  # .p8 檔案的完整內容，含 BEGIN/END 那兩行
  PRIVATE_KEY = ENV.fetch("APPLE_PRIVATE_KEY")

  # 每次呼叫都簽一個新的、五分鐘後過期的 JWT。
  # 這樣就不會有「六個月後突然全站登不進去」的問題。
  def self.generate
    key = OpenSSL::PKey::EC.new(PRIVATE_KEY)
    now = Time.now.to_i
    JWT.encode(
      {
        iss: TEAM_ID,
        iat: now,
        exp: now + 300,
        aud: "https://appleid.apple.com",
        sub: CLIENT_ID,
      },
      key,
      "ES256",
      { kid: KEY_ID },
    )
  end
end
app/apple_client_secret.py
import os
import time

import jwt  # 需要 pyjwt[crypto]

TEAM_ID = os.environ["APPLE_TEAM_ID"]
KEY_ID = os.environ["APPLE_KEY_ID"]
CLIENT_ID = os.environ["APPLE_SERVICES_ID"]
# .p8 檔案的完整內容，含 BEGIN/END 那兩行
PRIVATE_KEY = os.environ["APPLE_PRIVATE_KEY"]


def make_client_secret() -> str:
    """每次呼叫都簽一個新的、五分鐘後過期的 JWT。
    這樣就不會有「六個月後突然全站登不進去」的問題。"""
    now = int(time.time())
    return jwt.encode(
        {
            "iss": TEAM_ID,
            "iat": now,
            "exp": now + 300,
            "aud": "https://appleid.apple.com",
            "sub": CLIENT_ID,
        },
        PRIVATE_KEY,
        algorithm="ES256",
        headers={"kid": KEY_ID},
    )
tip

簽章的位元組格式要對。 JWT 的 ES256 簽章是 64 bytes 的 R || S 原始格式； OpenSSL 的低階 API（例如直接呼叫 dsa_sign、openssl dgst -sign）產生的是 ASN.1 DER 格式， 拿去當 JWT 簽章 Apple 會回 invalid_client。上面三個函式庫都會自己轉成正確格式， 自己手刻簽章時才要注意。

warning

這是 Apple 登入最常見的「某天突然全站登不進去」原因。

你在上線那天簽了一個六個月後過期的 secret，一切正常；六個月後某個半夜， 所有 Apple 登入開始回 invalid_client，而程式碼一行都沒改過。

三種做法，由好到差：

  1. 每次要用的時候即時簽一個（有效期設短，例如 5 分鐘）。最簡單也最不會忘， 簽一次的成本可以忽略 —— 上面三個範例都是這樣做的。
  2. 排程每個月重簽一次存起來。
  3. 手動簽一個貼進環境變數 —— 請在行事曆上設提醒。

.p8 私鑰本身不會過期，會過期的只有你簽出來的那段 JWT。

7. 完整的 callback​

跟 Google 的差別有四處：交易用的 cookie 要 SameSite=None、端點是 POST、 要接住 user 欄位、要把 refresh token 存起來（第 9 節刪帳號要用）。

Return URL 跟 Google 一樣從環境變數讀（APPLE_REDIRECT_URI），正式站與測試站各登記各的； 第 6 節的 APPLE_TEAM_ID、APPLE_KEY_ID、APPLE_SERVICES_ID、APPLE_PRIVATE_KEY 也在這裡用到。 用到的共用函式跟 Google 篇相同（對照表在 Google 篇第 3 節開頭）。 Apple 的授權請求參數文件沒有列出 PKCE 的 code_challenge，discovery 也沒有 code_challenge_methods_supported （見基礎篇第 8 節），所以這一篇的範例不帶 PKCE， 授權碼注入靠確實比對 nonce 來擋（見基礎篇第 5 節）。

var (
	redirectURI = os.Getenv("APPLE_REDIRECT_URI")
	// 同時有 iOS App、而且原生端的 ID token 也送到這個後端驗的話才需要，見第 10 節
	bundleID = os.Getenv("APPLE_BUNDLE_ID")

	authURL, tokenURL string // Init 從 discovery 讀
	verifier          *oidc.IDTokenVerifier
	httpClient        = &http.Client{Timeout: 10 * time.Second}

	// ★ 交易用的 cookie 必須是 SameSite=None，否則 Apple 的跨站 POST 帶不回來（第 4 節）
	txStore = func() *sessions.CookieStore {
		s := sessions.NewCookieStore([]byte(os.Getenv("SESSION_SECRET")))
		s.Options = &sessions.Options{
			Path: "/auth/apple", MaxAge: 600, HttpOnly: true, Secure: true,
			SameSite: http.SameSiteNoneMode,
		}
		return s
	}()
)

// Init 在程式啟動時呼叫一次，issuer 傳 "https://appleid.apple.com"。
// 做成參數的理由跟 Google 篇相同：測試時能指向假的 IdP
func Init(ctx context.Context, issuer string) error {
	provider, err := oidc.NewProvider(ctx, issuer)
	if err != nil {
		return err
	}
	endpoint := provider.Endpoint()
	authURL, tokenURL = endpoint.AuthURL, endpoint.TokenURL
	// go-oidc 的 ClientID 只能填一個值，而 aud 要同時接受 Services ID 與 Bundle ID，
	// 所以關掉它的 aud 檢查、改在 audienceAllowed 自己比 —— 只關不比等於沒驗
	verifier = provider.Verifier(&oidc.Config{SkipClientIDCheck: true})
	return nil
}

func Start(w http.ResponseWriter, r *http.Request) {
	state, nonce := web.RandomToken(), web.RandomToken()

	tx, _ := txStore.New(r, "apple_tx")
	tx.Values["state"] = state
	tx.Values["nonce"] = nonce
	// callback 讀不到 Lax 的登入 session，綁定流程要的「目前是誰」得先存在這裡
	tx.Values["uid"] = web.CurrentUserID(r)
	if err := tx.Save(r, w); err != nil {
		http.Error(w, "無法建立登入工作階段", http.StatusInternalServerError)
		return
	}

	q := url.Values{
		"client_id":     {clientID},
		"redirect_uri":  {redirectURI},
		"response_type": {"code"},
		"scope":         {"name email"},
		"response_mode": {"form_post"}, // 帶 scope 就必須是這個
		"state":         {state},
		"nonce":         {nonce},
	}
	http.Redirect(w, r, authURL+"?"+q.Encode(), http.StatusFound)
}

// 注意：註冊成 POST
func Callback(db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		ctx := r.Context()
		if err := r.ParseForm(); err != nil {
			http.Error(w, "無法解析表單", http.StatusBadRequest)
			return
		}
		tx, _ := txStore.Get(r, "apple_tx")
		state, _ := tx.Values["state"].(string)
		nonce, _ := tx.Values["nonce"].(string)
		uid, _ := tx.Values["uid"].(int64)
		tx.Options.MaxAge = -1 // 不論成敗都作廢
		_ = tx.Save(r, w)

		// 使用者按了取消：error=user_cancelled_authorize
		if r.FormValue("error") != "" {
			http.Redirect(w, r, "/login?error=cancelled", http.StatusSeeOther)
			return
		}
		if !web.SameToken(state, r.FormValue("state")) {
			http.Error(w, "state 不符", http.StatusBadRequest)
			return
		}

		// ★ 姓名只有第一次會有，先接住
		var displayName string
		if raw := r.FormValue("user"); raw != "" {
			var u struct {
				Name struct {
					FirstName string `json:"firstName"`
					LastName  string `json:"lastName"`
				} `json:"name"`
			}
			// 格式不如預期就當作沒有，不要讓整個登入失敗
			if err := json.Unmarshal([]byte(raw), &u); err == nil {
				// 中文習慣姓在前；要支援其他語系的話把兩個欄位分開存
				displayName = strings.TrimSpace(u.Name.LastName + u.Name.FirstName)
			}
		}

		secret, err := ClientSecret()
		if err != nil {
			log.Printf("無法產生 apple client_secret：%v", err)
			http.Error(w, "登入失敗", http.StatusInternalServerError)
			return
		}
		tokens, err := exchangeCode(ctx, r.FormValue("code"), secret)
		if err != nil {
			log.Printf("apple token 兌換失敗：%v", err)
			http.Error(w, "登入失敗", http.StatusBadGateway)
			return
		}

		idToken, err := verifier.Verify(ctx, tokens.IDToken) // 簽章、iss、exp
		if err != nil || !audienceAllowed(idToken.Audience) {
			log.Printf("apple id_token 驗證失敗：%v", err)
			http.Error(w, "登入失敗", http.StatusUnauthorized)
			return
		}
		// nonce 要自己比，函式庫不會做
		if !web.SameToken(nonce, idToken.Nonce) {
			log.Printf("apple id_token 的 nonce 不符")
			http.Error(w, "登入失敗", http.StatusUnauthorized)
			return
		}

		var claims struct {
			Sub            string `json:"sub"`
			Email          string `json:"email"`
			EmailVerified  any    `json:"email_verified"`   // 可能是 bool 或 "true"
			IsPrivateEmail any    `json:"is_private_email"` // 同上
		}
		if err := idToken.Claims(&claims); err != nil {
			http.Error(w, "無法解析 claims", http.StatusBadGateway)
			return
		}

		user, err := accounts.SignIn(ctx, db, accounts.ProfileFromProvider{
			Provider:       "apple",
			ProviderUserID: claims.Sub,
			Email:          claims.Email,
			EmailVerified:  truthy(claims.EmailVerified),
			EmailIsRelay:   truthy(claims.IsPrivateEmail),
			DisplayName:    displayName, // 只有第一次會有值
		}, uid) // ★ 發起時登入中的使用者（從交易 cookie 來，不是 web.CurrentUserID）
		if err != nil {
			web.SignInErrorRedirect(w, r, err)
			return
		}

		// ★ 刪帳號時 revoke 要用（第 9 節）。加密後存起來，連同發給哪個 client_id
		if err := saveAppleRefreshToken(ctx, db, user.ID, clientID, tokens.RefreshToken); err != nil {
			log.Printf("apple refresh token 儲存失敗：%v", err)
		}

		if err := web.StartSession(w, r, user.ID); err != nil {
			log.Printf("無法建立 session：%v", err)
			http.Error(w, "登入失敗", http.StatusInternalServerError)
			return
		}
		http.Redirect(w, r, "/", http.StatusSeeOther)
	}
}

type appleTokens struct {
	AccessToken  string `json:"access_token"`
	RefreshToken string `json:"refresh_token"`
	IDToken      string `json:"id_token"`
}

func exchangeCode(ctx context.Context, code, secret string) (*appleTokens, error) {
	form := url.Values{
		"grant_type":    {"authorization_code"},
		"code":          {code},
		"redirect_uri":  {redirectURI},
		"client_id":     {clientID},
		"client_secret": {secret},
	}
	req, err := http.NewRequestWithContext(ctx, http.MethodPost, tokenURL,
		strings.NewReader(form.Encode()))
	if err != nil {
		return nil, err
	}
	req.Header.Set("Content-Type", "application/x-www-form-urlencoded")

	res, err := httpClient.Do(req)
	if err != nil {
		return nil, err
	}
	defer res.Body.Close()
	body, err := io.ReadAll(io.LimitReader(res.Body, 1<<20))
	if err != nil {
		return nil, err
	}
	if res.StatusCode != http.StatusOK {
		// Apple 的錯誤通常只有一個字，例如 {"error":"invalid_client"}，對照第 11 節
		return nil, fmt.Errorf("HTTP %d：%s", res.StatusCode, body)
	}
	var t appleTokens
	if err := json.Unmarshal(body, &t); err != nil {
		return nil, err
	}
	if t.IDToken == "" {
		return nil, errors.New("回應缺少 id_token")
	}
	return &t, nil
}

// 網頁的 Services ID 與 App 的 Bundle ID 都要收，見第 10 節
func audienceAllowed(aud []string) bool {
	for _, a := range aud {
		if a == clientID || (bundleID != "" && a == bundleID) {
			return true
		}
	}
	return false
}

// Apple 的布林 claim 有時是 bool、有時是字串 "true"
func truthy(v any) bool {
	switch t := v.(type) {
	case bool:
		return t
	case string:
		return t == "true"
	default:
		return false
	}
}

module AppleOIDC
  ISSUER    = "https://appleid.apple.com".freeze
  AUTH_URL  = "https://appleid.apple.com/auth/authorize".freeze
  TOKEN_URL = "https://appleid.apple.com/auth/token".freeze
  JWKS_URL  = "https://appleid.apple.com/auth/keys".freeze
  REDIRECT_URI = ENV.fetch("APPLE_REDIRECT_URI")   # 必須跟 Return URLs 登記的逐字相同
  # 同時有 iOS App、而且原生端的 ID token 也送到這個後端驗的話才需要，見第 10 節
  BUNDLE_ID = ENV["APPLE_BUNDLE_ID"]

  TokenExchangeError = Class.new(StandardError)

  # 跟 Google 篇相同：平常回快取，遇到沒看過的 kid 才重抓，五分鐘內最多一次（見後端驗證第 3 節）
  JWKS_LOADER = lambda do |options|
    if options[:kid_not_found] && @jwks_fetched_at.to_i < Time.now.to_i - 300
      @cached_jwks = nil
    end
    @cached_jwks ||= begin
      @jwks_fetched_at = Time.now.to_i
      JSON.parse(Net::HTTP.get(URI(JWKS_URL)), symbolize_names: true)
    end
  end

  def self.verify_id_token(id_token, expected_nonce)
    claims, = JWT.decode(
      id_token, nil, true,
      algorithms: ["RS256"], jwks: JWKS_LOADER,
      iss: ISSUER, verify_iss: true,
      # 網頁的 Services ID 與 App 的 Bundle ID 都要收，見第 10 節
      aud: [AppleClientSecret::CLIENT_ID, BUNDLE_ID].compact,
      verify_aud: true, verify_expiration: true, leeway: 60,
    )
    # nonce 要自己比，函式庫不會做
    raise JWT::DecodeError, "nonce 不符" unless expected_nonce.present? &&
      ActiveSupport::SecurityUtils.secure_compare(claims["nonce"].to_s, expected_nonce.to_s)

    claims
  end
end

class Auth::AppleController < ApplicationController
  # Apple 的 form_post 不會帶我們的 CSRF token（靠 state 防護）
  skip_before_action :verify_authenticity_token, only: :callback

  def start
    state = SecureRandom.urlsafe_base64(32)
    nonce = SecureRandom.urlsafe_base64(32)

    # ★ 必須 SameSite=None，否則 Apple 的跨站 POST 帶不回來。
    # callback 讀不到 Lax 的登入 session，綁定流程要的「目前是誰」也一起放進來
    cookies.encrypted[:apple_tx] = {
      value: { state:, nonce:, uid: current_user&.id }.to_json,
      expires: 10.minutes.from_now,
      httponly: true, secure: true, same_site: :none,
      path: "/auth/apple",
    }

    query = {
      client_id: AppleClientSecret::CLIENT_ID,
      redirect_uri: AppleOIDC::REDIRECT_URI,
      response_type: "code",
      scope: "name email",
      response_mode: "form_post",      # 帶 scope 就必須是這個
      state:, nonce:,
    }
    redirect_to "#{AppleOIDC::AUTH_URL}?#{query.to_query}", allow_other_host: true
  end

  def callback
    tx = begin
      JSON.parse(cookies.encrypted[:apple_tx].to_s)
    rescue JSON::ParserError
      {}
    end
    cookies.delete(:apple_tx, path: "/auth/apple")

    # 使用者按了取消：error=user_cancelled_authorize
    return redirect_to(login_path, alert: "已取消登入") if params[:error].present?
    unless tx["state"].present? && ActiveSupport::SecurityUtils.secure_compare(
      tx["state"], params[:state].to_s
    )
      return head :bad_request
    end

    # ★ 姓名只有第一次會有，先接住；格式不如預期就當作沒有
    display_name =
      begin
        name = JSON.parse(params[:user].to_s).fetch("name", nil) || {}
        # 中文習慣姓在前；要支援其他語系的話把兩個欄位分開存
        "#{name['lastName']}#{name['firstName']}".strip.presence
      rescue JSON::ParserError, TypeError, NoMethodError
        nil
      end

    tokens = exchange_code(params[:code].to_s)
    claims = AppleOIDC.verify_id_token(tokens["id_token"], tx["nonce"])

    user = Identity.sign_in!(
      {
        provider: "apple",
        provider_user_id: claims["sub"],
        email: claims["email"],
        email_verified: truthy(claims["email_verified"]),
        email_is_relay: truthy(claims["is_private_email"]),
        display_name: display_name,
      },
      # ★ 發起時登入中的使用者（從交易 cookie 來，不是 current_user）
      current_user: User.find_by(id: tx["uid"]),
    )

    # ★ 刪帳號時 revoke 要用（第 9 節）。加密後存起來，連同發給哪個 client_id
    save_apple_refresh_token(user, AppleClientSecret::CLIENT_ID, tokens["refresh_token"])

    start_session(user)                    # 換發 session id，防 session fixation
    redirect_to root_path
  rescue Identity::SignInError => e
    redirect_sign_in_error(e)
  rescue AppleOIDC::TokenExchangeError
    head :bad_gateway
  rescue JWT::DecodeError => e
    Rails.logger.warn("apple id_token 驗證失敗：#{e.message}")
    head :unauthorized
  end

  private

  def exchange_code(code)
    res = Net::HTTP.post_form(URI(AppleOIDC::TOKEN_URL), {
      "grant_type"    => "authorization_code",
      "code"          => code,
      "redirect_uri"  => AppleOIDC::REDIRECT_URI,
      "client_id"     => AppleClientSecret::CLIENT_ID,
      "client_secret" => AppleClientSecret.generate,
    })
    unless res.is_a?(Net::HTTPSuccess)
      # Apple 的錯誤通常只有一個字，例如 {"error":"invalid_client"}，對照第 11 節
      Rails.logger.error("apple token 兌換失敗：#{res.body}")
      raise AppleOIDC::TokenExchangeError
    end
    JSON.parse(res.body)
  end

  # Apple 的布林 claim 有時是 bool、有時是字串 "true"
  def truthy(value) = value == true || value == "true"
end

@router.post("/auth/apple/callback")   # ★ POST
async def callback(request: Request, db: Session = Depends(get_db)):
    form = await request.form()

    try:
        tx = tx_signer.loads(request.cookies.get("apple_tx", ""), max_age=600)
    except BadSignature:  # 也涵蓋過期（SignatureExpired 是它的子類別）
        raise HTTPException(400, "登入工作階段已失效，請重新登入")

    # 使用者按了取消：error=user_cancelled_authorize
    if form.get("error"):
        return RedirectResponse("/login?error=cancelled", status_code=303)
    # compare_digest 收 str 時遇到非 ASCII 會丟 TypeError（變成 500），一律比 bytes
    if not secrets.compare_digest(
        str(tx.get("state", "")).encode(), str(form.get("state", "")).encode()
    ):
        raise HTTPException(400, "state 不符")

    # ★ 姓名只有第一次會有，先接住；格式不如預期就當作沒有
    display_name = None
    if raw_user := form.get("user"):
        try:
            name = json.loads(str(raw_user)).get("name") or {}
            # 中文習慣姓在前；要支援其他語系的話把兩個欄位分開存
            display_name = f"{name.get('lastName', '')}{name.get('firstName', '')}".strip() or None
        except (json.JSONDecodeError, AttributeError):
            pass

    async with httpx.AsyncClient(timeout=10) as client:
        res = await client.post(TOKEN_URL, data={
            "grant_type": "authorization_code",
            "code": str(form.get("code", "")),
            "redirect_uri": REDIRECT_URI,
            "client_id": CLIENT_ID,
            "client_secret": make_client_secret(),
        })
    if res.status_code != 200:
        # Apple 的錯誤通常只有一個字，例如 {"error":"invalid_client"}，對照第 11 節
        log.error("apple token 兌換失敗：%s", res.text)
        raise HTTPException(502, "登入失敗")
    tokens = res.json()

    try:
        claims = verify_id_token(tokens["id_token"], tx["nonce"])
    except jwt.PyJWTError as exc:
        log.warning("apple id_token 驗證失敗：%s", exc)
        raise HTTPException(401, "登入失敗") from exc

    profile = ProfileFromProvider(
        provider="apple",
        provider_user_id=claims["sub"],
        email=claims.get("email"),
        # Apple 的布林 claim 有時是 bool、有時是字串 "true"
        email_verified=claims.get("email_verified") in (True, "true"),
        email_is_relay=claims.get("is_private_email") in (True, "true"),
        display_name=display_name,
    )
    # ★ 發起時登入中的使用者（從交易 cookie 來，不是 get_current_user）
    current = db.get(User, tx["uid"]) if tx.get("uid") else None
    try:
        user = sign_in(db, profile, current_user=current)
    except SignInError as exc:
        return sign_in_error_redirect(exc)

    # ★ 刪帳號時 revoke 要用（第 9 節）。加密後存起來，連同發給哪個 client_id
    save_apple_refresh_token(db, user.id, CLIENT_ID, tokens.get("refresh_token"))

    start_session(request, user)  # 換發 session，防 session fixation
    resp = RedirectResponse("/", status_code=303)
    resp.delete_cookie("apple_tx", path="/auth/apple")
    return resp


def verify_id_token(id_token: str, expected_nonce: str) -> dict:
    """驗簽章、iss、aud、exp、nonce。任何一項失敗都丟 jwt.PyJWTError 的子類別。"""
    key = jwk_client.get_signing_key_from_jwt(id_token)
    claims = jwt.decode(
        id_token, key.key, algorithms=["RS256"],
        # 網頁的 Services ID 與 App 的 Bundle ID 都要收，見第 10 節
        audience=[CLIENT_ID, BUNDLE_ID] if BUNDLE_ID else CLIENT_ID,
        issuer=ISSUER, leeway=60,
        options={"require": ["exp", "iat", "sub", "aud", "iss"]},
    )
    # nonce 要自己比，函式庫不會做
    if not expected_nonce or not secrets.compare_digest(
        str(claims.get("nonce", "")).encode(), expected_nonce.encode()
    ):
        raise jwt.InvalidTokenError("nonce 不符")
    return claims

8. 私密轉寄信箱（Hide My Email）​

使用者可以在同意畫面上選擇「隱藏我的電子郵件」，這時你拿到的 email 會是 a1b2c3d4e5@privaterelay.appleid.com 這種位址，ID token 裡 is_private_email 為 true。

特性說明
能不能寄信可以，Apple 會轉寄給使用者的真實信箱 —— 但你必須先做 2.5 的寄件來源登記
會不會失效使用者隨時可以停用轉寄，之後信就寄不到了；有接伺服器通知的話會收到 email-disabled
每個 App 一樣嗎同一個開發者團隊（Team）底下的 App 與網站是同一個；不同團隊不同。App 轉移到別的團隊時會換一個
能拿來比對帳號嗎不能。它跟使用者在別處用的 email 不同，拿它去撞號永遠撞不到

這就是帳號串接裡 email_is_relay 這個欄位存在的原因。

is_private_email 與 email_verified 在 ID token 裡有時是布林值 true、 有時是字串 "true"（Apple 文件本身的範例就是字串）。判斷式要兩種都接受 —— 第 7 節範例裡的 truthy() 就是在處理這件事；只寫 == true 的話，字串那種會被靜默當成 false。

9. 帳號刪除時要呼叫 revoke​

App Store 審核規則 5.1.1(v) 要求：App 如果能建立帳號，就必須能在 App 內刪除帳號（2022 年 6 月 30 日起）。 Apple 對 Sign in with Apple 的補充說明是： 刪除帳號時要用 REST API 撤銷這個使用者的 token，解除 Apple 帳號與你的 App 的關聯。

curl -X POST https://appleid.apple.com/auth/revoke \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=com.example.myapp.web" \
  -d "client_secret=<你簽的 JWT>" \
  -d "token=<存起來的 refresh_token>" \
  -d "token_type_hint=refresh_token"
  • token 可以是 refresh token（token_type_hint=refresh_token）或 access token（token_type_hint=access_token）。 access token 只有一小時效期，實務上要存的是 refresh token。
  • client_id 要跟當初發這個 token 的 client 一致：網頁登入拿到的用 Services ID， 原生 App 拿到的用 Bundle ID，client_secret 的 sub 也跟著換。所以存 token 時要一起記下它來自哪個 client_id。
  • 成功時回 200 且空 body（token 本來就已失效也是 200）—— 照狀態碼判斷，不要解析內容。
warning

這代表你應該在使用者第一次登入時就把 refresh_token 存起來（加密）， 否則到了要刪帳號的時候手上沒有 token 可以撤銷。

真的沒存到的話，Apple 的 TN3194 給的退路是：可以在刪除當下請使用者再用 Apple 登入一次，拿新的 code 換出 token 再撤銷； 如果連這個也做不到，仍然要完成刪除，然後引導使用者自己到 Apple 帳號設定裡對你的 App 停止使用 Sign in with Apple。 沒有撤銷的話，這個人下次來登入時 Apple 仍視為「已授權」，不會再給你姓名（第 5 節）。

另外 Apple 建議拿 refresh token 去驗證使用者狀態時一天最多一次，太頻繁會被限流。

9.1 伺服器對伺服器通知​

Apple 可以在使用者做了以下事情時，POST 一個通知到你的伺服器：

事件 type什麼時候
email-disabled / email-enabled使用者停用／重新啟用轉寄信箱的轉寄
consent-revoked使用者對你的 App 停止使用 Sign in with Apple
account-deleted使用者要求 Apple 永久刪除他的 Apple 帳號

設定位置在 primary App ID 上，不是 Services ID： Identifiers → 選 2.1 的 App ID → Sign in with Apple → Configure → Server-to-Server Notification Endpoint， 填一個完整的 https://… 網址（伺服器要支援 TLS 1.2 以上），每個 App 群組只能填一個。

通知的 body 是 {"payload": "<JWT>"}，那段 JWT 由 Apple 簽章 —— 跟 ID token 一樣用 Apple 的 JWKS 驗簽， 驗過 iss 與 aud 之後才讀 events 裡的 type 和 sub，不然任何人都能打這支 API 把你的使用者登出或停掉寄信。

有在寄信給使用者、或要做到「使用者在 Apple 那邊解除連結就同步登出」的服務值得接。 開發者所在地是南韓的話，從 2026 年 1 月 1 日起新增或修改 Services ID 時必須填這個端點。

10. 網頁與原生 App 的 aud 不一樣​

這是同時有網站和 iOS App 時一定會踩到的：

來源client_id／ID token 的 aud
網頁（appleid.apple.com/auth/authorize）Services ID（com.example.myapp.web）
iOS 原生（ASAuthorizationAppleIDProvider）Bundle ID（com.example.myapp）

如果後端用同一套驗證收兩邊的 ID token，驗證時 aud 要接受兩個值 （上面三個範例都已經這樣寫了，設了 APPLE_BUNDLE_ID 就會生效）。

原生 App 把 authorizationCode 送到後端換 token 時，client_id 要用 Bundle ID， client_secret 的 sub 也要是 Bundle ID —— 也就是說後端要能簽兩種 sub 的 client_secret。 client_id 和 sub 對不上時，Apple 回的是 invalid_client 或 invalid_request。

好消息是：同一個人在 Services ID 和 Bundle ID 拿到的 sub 是相同的。 Apple 的使用者識別碼與轉寄信箱都是以開發者團隊（Team）為範圍的， 同一個 Team 底下的 App 和網站看到的是同一個值，所以帳號不會分裂。 （primary App ID 與 App 群組決定的是同意畫面：同一個群組裡的 App 和網站，使用者只需要同意一次。）

反過來說，把 App 轉移到另一個開發者團隊時，sub 和轉寄信箱都會變。 Apple 提供 60 天的轉移期，要在期間內用 user migration 流程把舊的識別碼換成新的 （見 TN3159）。 有計畫賣 App 或換公司帳號的話，要把這件事列進時程。三家 sub 範圍的比較見帳號串接 2.1。

11. 常見錯誤​

Apple 的錯誤回應只有一個 error 代碼、沒有說明文字，同一個代碼在不同端點代表不同的事， 所以要先看是哪一支端點回的：

在哪裡症狀原因
授權頁invalid_clientclient_id 找不到 —— Services ID 打錯（大小寫也算）、或還沒按 Save
授權頁unauthorized_client，或頁面顯示 invalid_request（Invalid web redirect url）redirect_uri 沒登記、跟登記的不是逐字相同、是 IP 或 localhost
callbackerror=user_cancelled_authorize使用者按了取消，正常流程，導回登入頁
callback進來了但 state 對不上、session 是空的form_post 的跨站 POST + SameSite=Lax，見第 4 節
tokeninvalid_clientclient_secret 過期（最常見）／sub 跟 client_id 不完全相同（常見是填成 Team ID）／iss 不是 Team ID／kid 沒放進 header／用錯 .p8／簽章是 DER 格式
tokeninvalid_grantcode 已用過或過期（Apple 的 code 只有 5 分鐘、只能用一次）；client_id 跟當初發 code 的不同（例如原生 App 的 code 用 Services ID 去換）
tokeninvalid_request缺參數、Content-Type 不是 application/x-www-form-urlencoded、參數重複、使用者已經撤銷授權
登入後拿不到姓名只有第一次授權會給；要重測請先在帳號設定裡對你的 App 停止使用，見第 5 節
登入後寄信給使用者一直退信沒做 2.5 的寄件來源登記，或 SPF／DKIM 沒過
開發時本機測不了Apple 不接受 localhost 與 IP，必須用網域，見 2.2
