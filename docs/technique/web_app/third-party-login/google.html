Google 登入

Google 是三家裡面申請最快、文件最完整、坑最少的一家，適合當第一個接的供應商。 基本的登入 scope（openid email profile）不需要任何審查就能上線。

這一篇的程式碼是整個系列的基準實作 —— LINE 和 Apple 兩篇只會講「哪裡不一樣」。

先讀：OAuth 2.0 與 OIDC 基礎（授權碼流程、state／nonce／PKCE）。 程式碼會用到帳號串接的 SignIn 與後端驗證的 session 函式，第 3 節開頭有對照。

1. 申請步驟​

1.1 建立專案與 OAuth 設定​

  1. 到 Google Cloud Console 建立一個專案 （或選一個現成的）。
  2. 左側選單找到 Google Auth Platform（以前是「API 和服務 → OAuth 同意畫面」， 2025 年改版後獨立成這個項目）。第一次進來會要你先做基本設定。

設定分成四個頁籤，意義如下：

頁籤你要填什麼影響
Branding應用程式名稱、logo、使用者支援 email、首頁與隱私權政策／服務條款網址、授權網域（Authorized domains）、開發人員聯絡資訊使用者在同意畫面上看到的東西
AudienceInternal 或 External；發布狀態（Testing／In production）；測試使用者名單誰能登入
Data Access要索取哪些 scope同意畫面上列出的權限、要不要送審
Clients建立 OAuth client、填 JavaScript 來源與 redirect URI你程式裡用的 client_id 與 client_secret

Branding、Audience、Data Access 是整個專案共用的；Clients 底下可以有好幾個 client， 每個 client 各自有自己的 ID、secret 與 redirect URI 清單。

1.2 Audience：Internal 還是 External​

InternalExternal
誰能登入只有你組織裡的帳號任何 Google 帳號
前提專案要隸屬於一個 Google Cloud 組織（通常來自 Google Workspace 或 Cloud Identity）無
有沒有 Testing 狀態沒有有，新建時預設是 Testing
要不要審查不用基本 scope 不用

選 External 之後，應用程式會先處於 Testing（測試中） 狀態。 這個狀態的限制取決於你要了哪些 scope：

只要 openid／email／profile還要了其他 scope
誰能授權任何 Google 帳號，不必在測試使用者名單上只有測試使用者名單上的帳號（最多 100 個），其他人會看到 Error 403: access_denied
授權前的警告頁不會出現會出現
授權效期不會 7 天過期7 天後失效，連帶 refresh token 也失效
tip

只做登入的話，Testing 狀態其實不會擋人 —— 這也是為什麼很多人沒發現自己一直停在 Testing。 問題會在之後加了任何一個非基本 scope 的那天才出現：除了測試使用者之外所有人都登不進來， 測試使用者的 refresh token 也每 7 天失效一次。

所以正式上線前還是要到 Audience → Publish app（發布應用程式） 把狀態切到 In production。 只用非敏感 scope 的話，按下去就直接生效，不需要送審。

1.3 Data Access：哪些 scope 要送審​

類別例子要送審嗎
非敏感openid、email、profile不用
敏感（Sensitive）讀日曆、讀聯絡人要，並且要寫用途、附操作示範影片
受限（Restricted）Gmail 內容、雲端硬碟全部檔案要，而且可能要第三方資安評估

做登入只需要非敏感的三個。 不要「順便」把 Drive、Calendar 的 scope 一起要 —— 那會讓你掉進一個需要好幾週的審查流程，而且同意畫面上的權限變多會直接降低使用者的同意率。

tip

想讓同意畫面顯示你的應用程式名稱和 logo，需要通過品牌驗證（brand verification）； 沒驗證之前使用者只會看到你的網域。品牌驗證跟 scope 審查是兩件事，比較輕量 （官方說明一般是幾個工作天），但要先把 Branding 頁的首頁、隱私權政策網址與授權網域填好， 而且那些網域要是你能證明擁有的。一般網站不做也能正常登入，只是畫面比較陽春。

1.4 Clients：建立 OAuth client​

Clients → Create client → Application type 選 Web application，然後填兩個欄位：

欄位填什麼什麼時候需要
Authorized JavaScript origins（已授權的 JavaScript 來源）https://app.example.com（scheme + 主機名稱（+ port），不含路徑）只有在前端載入 Google 的 JS（GIS 按鈕、One Tap，見第 4 節）時
Authorized redirect URIs（已授權的重新導向 URI）https://app.example.com/auth/google/callback（完整網址，含路徑）用伺服器端授權碼流程時；GIS 的 data-login_uri 也要登記在這裡

本篇第 3 節的做法（瀏覽器被導到後端的 /auth/google，前端完全不載 Google 的 JS） 只需要 redirect URI，JavaScript 來源可以留空。 之後要加 GIS 按鈕或 One Tap 時再回來填。

redirect URI 必須跟你程式送出的 redirect_uri 逐字相同 —— scheme、主機名稱、port、路徑、 大小寫、結尾斜線，差一個字元就是 redirect_uri_mismatch。Google 不做任何正規化， https://app.example.com/auth/google/callback 和 https://app.example.com/auth/google/callback/ 是兩個不同的值。另外還有幾條硬性規則：

  • 必須是 https；localhost（含 127.0.0.1 這類 localhost IP）是例外。 但 http://localhost:3000 和 http://127.0.0.1:3000 是兩個不同的字串，你用哪個測就要登記哪個
  • 不能用一般的 IP 位址當主機、不能有萬用字元、不能有 #fragment
  • 在 Console 改完之後，生效可能要 5 分鐘到幾個小時

建完會給你 Client ID（長得像 123456789-abc.apps.googleusercontent.com） 與 Client secret。

client secret 只有建立當下看得到完整內容。 從 2025 年 6 月起的新 client（既有的 client 則從 2025 年 11 月起）， Google 只存雜湊，之後 Console 只顯示最後四碼，也不能再下載完整的 secret。 建立的那個對話框就要把它存進你的密鑰管理（環境變數、Secret Manager），不要進版控。 弄丟了也不用重建 client：在同一個 client 底下 Add secret 新增一組， 兩組可以並存，換好之後把舊的 Disable 再刪除 —— 這也是正常輪替的方式。

建立時 Console 也提供下載一個 JSON 檔（常見檔名是 client_secret_….json）， 裡面是 client ID、secret、各種端點與 redirect URI。自己寫授權碼流程的話，後端只需要 client ID 和 secret 兩個值， 放環境變數就好，那個 JSON 不必放上伺服器。它是給 Google 自家的用戶端函式庫 （例如 Python 的 google-auth-oauthlib）直接讀檔用的；你沒用那些函式庫， 多放一個含 secret 的檔案在伺服器上只是多一個外洩的地方。

1.5 每個環境（正式、測試）各建一個 OAuth client​

正式站和測試站各建一個 client，各自只登記自己的 redirect URI：

環境client登記的 redirect URI伺服器上的環境變數
正式app-prodhttps://app.example.com/auth/google/callback正式那組的 ID + secret
測試app-staginghttps://staging.example.com/auth/google/callback測試那組的 ID + secret
本機app-dev（可選）http://localhost:3000/auth/google/callback開發者自己的 .env

這樣做的好處是：測試站的 secret 外洩或要輪替，不會動到正式站；也不會有 「正式的 client 上掛著一堆測試網址」這種白名單越開越大、之後沒人敢刪任何一條的情況 （見基礎篇的 redirect URI 白名單）。

warning

client ID 和 secret 一定要取自同一個 client。 兩個環境的值長得很像， 複製貼上時把 A 的 ID 配上 B 的 secret 是很常見的事，而且錯誤訊息不會告訴你是這個原因：

  • 導去 Google 的那一步只用到 client ID，所以會正常出現登入畫面，使用者也能按同意
  • 到了後端拿 code 換 token 時才失敗，拿到的是 invalid_client， 描述往往只有一句 Unauthorized —— 看起來像 secret 打錯，而你會去檢查一個其實沒打錯的 secret

反過來，ID 是對的、但 redirect URI 只登記在另一個 client 上的話，會在第一步就得到 redirect_uri_mismatch。這兩種錯誤只要看到，先確認三個值（ID、secret、redirect URI）出自同一個 client。

幾個相關的細節：

  • 兩個 client 可以放在同一個專案，也可以分成兩個專案。 同一個專案的話，Branding、 Audience（包括發布狀態）是共用的 —— 測試站沒辦法單獨停在 Testing。需要把兩邊完全隔開 （例如測試站要用另一個應用程式名稱）就分專案。
  • Google 的 sub 在不同 client 之間是同一個值。 官方的定義是「在所有 Google 帳戶中唯一、 而且永不重複使用」的帳戶識別碼，不是 per-client 的。所以同一個人在正式站和測試站會拿到相同的 sub （LINE 與 Apple 不是這樣，三家的比較見帳號串接 2.1）。
  • 久沒用的 client 會被自動刪除。 連續六個月沒有任何授權或 token 請求、也沒有被修改過的 client， Google 會先寄通知、30 天後刪除，之後用它登入會得到 deleted_client（刪除後至少 30 天內可以從 Console 還原）。 少用的測試站和本機 client 最容易中這一條。

1.6 各種 client type 的差別​

Application type有 client_secret 嗎用在哪
Web application有有後端的網站
Android / iOS沒有（公開用戶端）原生 App，靠 PKCE + 套件名稱／簽章或 Bundle ID 識別
Desktop app有，但不被當成機密桌面程式，用 loopback redirect

原生 App 的做法見原生 App 與行動裝置。

3. 完整實作​

三個版本做的事完全一樣：產生 state／nonce／PKCE → 導向 Google → 比對 state → 換 token → 驗 id_token → 呼叫帳號串接裡的 SignIn／sign_in!／sign_in → 換發 session。

client ID、secret、redirect URI 三個都從環境變數讀（GOOGLE_CLIENT_ID、GOOGLE_CLIENT_SECRET、GOOGLE_REDIRECT_URI）， 這樣正式站與測試站只差設定、不差程式碼（1.5）。

用 go-oidc + x/oauth2。 go-oidc 會自己讀 discovery document，並處理 JWKS 的快取與金鑰輪替。 路由寫法（"GET /path"）需要 Go 1.22 以上；另外這幾個套件的最新版本會要求較新的 Go （撰稿時 x/oauth2 最新版要求 Go 1.26），Go 1.21 起 go get 預設會自動下載需要的工具鏈。

go get github.com/coreos/go-oidc/v3/oidc golang.org/x/oauth2 github.com/gorilla/sessions
internal/authgoogle/google.go
package authgoogle

import (
	"context"
	"database/sql"
	"log"
	"net/http"
	"os"

	"github.com/coreos/go-oidc/v3/oidc"
	"github.com/gorilla/sessions"
	"golang.org/x/oauth2"

	"example.com/app/internal/accounts"
	"example.com/app/internal/web"
)

var (
	oauthConf *oauth2.Config
	verifier  *oidc.IDTokenVerifier
	// 只放 OAuth 交易用的短命資料（state、nonce、code_verifier），跟登入用的 session 分開
	txStore = sessions.NewCookieStore([]byte(os.Getenv("SESSION_SECRET")))
)

// Init 在程式啟動時呼叫一次，issuer 傳 "https://accounts.google.com"。
// 做成參數是為了測試時能指向假的 IdP（見測試篇第 2 節）。
// oidc.NewProvider 會抓 discovery document，之後的 JWKS 快取也由它管理。
func Init(ctx context.Context, issuer string) error {
	provider, err := oidc.NewProvider(ctx, issuer)
	if err != nil {
		return err
	}
	clientID := os.Getenv("GOOGLE_CLIENT_ID")

	oauthConf = &oauth2.Config{
		ClientID:     clientID,
		ClientSecret: os.Getenv("GOOGLE_CLIENT_SECRET"), // 必須跟 ClientID 出自同一個 client
		RedirectURL:  os.Getenv("GOOGLE_REDIRECT_URI"),  // 必須跟 Console 登記的逐字相同
		Endpoint:     provider.Endpoint(),
		Scopes:       []string{oidc.ScopeOpenID, "email", "profile"},
	}
	// Verifier 會檢查簽章、iss、aud、exp
	verifier = provider.Verifier(&oidc.Config{ClientID: clientID})
	return nil
}

// ── 第一步：把使用者導去 Google ──────────────────────────────
func Start(w http.ResponseWriter, r *http.Request) {
	state := web.RandomToken()
	nonce := web.RandomToken()
	codeVerifier := oauth2.GenerateVerifier()

	tx, _ := txStore.New(r, "google_tx")
	tx.Values["state"] = state
	tx.Values["nonce"] = nonce
	tx.Values["code_verifier"] = codeVerifier
	tx.Options = &sessions.Options{
		Path: "/", HttpOnly: true, Secure: true, MaxAge: 600,
		SameSite: http.SameSiteLaxMode,
	}
	if err := tx.Save(r, w); err != nil {
		http.Error(w, "無法建立登入工作階段", http.StatusInternalServerError)
		return
	}

	http.Redirect(w, r, oauthConf.AuthCodeURL(state,
		oidc.Nonce(nonce),
		oauth2.S256ChallengeOption(codeVerifier),
		// 需要離線呼叫 Google API 才加這兩個；純登入不需要
		// oauth2.AccessTypeOffline,
		// oauth2.ApprovalForce,
	), http.StatusFound)
}

// ── 第二步：Google 導回來 ────────────────────────────────────
func Callback(db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		ctx := r.Context()
		q := r.URL.Query()

		tx, _ := txStore.Get(r, "google_tx")
		state, _ := tx.Values["state"].(string)
		nonce, _ := tx.Values["nonce"].(string)
		codeVerifier, _ := tx.Values["code_verifier"].(string)
		tx.Options.MaxAge = -1 // 不論成敗都作廢，避免重放
		_ = tx.Save(r, w)

		// 使用者按了「取消」會走到這裡，error=access_denied
		if q.Get("error") != "" {
			http.Redirect(w, r, "/login?error=cancelled", http.StatusSeeOther)
			return
		}
		if !web.SameToken(state, q.Get("state")) {
			http.Error(w, "state 不符", http.StatusBadRequest)
			return
		}

		// 用 code 換 token（伺服器對伺服器，client_secret 只出現在這裡）
		tok, err := oauthConf.Exchange(ctx, q.Get("code"), oauth2.VerifierOption(codeVerifier))
		if err != nil {
			// 錯誤內容含 Google 回的 error／error_description，記下來。
			// invalid_client 先懷疑 ID 與 secret 是不是出自同一個 client（1.5 節）
			log.Printf("google token 兌換失敗：%v", err)
			http.Error(w, "登入失敗", http.StatusBadGateway)
			return
		}

		rawIDToken, ok := tok.Extra("id_token").(string)
		if !ok {
			http.Error(w, "回應缺少 id_token", http.StatusBadGateway)
			return
		}
		// 簽章、iss、aud、exp 在這一行一起驗
		idToken, err := verifier.Verify(ctx, rawIDToken)
		if err != nil {
			log.Printf("id_token 驗證失敗：%v", err)
			http.Error(w, "登入失敗", http.StatusUnauthorized)
			return
		}
		// nonce 要自己比，函式庫不會做
		if !web.SameToken(nonce, idToken.Nonce) {
			log.Printf("id_token 的 nonce 不符")
			http.Error(w, "登入失敗", http.StatusUnauthorized)
			return
		}

		var claims struct {
			Sub           string `json:"sub"`
			Email         string `json:"email"`
			EmailVerified bool   `json:"email_verified"`
			Name          string `json:"name"`
			Picture       string `json:"picture"`
		}
		if err := idToken.Claims(&claims); err != nil {
			http.Error(w, "無法解析 claims", http.StatusBadGateway)
			return
		}

		user, err := accounts.SignIn(ctx, db, accounts.ProfileFromProvider{
			Provider:       "google",
			ProviderUserID: claims.Sub, // ★ 使用者的唯一鍵，不要用 email
			Email:          claims.Email,
			EmailVerified:  claims.EmailVerified,
			DisplayName:    claims.Name,
			AvatarURL:      claims.Picture,
		}, web.CurrentUserID(r)) // 已登入就是「綁定」，見帳號串接第 6 節
		if err != nil {
			web.SignInErrorRedirect(w, r, err)
			return
		}
		// 換發 session ID（防 session fixation）
		if err := web.StartSession(w, r, user.ID); err != nil {
			log.Printf("無法建立 session：%v", err)
			http.Error(w, "登入失敗", http.StatusInternalServerError)
			return
		}
		http.Redirect(w, r, "/", http.StatusSeeOther)
	}
}

  REDIRECT_URI  = ENV.fetch("GOOGLE_REDIRECT_URI")    # 必須跟 Console 登記的逐字相同
  AUTH_URL      = "https://accounts.google.com/o/oauth2/v2/auth".freeze
  TOKEN_URL     = "https://oauth2.googleapis.com/token".freeze
  JWKS_URL      = "https://www.googleapis.com/oauth2/v3/certs".freeze
  # Google 的 iss 有兩種寫法，兩個都要接受
  ISSUERS       = ["https://accounts.google.com", "accounts.google.com"].freeze

  TokenExchangeError = Class.new(StandardError)

  # ruby-jwt 的 jwks loader：平常回快取；遇到快取裡沒有的 kid 時
  # （options[:kid_not_found]）重抓，但五分鐘內最多重抓一次，
  # 免得一堆亂填 kid 的 token 讓你一直去打 Google
  JWKS_LOADER = lambda do |options|
    if options[:kid_not_found] && @jwks_fetched_at.to_i < Time.now.to_i - 300
      @cached_jwks = nil
    end
    @cached_jwks ||= begin
      @jwks_fetched_at = Time.now.to_i
      JSON.parse(Net::HTTP.get(URI(JWKS_URL)), symbolize_names: true)
    end
  end

  def self.verify_id_token(id_token, expected_nonce)
    claims, = JWT.decode(
      id_token, nil, true,
      algorithms: ["RS256"],      # 白名單，防 alg confusion
      jwks: JWKS_LOADER,
      iss: ISSUERS, verify_iss: true,
      aud: CLIENT_ID, verify_aud: true,
      verify_expiration: true,
      leeway: 60,                 # 容忍時鐘誤差
    )
    # nonce 要自己比，函式庫不會做
    raise JWT::DecodeError, "nonce 不符" unless expected_nonce.present? &&
      ActiveSupport::SecurityUtils.secure_compare(claims["nonce"].to_s, expected_nonce.to_s)

    claims
  end
end

    nonce         = SecureRandom.urlsafe_base64(32)

                            "code_verifier" => code_verifier }

    query = {
      client_id: GoogleOIDC::CLIENT_ID,
      redirect_uri: GoogleOIDC::REDIRECT_URI,
      response_type: "code",
      scope: "openid email profile",
      state: state,
      nonce: nonce,
      code_challenge: Base64.urlsafe_encode64(
        Digest::SHA256.digest(code_verifier), padding: false,
      ),
      code_challenge_method: "S256",
      # 需要離線呼叫 Google API 才加：access_type: "offline", prompt: "consent"
    }
    redirect_to "#{GoogleOIDC::AUTH_URL}?#{query.to_query}", allow_other_host: true
  end

  # callback 是 GET，Rails 的 CSRF 檢查本來就不管 GET；這裡靠 state 防護
  def callback
    saved = session.delete(:google_tx) # 不論成敗都作廢，避免重放

    # 使用者按了「取消」會走到這裡
    return redirect_to(login_path, alert: "已取消登入") if params[:error].present?

    unless saved && ActiveSupport::SecurityUtils.secure_compare(
      saved["state"], params[:state].to_s
    )
      return head :bad_request
    end

    tokens = exchange_code(params[:code].to_s, saved["code_verifier"])
    claims = GoogleOIDC.verify_id_token(tokens["id_token"], saved["nonce"])

    user = Identity.sign_in!(
      {
        provider: "google",
        provider_user_id: claims["sub"],   # ★ 唯一鍵，不要用 email
        email: claims["email"],
        email_verified: claims["email_verified"],
        email_is_relay: false,
        display_name: claims["name"],
        avatar_url: claims["picture"],
      },
      current_user: current_user,          # 已登入就是「綁定」，見帳號串接第 6 節
    )

    start_session(user)                    # 換發 session id，防 session fixation
    redirect_to root_path
  rescue Identity::SignInError => e
    redirect_sign_in_error(e)
  rescue GoogleOIDC::TokenExchangeError
    head :bad_gateway
  rescue JWT::DecodeError => e
    Rails.logger.warn("google id_token 驗證失敗：#{e.message}")
    head :unauthorized
  end

  private

  def exchange_code(code, code_verifier)
    res = Net::HTTP.post_form(URI(GoogleOIDC::TOKEN_URL), {
      "grant_type"    => "authorization_code",
      "code"          => code,
      "redirect_uri"  => GoogleOIDC::REDIRECT_URI, # 必須與第一步完全相同
      "client_id"     => GoogleOIDC::CLIENT_ID,
      "client_secret" => GoogleOIDC::CLIENT_SECRET,
      "code_verifier" => code_verifier,
    })
    unless res.is_a?(Net::HTTPSuccess)
      # body 是 Google 回的 error／error_description，記下來。
      # invalid_client 先懷疑 ID 與 secret 是不是出自同一個 client（1.5 節）
      Rails.logger.error("google token 兌換失敗：#{res.body}")
      raise GoogleOIDC::TokenExchangeError
    end
    JSON.parse(res.body)
  end
end

    request: Request,
    code: str | None = None,
    state: str | None = None,
    error: str | None = None,
    db: Session = Depends(get_db),
):
    saved = request.session.pop("google_tx", None)  # 不論成敗都作廢

    # 使用者按了「取消」會走到這裡，error=access_denied
    if error:
        return RedirectResponse("/login?error=cancelled", status_code=303)
    # compare_digest 收 str 時遇到非 ASCII 會丟 TypeError（變成 500），一律比 bytes
    if not saved or not secrets.compare_digest(
        saved["state"].encode(), (state or "").encode()
    ):
        raise HTTPException(400, "state 不符")
    if not code:
        raise HTTPException(400, "缺少 code")

    tokens = await exchange_code(code, saved["code_verifier"])
    try:
        claims = verify_id_token(tokens["id_token"], saved["nonce"])
    except jwt.PyJWTError as exc:
        log.warning("google id_token 驗證失敗：%s", exc)
        raise HTTPException(401, "登入失敗") from exc

    profile = ProfileFromProvider(
        provider="google",
        provider_user_id=claims["sub"],  # ★ 唯一鍵，不要用 email
        email=claims.get("email"),
        email_verified=bool(claims.get("email_verified")),
        display_name=claims.get("name"),
        avatar_url=claims.get("picture"),
    )
    try:
        # 已登入就是「綁定」，見帳號串接第 6 節
        user = sign_in(db, profile, current_user=get_current_user(request, db))
    except SignInError as exc:
        return sign_in_error_redirect(exc)

    start_session(request, user)  # 換發 session，防 session fixation
    return RedirectResponse("/", status_code=303)


async def exchange_code(code: str, code_verifier: str) -> dict:
    async with httpx.AsyncClient(timeout=10) as client:
        res = await client.post(TOKEN_URL, data={
            "grant_type": "authorization_code",
            "code": code,
            "redirect_uri": REDIRECT_URI,  # 必須與第一步完全相同
            "client_id": CLIENT_ID,
            "client_secret": CLIENT_SECRET,
            "code_verifier": code_verifier,
        })
    if res.status_code != 200:
        # body 是 Google 回的 error／error_description，記下來。
        # invalid_client 先懷疑 ID 與 secret 是不是出自同一個 client（1.5 節）
        log.error("google token 兌換失敗：%s", res.text)
        raise HTTPException(502, "登入失敗")
    return res.json()


def verify_id_token(id_token: str, expected_nonce: str) -> dict:
    """驗簽章、iss、aud、exp、nonce。任何一項失敗都丟 jwt.PyJWTError 的子類別。"""
    signing_key = jwk_client.get_signing_key_from_jwt(id_token)
    claims = jwt.decode(
        id_token,
        signing_key.key,
        algorithms=["RS256"],   # 白名單，防 alg confusion
        audience=CLIENT_ID,
        issuer=ISSUERS,         # PyJWT 2.9 起可以傳多個
        leeway=60,              # 容忍時鐘誤差
        options={"require": ["exp", "iat", "sub", "aud", "iss"]},
    )
    # nonce 要自己比，函式庫不會做
    if not expected_nonce or not secrets.compare_digest(
        str(claims.get("nonce", "")).encode(), expected_nonce.encode()
    ):
        raise jwt.InvalidTokenError("nonce 不符")
    return claims

如果你只要「一鍵登入」、不需要呼叫任何 Google API，可以用官方的 JS 元件（Google Identity Services，簡稱 GIS）， 它會直接給你一段 ID token（也就是總覽裡的（B）架構）。

data-nonce 要由後端在產生這一頁的時候隨機產生、存進 session（下面範例用 gsi_nonce 這個鍵）， 再輸出到頁面上；data-auto_prompt="false" 表示只顯示按鈕、不自動跳 One Tap。

後端收的一定是原始的 credential 字串，自己驗簽；前端解開的 payload 是使用者可以隨手改的 （理由見後端驗證第 1 節）。

用 GIS 時 Console 上要多登記兩樣東西（純後端流程不需要，見 1.4）：

  • Authorized JavaScript origins：載入按鈕的那個網域，例如 https://app.example.com。 本機測試要同時登記 http://localhost 和 http://localhost:<port>， 並讓頁面回應 Referrer-Policy: no-referrer-when-downgrade
  • Authorized redirect URIs：data-login_uri 的完整網址，也必須逐字相同 （只有在 popup 模式又改用 data-callback 接結果時才不需要）

另外，按鈕預設是 data-ux_mode="popup"。改成 redirect 的話，送到 data-login_uri 的 POST 是從 Google 的頁面發過來的跨站 POST，SameSite=Lax 的 session cookie 不會跟著送出 —— 跟 Apple 第 4 節是同一個問題，session 裡的 gsi_nonce 會讀不到。

note

One Tap 已經全面改用瀏覽器的 FedCM API。 Google 從 2024 年 10 月起把 One Tap 的流量 全部遷到 FedCM，data-use_fedcm_for_prompt（JS 的 use_fedcm_for_prompt）現在已標為 deprecated、 設了也會被忽略，網路上舊範例裡的這個屬性可以直接拿掉。按鈕則是另一個選用的 data-use_fedcm_for_button，預設 false。

遷移後最常見的「One Tap 不跳」原因：

  • 還在用 prompt() 回呼裡的顯示狀態方法（isNotDisplayed()、getNotDisplayedReason() 等） —— FedCM 下不再回報這些狀態，依賴它們的邏輯會失效
  • 按鈕放在跨來源的 <iframe> 裡，但 iframe 沒加 allow="identity-credentials-get"
  • 自訂的 One Tap 位置、樣式：FedCM 的提示由瀏覽器繪製，不吃這些設定

細節見 Google：遷移到 FedCM。

5. Refresh token 的行為​

純登入用不到 refresh token；要定期呼叫 Google API 才需要。Google 的規則比較特別：

  • 只有 access_type=offline 才會核發。
  • 只有第一次授權那次會給。使用者之後再登入，回應裡不會再有 refresh_token —— 除非你加上 prompt=consent 強制重新同意，或使用者先撤銷了授權。
  • 所以 refresh token 拿到就要存起來，而且要當成密碼等級的機密保護 （存法見後端驗證第 6 節）。
  • 每個 Google 帳號對每個 client 最多 100 個有效的 refresh token，超過時最舊的會自動失效。 每次登入都加 prompt=consent 重拿一個的寫法，會在某天讓舊的悄悄失效。
  • 應用程式在 Testing 狀態、而且要了 openid／email／profile 以外的 scope 時， refresh token 7 天就過期（見 1.2）。
  • 其他會讓它失效的情況：六個月沒使用、使用者撤銷授權、使用者授權時選了限時存取而時間到了、 （要了 Gmail scope 時）使用者改了密碼、Workspace 管理員限制了你要的服務。 你的程式要能處理「refresh 失敗」，引導使用者重新授權，而不是丟 500。

6. Google 特有的坑​

症狀原因
Error 400: redirect_uri_mismatch送出的 redirect_uri 與這個 client 登記的值不是逐字相同。見下方說明
登入畫面正常出現，換 token 時 invalid_client（常常只寫 Unauthorized）client ID 和 secret 取自不同的 client（例如正式站的 ID 配上測試站的 secret）；或那組 secret 已經被 Disable。見 1.5
Error 401: deleted_client這個 client 被刪了 —— 可能是有人手動刪，也可能是六個月沒用被自動刪除。30 天內可以到 Console 還原
Error 403: access_denied，只有少數帳號能登入應用程式還在 Testing，而且要了基本三個以外的 scope，其他人不在測試使用者名單裡。只要 openid email profile 的話 Testing 不會擋人
Error 403: org_internalAudience 選了 Internal，非組織成員無法登入
disallowed_useragent在 WebView 裡跑登入，Google 會直接擋。見原生 App
拿不到 refresh_token沒帶 access_type=offline，或使用者先前已同意過（要加 prompt=consent）
拿不到 emailscope 沒有 email；或者拿到了但 email_verified 是 false
同意畫面只顯示網域，沒有應用程式名稱和 logo還沒通過品牌驗證，見 1.3

redirect_uri_mismatch 怎麼查： 錯誤頁本身不會告訴你哪裡不一樣，但頁面上有一個 「錯誤詳情」（error details）的連結，展開後的 Request details 會列出你實際送出的 redirect_uri=…。把那個值複製出來，跟 Console 上同一個 client 的清單逐字比對：

  • scheme：http vs https（反向代理後面的程式最常自己組出 http://）
  • 主機名稱：www.example.com vs example.com、localhost vs 127.0.0.1
  • port：:3000 有沒有、是不是同一個
  • 路徑：大小寫、結尾斜線
  • client：確認你看的 Console 頁面就是程式裡那個 client ID 對應的 client

同一行後面常會接著 flowName=GeneralOAuthFlow，那是 Google 自己的參數，不是你的 redirect URI 的一部分。 改完 Console 之後，生效可能要 5 分鐘到幾個小時，剛改完馬上測還是失敗不一定代表改錯。
