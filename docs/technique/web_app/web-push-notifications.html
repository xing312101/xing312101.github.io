網頁的桌面通知（Web Push）

網站的通知除了畫面上的鈴鐺，還可以跳到作業系統的通知：Windows 右下角、Mac 右上角、Linux 桌面的通知泡泡。 這份講它怎麼運作、使用者要在電腦上設什麼（這是最常被問的）、沒跳出來怎麼查，最後是實作時的坑。

0. 兩種做法，差在「網頁關了收不收得到」​

A. Notification APIB. Web Push
什麼時候跳網頁開著才會（分頁在背景、視窗縮小都可以）網頁關了也會：電腦開著、瀏覽器在背景執行就收得到
誰叫它跳頁面上的 JavaScript 收到資料後自己叫 new Notification()伺服器 → 瀏覽器廠商的推播服務 → 瀏覽器的 Service Worker
工程只改前端前後端都要改、要存每台電腦的訂閱、要一把金鑰

使用者說「瀏覽器關了也要收」就是 B。B 做好之後網頁開著時一樣會跳，A 不用另外做。

1. Web Push 怎麼運作（鎖定的是「瀏覽器」，不是電腦也不是帳號）​

① 使用者按「允許通知」
   瀏覽器向自家的推播服務要一個「投遞地址」(endpoint)
     Chrome → fcm.googleapis.com（Google）
     Edge   → *.notify.windows.com（微軟 WNS）
     Firefox→ updates.push.services.mozilla.com
     Safari → *.push.apple.com
② 前端把 endpoint ＋ 兩把加密用的鑰匙（p256dh、auth）送到你的伺服器，記在這個帳號底下
③ 有通知時：伺服器用那兩把鑰匙加密內容、用自己的 VAPID 私鑰簽名 → POST 到 endpoint
④ 推播服務把它送到那台電腦的那個瀏覽器 → Service Worker 收到 push 事件 → showNotification()
⑤ 作業系統把它顯示成通知
  • endpoint 代表「這台電腦的這個瀏覽器」。同一個人在三台電腦按過允許，就有三個 endpoint；同一台電腦的 Chrome 和 Edge 也是兩個
  • 推播服務看不到內容：內容用瀏覽器給的公鑰加密（RFC 8291），它只知道「什麼時候送了一則給誰」
  • VAPID 金鑰：伺服器的一把 P-256 私鑰，瀏覽器訂閱時記住對應的公鑰，用來確認「這則真的是這個網站送的」。 一站一把、之後不要換 —— 換了之後舊的訂閱全部推不出去，每個人都要重新按一次允許
  • 費用：免費，各家推播服務都不收錢（跟 LINE 推播不同，不算額度）

2. 使用者端的設定​

三層都要開，少一層就不會跳，而且沒有任何錯誤訊息：

  1. 網站層：瀏覽器准這個網站送通知
  2. 瀏覽器層：作業系統准這個瀏覽器送通知
  3. 背景執行：瀏覽器關掉視窗後還在背景跑（不然「瀏覽器關了也要收」做不到）
實測範圍

2026-11 實測：

  • Windows：通知照常跳在右下角
  • macOS＋Google Chrome：訂閱、收到、分頁關掉也收到、測試通知回報都正常，但畫面上一則都沒跳 —— 原因是專注模式開著， 通知全進了通知中心（見 §3.1）。關掉之後就跳出來了。網頁端判斷「收到了」是對的，擋住的是作業系統
  • Linux 的選單路徑照設定介面整理，沒有實測；版本不同時名稱可能略有出入，以畫面為準

2.1 Windows 10／11​

① 網站准許通知

  • 第一次打開網站的通知開關時，瀏覽器會跳出「要允許通知嗎」→ 按允許
  • 按成封鎖的話：點網址列左邊的鎖頭（或設定圖示）→「通知」改成「允許」，重新整理頁面
  • 也可以到總表改：
    • Chrome：chrome://settings/content/notifications
    • Edge：edge://settings/content/notifications

② Windows 准許瀏覽器通知

  • Windows 11：設定 → 系統 → 通知
    • 最上面的「通知」要開
    • 往下找 Google Chrome／Microsoft Edge，開關要開
    • 點進去可以設「顯示通知橫幅」「在通知中心顯示」「在鎖定畫面上顯示」
  • Windows 10：設定 → 系統 → 通知與動作，「取得來自應用程式和其他寄件者的通知」要開，下面的瀏覽器也要開
  • 勿擾（Windows 11，通知設定最上面）／專注輔助（Windows 10）開著的話，通知只會進通知中心、不會跳出來。 會議、簡報時 Windows 可能自動打開

③ 關掉瀏覽器後還要收

  • Chrome：設定 → 系統 →「關閉 Google Chrome 後繼續執行背景應用程式」 打開
  • Edge：設定 → 系統與效能 →「關閉 Microsoft Edge 時，繼續執行背景擴充功能及應用程式」 打開
  • 確認方法：關掉所有視窗後，右下角系統匣（^ 箭頭裡）還看得到 Chrome／Edge 的圖示
  • 重新開機之後，保險的做法是先打開一次瀏覽器（之後可以關）。有沒有開機自動在背景啟動依版本與設定而定，以實測為準

隱私：Windows 的通知中心會留著歷史，登出網站後用同一台電腦的人點開通知中心還看得到；鎖定畫面也可能顯示內容。 共用電腦建議在 ② 把「在鎖定畫面上顯示」關掉。網站那邊最好只推標題、不推個資（見 §4）。

2.2 macOS​

① 網站准許通知：同 Windows（網址列左邊的圖示 → 通知 → 允許）。Safari 是 Safari → 設定 → 網站 → 通知。

② macOS 准許瀏覽器通知

  • 系統設定 → 通知 → Google Chrome（或 Microsoft Edge、Safari）→「允許通知」打開
  • 提示樣式：
    • 「橫幅」：幾秒後自己消失
    • 「提示」：要按掉才會消失，比較不會漏看
  • 第一次網站要送通知時，macOS 會另外問一次「Google Chrome 想傳送通知」→ 要按允許。 這一步沒按，網站那邊顯示已允許、卻一則都不會出現
  • 專注模式開著時不會跳、但會進通知中心，而且沒有任何提示 —— 這是 Mac 上最常見的「設定全對卻沒跳」：
    • 看有沒有開：選單列右上角出現月亮（或其他專注圖示）；或打開控制中心（右上角兩個開關的圖示）看「專注模式」
    • 關掉它；不想關的話到 系統設定 → 專注模式 → 那個模式 →「允許的通知」 把瀏覽器加進去
    • 有些模式會照時間、地點或打開某個 App 時自動開（「排程」），關了之後過一陣子又自己開起來，要去那裡看
    • 跟 iPhone 共用專注狀態（「跨裝置共享」）的話，手機開了勿擾 Mac 也跟著開
  • 鏡像輸出或共享螢幕時 macOS 預設不跳通知：系統設定 → 通知 最上面「鏡像輸出或共享顯示器時允許通知」
  • 系統設定的通知列表裡可能有兩個同名的「Google Chrome」（不同版本、不同安裝位置留下來的），兩個都要開
  • 新版 macOS 的提示樣式改成勾選「桌面」「鎖定畫面」「通知中心」：要跳出來就要勾「桌面」

③ 關掉瀏覽器後還要收

  • Mac 上關掉視窗不等於結束程式：Dock 上的 Chrome 下面還有小點就還在跑，收得到
  • 按 ⌘Q 結束就收不到了
  • Safari：macOS 13（Ventura）起支援 Web Push；Safari 沒開著時收不收得到依版本而定

2.3 Linux 桌面版​

① 網站准許通知：同上。

② 桌面環境准許通知：瀏覽器走的是桌面的通知服務（freedesktop 的 org.freedesktop.Notifications）。

  • GNOME：設定 → 通知 → 找到 Chrome／Chromium／Firefox，開關要開。最上面的「勿擾」要關
  • KDE Plasma：系統設定 → 通知 → 應用程式設定裡找瀏覽器
  • 很精簡的視窗管理員（i3、sway 這類）要自己裝通知程式（dunst、mako），不然瀏覽器送了也沒地方顯示
  • 用 notify-send 測試 "看得到這一則嗎" 先確定桌面本身會顯示通知

③ 關掉瀏覽器後還要收

  • Chrome：設定 → 系統 →「關閉 Google Chrome 後繼續執行背景應用程式」
  • ⚠️ 不是 Google 官方版的 Chromium 可能訂閱不了：Chrome 的推播走 Google 的服務，發行版自己編的 Chromium、Flatpak 版 常見的情況是沒有帶 Google 的金鑰，訂閱時失敗（AbortError: Registration failed - …，後面的字依版本而定）。 2026-11 實測：Playwright 內建的 Chromium 訂閱失敗、同一台電腦裝的 Google Chrome 就成功。遇到時請改裝 Google Chrome 或 Microsoft Edge

2.4 Firefox 要特別講​

Firefox 桌面版關掉之後就收不到（它不會留在背景）。開著的時候收得到。要「瀏覽器關了也要收」的人請用 Chrome 或 Edge。

2.5 手機​

  • Android 的 Chrome 支援，但通常手機已經有 LINE 或 app 推播，網站不一定要在手機上問
  • iPhone／iPad：iOS 16.4 起，要先把網站「加入主畫面」，從主畫面打開的那個才能訂閱；Safari 分頁裡不行

3. 沒跳出來時，照這個順序查​

第一步永遠是打開通知中心，看那一則在不在（Windows 點右下角的時間；Mac 點右上角的日期時間；Linux 打開桌面的通知清單）：

  • 在裡面 → 電腦收到了、只是沒讓它跳出來。九成是勿擾／專注模式，其次是「橫幅」被關掉（只進通知中心）。直接看下表的「勿擾／專注」那一列
  • 不在裡面 → 網站、瀏覽器或作業系統那一層沒准，或瀏覽器根本沒收到。照下表從上往下查
查什麼怎麼看常見原因
網站准了沒網址列左邊的圖示 → 通知第一次按成「封鎖」
作業系統准了沒Windows：設定 → 系統 → 通知；Mac：系統設定 → 通知瀏覽器那一列被關掉、macOS 那次詢問沒按允許
勿擾／專注通知設定最上面、控制中心開會時自動打開、忘了關
瀏覽器有沒有在背景系統匣（Windows）、Dock 的小點（Mac）背景執行沒開、⌘Q 結束了、重開機後沒開過瀏覽器
進了通知中心但沒跳點開通知中心看有沒有橫幅被關掉（只進通知中心）、勿擾
網站那邊的開關網站的設定頁換了電腦（每台要各自開）、登出時自動關掉了、太久沒開網站被停掉
用的是哪個瀏覽器Firefox 關著收不到、Linux 自己編的 Chromium 訂閱不了

分辨是哪一段的問題：網站有「送一則測試通知」的話（§4.6），它會告訴你瀏覽器收到了沒。 瀏覽器收到了卻沒跳出來 → 問題在 §2 的 ②（作業系統那一層）；瀏覽器沒收到 → 問題在網路（公司防火牆擋了推播服務）、伺服器或訂閱。 Chrome 另外有 chrome://gcm-internals 可以看推播服務的連線與收到的訊息（開始記錄之後才會記）。

3.1 Mac：看作業系統為什麼沒讓它跳（給工程人員）​

畫面上看不出來被擋的原因時，macOS 的系統紀錄寫得很清楚。開一個終端機，送一則測試通知，看它寫什麼：

# 注意要寫 /usr/bin/log：zsh 有一個同名的內建指令 log，直接打 log 會跑錯
/usr/bin/log stream --style compact \
  --predicate 'process == "usernoted" OR process == "NotificationCenter"' | grep -iE 'chrome|suppress|DND|focus'
紀錄裡看到意思
muted by DND suppression: delay、activeModeUUID 有值專注模式擋住了：通知收進通知中心、不跳。關掉專注模式，或把瀏覽器加進那個模式的「允許的通知」
suppression 是 none沒被擋，應該會跳；還是沒看到的話看提示樣式／「桌面」有沒有勾
完全沒有那個瀏覽器的紀錄通知沒到作業系統：瀏覽器那一層（§2 的 ①）、或瀏覽器根本沒收到

2026-11 Mac 沒跳的那次就是這樣查到的：設定畫面全部正確，紀錄寫著 muted by DND suppression，原因是專注模式開著。

3.2 Windows：先看通知中心，再看勿擾​

  • 右下角時間旁邊出現月亮／「勿擾」圖示＝勿擾開著。點時間打開通知中心，最上面就有勿擾的開關
  • Windows 11 的勿擾可以照時間自動打開、複製畫面（投影）／全螢幕遊戲／全螢幕 App 時自動打開：設定 → 系統 → 通知 →「自動開啟勿擾」
  • 通知進了通知中心卻沒跳：設定 → 系統 → 通知 → 點進瀏覽器 →「顯示通知橫幅」要開

4. 實作時的坑（開發者看）​

4.0 VAPID 金鑰：產生、存放、不要換​

  • 一把 P-256（prime256v1）私鑰。一個網站（一個環境）一把：測試站與正式站分開，一邊外流不影響另一邊，通知也不會跑錯站

  • 只要存私鑰一個值，公鑰從私鑰算（給瀏覽器訂閱用的 applicationServerKey＝未壓縮點的 base64url，65 bytes、0x04 開頭）。存兩個值容易對不上

  • 在主機上產生、直接寫進 .env，不印到畫面、不貼到聊天、不進 Git／CI 變數。拿到它就能冒充網站推通知（可以拿來釣魚）

    # Python（cryptography）：印成一行 .env 設定，直接附加進去
    python -c "import base64; from cryptography.hazmat.primitives.asymmetric import ec; \
    k = ec.generate_private_key(ec.SECP256R1()); \
    print('VAPID_PRIVATE_KEY=' + base64.urlsafe_b64encode(k.private_numbers().private_value.to_bytes(32, 'big')).decode().rstrip('='))" >> .env
    # Node：npx web-push generate-vapid-keys（會印出公鑰與私鑰，要自己貼，注意別留在終端機紀錄裡）

  • 之後固定不換：瀏覽器訂閱時記住的是那時候的公鑰，換了之後舊的訂閱全部推不出去，每個人都要重新打開一次。 主機重建、搬家時要把這一行帶走（跟 JWT 的簽章金鑰一樣）

  • 加之前先備份 .env、確認還沒有這一行（重產＝換掉）

  • 沒設的時候功能應該整個關著（開關顯示「伺服器還沒設定」），不要讓其他功能跟著壞

  • 另外要一個 sub（mailto: 或 https:// 網址）：推播服務出問題時找得到發的人。可以直接用網站網址

4.1 內容不要放個資​

右下角跳出來旁人看得到，Windows 通知中心會留著，鎖定畫面可能顯示。只推標題＋一句摘要（例如「工單完工：RP-001｜服務總表」）， 電話、地址、內容要點進網站才看得到。

4.2 收進來的 endpoint 要擋網域（SSRF）​

endpoint 是瀏覽器給的，但經過使用者的手送到你的伺服器 —— 之後伺服器會對這個網址發 POST。不擋的話， 有人可以登記 http://169.254.169.254/...（雲端主機的中繼資料）或內網網址，讓伺服器替他去打。 只收 https、預設埠，主機名是那幾家推播服務（§1 的清單，比對要用「等於」或「結尾是 .notify.windows.com」， 不要用「包含」—— fcm.googleapis.com.evil.example 也包含）。

4.3 訂閱什麼時候要刪​

時機為什麼
使用者關掉開關後端那一列＋瀏覽器的 subscription.unsubscribe() 都要做
登出共用電腦：不刪的話下一個人會收到上一個人的通知。要在清掉登入憑證之前（刪的 API 要登入）
帳號停用他家裡的電腦會一直收到
推播服務回 404／410訂閱已經沒了（使用者清掉網站資料、在瀏覽器取消）
太久沒打開網站（例如 60 天）共用電腦沒登出就關掉的情況
打開網站時發現瀏覽器裡的訂閱不是現在登入的人的上一個人沒登出 → 取消掉，不要默默轉給新的人

憑證過期不要刪：同一個人再登入回來還要收得到，不然每次過期都要重開一次。

「取消這台」可以不檢查是誰的：endpoint 只有那個瀏覽器自己拿得到，拿得出來就代表人在那台電腦前面。 「刪我其他電腦」就一定要限自己的。

4.4 推的時機：寫進資料庫、commit 之後​

  • 寫通知的地方通常不只一個（事件、排程、報表⋯），掛在資料表的寫入上（ORM 的 after_flush 收、after_commit 推）比每個呼叫端各加一行可靠，之後新加的通知也不會漏
  • rollback 的不要推：推出去收不回來
  • 推播服務可能很慢：丟到背景執行緒，不要卡住原本的請求
  • 掛勾要放在「寫通知一定會載入」的模組（例如 model 所在的檔案）。放在另一個套件裡的話，沒有 import 那個套件的腳本寫的通知會默默沒推 —— 實測踩過

4.5 Service Worker 那一端​

self.addEventListener('push', (event) => {
  const data = event.data ? event.data.json() : {};
  // 每一則都要跳出東西：訂閱時答應了 userVisibleOnly，不跳的話 Chrome 會自己補一則「網站在背景更新了」
  event.waitUntil(self.registration.showNotification(data.title, {
    body: data.body, icon: '/icon-192.png', tag: data.tag, data: { url: data.url },
  }));
});

self.addEventListener('notificationclick', (event) => {
  event.notification.close();
  const target = new URL(event.notification.data?.url || '/', self.location.origin).href;
  event.waitUntil(clients.matchAll({ type: 'window', includeUncontrolled: true }).then((list) => {
    const same = list.find((c) => c.url === target);
    // 已經開著那一頁就切過去；沒有就開新分頁 —— 不要把使用者正在用的分頁導走（他可能填表填到一半）
    return same ? same.focus() : clients.openWindow(target);
  }));
});
  • tag 用通知的 id：推播服務重送時只會留一則
  • 推的時候設 TTL（例如一天）：電腦關機一週，開機時跳出一整排舊通知沒有意義
  • Notification.requestPermission() 只能在使用者按下按鈕的那一下叫，頁面一載入就問會被瀏覽器擋、使用者也會直接封鎖

4.6 打開時送一則測試通知​

網頁判斷得出來的只有前半段，後半段要問使用者：

哪一段網頁看得到嗎
網站准不准（Notification.permission）看得到
訂閱成功沒看得到
伺服器推不推得到推播服務看得到（推播服務回 201）
這個瀏覽器收到了沒看得到：Service Worker 收到後 client.postMessage() 回報開著的網頁
作業系統有沒有真的顯示看不到：Windows 關掉瀏覽器通知、勿擾開著時，showNotification() 照樣成功
瀏覽器關掉後還收不收得到看不到：只能照瀏覽器種類提醒（Firefox 一定不行、Chrome／Edge 要開背景執行、Mac 不能 ⌘Q）

做法：打開開關後伺服器推一則帶 test_id 的測試通知（不寫進站內通知），Service Worker 收到後回報同一個 test_id， 網頁等十幾秒。收到了就問「有跳出來嗎？」—— 照 navigator.userAgent 講他那台電腦（Windows 問「右下角」、Mac 問「右上角」， 不要寫成「右下角（Mac 是右上角）」讓人自己對）。按「沒有」時同樣照他那台電腦、那個瀏覽器，照 §3 的順序列： 先叫他打開通知中心看那一則在不在（在＝勿擾／專注模式），再列 §2 的設定。實測 Mac 被專注模式擋住時，設定那幾頁全部正確 —— 只列設定的話，使用者看完會以為設定都對、是網站壞了。 等不到就是網路那一段的問題（公司防火牆擋了推播服務很常見），直接講、不要問。 先開始聽 message 再呼叫 API：推播服務很快的時候，回報會比 API 的回應還早到。

4.7 測試​

  • 單元測試：把送出去的 HTTP 請求攔下來，用「瀏覽器那一端」的私鑰解密（http_ece），確認內容與 VAPID 的 aud
  • 真的推一次：Playwright 用 channel: 'chrome'（裝在電腦上的 Google Chrome）＋ permissions: ['notifications']。 內建的 Chromium 實測訂閱失敗（AbortError: Registration failed - permission denied，同 §2.3）。收到了沒用 (await navigator.serviceWorker.ready).getNotifications() 看
  • 關掉分頁再推一次，確認 Service Worker 收得到；登出後確認後端與瀏覽器的訂閱都沒了
