DooD 的沙箱：讓容器摸得到 docker，卻摸不到宿主

接續〈用開發容器當控制面直接管理宿主 Docker（DooD）〉。那篇教你把 socket 掛進 容器；這篇處理它留下的洞。容器本身的硬化參數（cap_drop、資源上限…）另見 〈docker run 沙箱參數〉／〈Compose 版〉—— 但請先讀完本篇 §1：socket 開著時那些參數形同虛設。

目標讀者：在容器裡跑開發環境（尤其是跑 AI agent）、又需要讓它自己起停應用疊的人。

適用前提：單機、同一顆 Docker daemon。真正的隔離要一個專案一顆 daemon，代價在 §7。

範例占位符（與前一篇一致，請自行代換）：

  • dev：開發容器（控制面）；dood-proxy：本篇要加的代理容器
  • ${PROJECT_DIR}：專案在宿主上的絕對路徑，例如 /Users/me/myapp
  • myapp：開發容器與代理所在的 compose 專案名（＝租戶名）
  • myapp-infra／myapp-net：沙箱裝好之前就存在的資料庫疊與它的網路

目錄：§0 總結｜§1 洞有多大｜§2 兩層防線｜§3 怎麼設定範圍｜§4 代理裡面怎麼判斷｜ §5 為什麼得自己寫｜§6 驗證｜§7 沒防到什麼｜§8 一頁速查

0. 一句話總結​

開發容器不掛真 socket，改連一個會檢查內容的代理；宿主那邊把 Docker 的共享目錄縮到只剩專案。 兩層合起來的效果：容器仍能 build／起停／exec 自己的東西，但掛不走專案目錄以外的檔案， 也看不到別的專案。

做完你會有三樣東西：

  1. Docker Desktop 的 File sharing 清單只剩 ~/workspace 這類根目錄（一次性設定）。
  2. 一個 dood-proxy sidecar（Go 標準庫、約 1200 行、FROM scratch 9MB），開發容器的 DOCKER_HOST 指向它開的 socket。
  3. 一份 .env，用三個旋鈕明列容器能碰的檔案、物件、網路範圍（§3）。

1. 先看清洞有多大​

-v /var/run/docker.sock:/var/run/docker.sock 的意思不是「容器可以用 docker」， 而是容器可以叫宿主的 daemon 做任何事。在容器內：

# 把宿主家目錄掛進另一個容器，讀走私鑰、shell 歷史、keychain
docker run --rm -v /Users/you:/h:ro alpine cat /h/.ssh/id_rsa

# 讀別的專案容器 env 裡的明文祕密（DB 密碼、tunnel token、API key）
docker inspect other_project_container

# 特權容器 ＝ 整台機器
docker run --rm --privileged -v /:/host alpine chroot /host sh

實測（macOS Docker Desktop）：-v /Users/<you>:/h:ro 讀得到 ~/.ssh、~/.gnupg、 ~/.zsh_history、~/Library/Keychains；-v /:/vm:ro 拿得到整個 Docker Desktop VM 的根目錄， 而 macOS 分享給 Docker 的檔案全部掛在那顆 VM 的 /host_mnt 底下——所以就算開發容器本身 只被掛了一個專案目錄，也能這樣越過去：

# 唯讀 PoC：掛 VM 根目錄，再從 /host_mnt 走到 macOS 家目錄
docker run --rm -v /:/hostroot:ro alpine ls /hostroot/host_mnt/Users/<you>/

只有 Desktop、Documents、Downloads 被 macOS 的 TCC 擋下——那是 Docker Desktop 沒拿到隱私授權 的副作用，別為了方便給它 Full Disk Access。

三個常被誤以為「有防到」的東西：

  • cap_drop: ALL、no-new-privileges、read_only 在 socket 開著時形同虛設。 你關掉的是 capability，但開了一個比 capability 大得多的後門。
  • 容器改用非 root 使用者跑也一樣。socket 在 VM 裡是 root:root 0660，DooD 教學裡那行 group_add: ["0"] 做的正是把 gid 0 補給 uid 1000——上面每一條都以一般使用者身分執行， 不需要提權、不需要任何 CVE。稽核時看到 id 印出 groups=…,0(root) 而且 test -w /var/run/docker.sock 成立，就等於看到了宿主 root。
  • 「我只掛了專案目錄」也一樣。掛進來的是專案目錄沒錯，但 socket 那頭的 daemon 什麼都 能掛——上面的 /host_mnt PoC 就是這條路。

為什麼現在比以前重要​

以前這是「本機開發、可接受的風險」。現在容器裡跑的可能是一個會自己下指令的 agent， 或某個相依套件的 postinstall 腳本。風險不再只來自你自己手滑。

2. 兩層防線​

一層擋不住，兩層合起來才是圍牆。

層擋什麼在哪強制繞得過嗎
一：收窄 Docker Desktop 的共享目錄宿主檔案Docker 之外（Desktop／VM 的檔案分享層）繞不過
二：過濾式 socket 代理docker API 呼叫你自己的代理行程能改代理設定的人可以

第一層：收窄共享根目錄（一次性，最划算）​

Docker Desktop → Settings → Resources → File sharing → 把清單縮到只剩放專案的目錄 （例如 /Users/you/workspace）→ Apply & restart。

之後任何容器要掛範圍外的路徑，會在建立容器時就被擋下：

Error response from daemon: mounts denied:
The path /Users/you/.ssh is not shared from the host and is not known to Docker.

代價：原本「掛宿主單一設定檔」的用法會失效，例如 - ~/.gitconfig:/home/node/.gitconfig:ro。 改成啟動腳本複製一份進容器的持久化家目錄即可（複製一次，之後兩邊各自獨立）。

Linux 宿主沒有這個分享層（bind mount 直接對應真實檔案系統），所以第一層在 Linux 上 不存在——那邊要靠第二層加上 rootless daemon 或 Sysbox（§7）。

第二層：過濾式 socket 代理​

開發容器不掛真 socket，改連一個代理開出來的 unix socket：

dev ──DOCKER_HOST=unix:///run/dood/docker.sock──▶ dood-proxy ──真 socket──▶ 宿主 daemon
                                                  （只有它摸得到真 socket）

compose 大致長這樣（共用一個 volume 傳遞 socket 檔）：

services:
  dev:
    environment:
      DOCKER_HOST: unix:///run/dood/docker.sock
    volumes:
      - dood-sock:/run/dood          # ← 不是 /var/run/docker.sock
    depends_on: [dood-proxy]
    security_opt: ["no-new-privileges:true"]

  dood-proxy:
    build: ./docker/proxy
    read_only: true
    cap_drop: [ALL]
    # uid 0 才讀得到宿主 socket；gid 設成開發容器的 gid，過濾 socket 才不必靠 chown
    #（cap_drop: ALL 之後沒有 CAP_CHOWN）就能讓 uid 1000 連得上
    user: "0:1000"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock   # 真 socket 到此為止
      - dood-sock:/run/dood
    environment:
      DOOD_TENANT: myapp
      DOOD_ALLOWED_BIND_ROOTS: ${PROJECT_DIR}
      DOOD_SELF_CONTAINER: myapp_dev

volumes:
  dood-sock:

這裡只填了三個最基本的值。其餘旋鈕（舊疊要不要認領、既有網路要不要借用）在 §3。

💡 一條 symlink 省掉改程式碼：docker CLI 吃 DOCKER_HOST，但語言 SDK（Go 的 bollard、 Python 的 docker-py…）多半把 /var/run/docker.sock 寫死。在映像裡做 ln -sf /run/dood/docker.sock /var/run/docker.sock，那些客戶端就自動走代理。

🛡️ 代理設定目錄要唯讀掛進容器。容器內的程式若能改 compose 或代理規則，等你在宿主 重建時就以你的權限生效了。唯讀＝「可讀、可提議，不可自行套用」；重建前看一眼 git diff。

3. 怎麼設定範圍：實際要填的東西​

前兩節講「牆怎麼蓋」，這一節講「門開多大」。範圍只有三種——檔案、物件、網路—— 各由一個旋鈕決定，全部放在 compose 檔旁邊的 .env，改完只要重建代理容器 （docker compose up -d dood-proxy），開發容器不必動、裡面跑的東西不會斷。

旋鈕總表​

範圍旋鈕預設決定什麼
租戶名DOOD_TENANTcompose 專案名透過代理新建的容器／網路／volume 都蓋這個標籤；不同租戶互相看不到
檔案DOOD_ALLOWED_BIND_ROOTS（要多開用 DOOD_EXTRA_BIND_ROOTS）專案目錄＋環境目錄子容器 -v 能掛的宿主根目錄；不在裡面一律拒
物件DOOD_OWNED_PROJECTS空沙箱裝好之前就存在、沒有標籤的 compose 疊：整疊視同自己的（可 inspect／exec／stop／rm）
網路DOOD_SHARED_NETWORKS空沒有標籤的既有網路：可用不可刪——可 inspect、建子容器時指定、connect；delete／prune 仍拒
自己DOOD_SELF_CONTAINER開發容器名對「自己」只放行兩件事：唯讀 inspect、把自己接上租戶／共用網路
埠DOOD_FORCE_LOCALHOST_PORTS1publish 的埠改綁 127.0.0.1，不暴露到區網
外送DOOD_ALLOW_IMAGE_PUSH0docker push
稽核DOOD_LOG_ALL1每個放行／拒絕記一行到代理 log

兩個原則：

  • 透過代理建出來的東西不用設定，標籤是自動蓋的。要手動列的只有「沙箱之前就有的」。
  • 範圍是明列，不是猜。旋鈕留空＝那一類完全不放行；代理不會因為「看起來像你的」就通融。

一個具體例子​

專案 myapp，開發容器與代理在 compose 專案 myapp；資料庫早就用另一個 compose 專案 myapp-infra 起好，網路叫 myapp-net。容器內跑的工具要做三件事：掛專案目錄、在 myapp-net 上起一顆 psql 子容器去灌資料、在自己建的內部網路上起一顆 RPC 容器再用容器名連它。

# .env（compose 旁）
DOOD_TENANT=myapp
DOOD_ALLOWED_BIND_ROOTS=/Users/me/myapp
DOOD_SELF_CONTAINER=myapp_dev

# 資料庫那疊是沙箱之前起的：二選一
DOOD_OWNED_PROJECTS=myapp-infra    # 整疊認領：容器內能 inspect/exec/stop 那些 DB 容器
DOOD_SHARED_NETWORKS=myapp-net     # 只借路：能在 myapp-net 上起子容器、用名字連 DB，碰不到 DB 容器本身

怎麼選：那疊裡若有你不想讓容器內程式碰到的東西（tunnel token 容器、反向代理）， 用 SHARED_NETWORKS 只借網路；那疊就是純資料庫、你本來就會從容器內 docker start 它們，用 OWNED_PROJECTS。兩個同時設也行，語意是聯集。

第三件事（自建內部網路＋RPC 容器）不用設定：網路是代理建的、自動有標籤； 開發容器把自己接上去走「自我掛網」規則（§4），也是自動放行。

⚠️ 自己那疊不要認領。 DOOD_OWNED_PROJECTS=myapp 會讓容器內的程式能 stop／rm 掉開發容器與代理本身——圍牆從裡面就拆得掉。

被擋了怎麼對到旋鈕​

代理的每個拒絕都會說明原因，照訊息找旋鈕：

訊息長這樣動哪個旋鈕
bind 來源不在允許的根目錄內（允許：…）DOOD_EXTRA_BIND_ROOTS 加那個宿主目錄
containers "db"（myapp-infra）不屬於租戶 myapp真是你的 → DOOD_OWNED_PROJECTS=myapp-infra；否則就是租戶隔離在做事
NetworkMode 指向不屬於本租戶的網路 / 要接的網路不屬於本租戶DOOD_SHARED_NETWORKS 加那條網路名（或認領它所屬的專案）
networks "myapp-net"…不屬於租戶，而你在做 network rm不放行是對的：共用網路只能用不能刪，要刪去宿主刪
服務起來了卻一直「沒健康」、代理 log 有 network connect 被拒開發容器自我掛網被舊版代理擋下；升級到有自我掛網規則的代理。client 那邊記得把 403 拿去 inspect 驗成員（§4）

看不出被擋在哪：docker compose logs dood-proxy（DOOD_LOG_ALL=1 時每個呼叫一行）。

4. 代理裡面怎麼判斷​

這是本篇的核心。只過濾 method＋path 是不夠的——這也是現成方案的極限（§5）。 代理做三件事。

(1) 預設拒絕的路由表​

只放行開發真的需要的端點：/version、/info、/containers/*、/images/*、/build、 /networks/*、/volumes/*、BuildKit 的 /session。其餘一律擋，包括：

擋掉的為什麼
/swarm、/services、/nodes、/secrets、/configs、/plugins叢集與外掛管理，開發沙箱用不到
/system/df會把全機所有映像／volume／容器的用量攤開＝跨專案清冊
/*/prune會掃到別的專案的容器／映像／volume
/images/get、/images/{name}/push把任何映像整包匯出或送出這台機器＝資料外送路徑

預設拒絕的好處：新版 docker 加了端點不會自動變成洞。代價是偶爾要為新用法補規則—— 拒絕訊息直接印出被擋的路徑，補起來很快。

(2) 租戶隔離：讓別的專案「不存在」​

代理建出來的每個容器／網路／volume 都蓋上標籤 dood.tenant=<租戶>。之後：

  • 任何針對既有物件的操作（inspect／exec／logs／stop／rm／cp）都先查標籤，不是自己的就擋。
  • list 類端點（/containers/json、/networks、/volumes）改成「先向上游取得、 再依標籤過濾才回傳」——別的專案在容器眼中不是不能碰，是看不到。
  • /events 注入租戶 label filter，事件流也只看得到自己的。

這一點是「method＋path 型代理」做不到的：list 與 inspect 天生全域，要收斂只能改回應。

沙箱之前就存在的東西怎麼算。 標籤是代理蓋的，所以沙箱裝好之前就存在的物件都沒有標籤： 宿主 compose 建的網路、早就起好的資料庫容器、還有開發容器「自己」。預設它們全是「別人的」， 這正是租戶隔離該有的樣子，靠 §3 的兩個旋鈕明列例外：認領整疊（OWNED_PROJECTS）或只借 網路（SHARED_NETWORKS，可用不可刪）。

「自己」是第三種身分。 開發容器既不在租戶內（它屬於外層那疊），又不是陌生人。 代理對它只放行兩件事：唯讀 inspect（控制腳本靠它認出自己是誰），以及把自己接上 租戶／共用網路（network connect/disconnect）。後者是「引擎在租戶內部網路上起一顆 RPC 容器、再用容器名連它」這類用法的必要條件；接上一條 bridge 網路拿不到檔案、拿不到別人的 容器，所以不會多出宿主存取。self 其他的動作（stop／rm／exec／改設定）維持只讀。

(3) 建立請求的內容檢查​

路由表只能回答「這個端點能不能碰」，擋不住「端點合法、內容是逃逸」—— POST /containers/create 的 body 裡一行 Binds: ["/Users/you:/h"] 就把家目錄掛進新容器了。 所以建立類請求的 body 要拆開看：

欄位規則
Binds / Mounts[].Source宿主路徑必須落在白名單根目錄內；具名 volume 必須屬於本租戶
Privileged、CapAdd、Devices、DeviceRequests、Sysctls一律拒絕
PidMode／IpcMode／UTSMode／UsernsMode／NetworkMode ＝ host拒絕（container:X 要驗 X 的歸屬；具名網路要是租戶的或共用的）
SecurityOpt只收 no-new-privileges（seccomp=unconfined 等於把預設防護關掉）
MaskedPaths／ReadonlyPaths不允許覆寫（覆寫的用途就是打開 /proc/kcore 這類路徑）
Runtime只收 runc
VolumesFrom拒絕（會繼承別的容器的掛載）
LogConfig.Type只收 json-file／local／none（syslog 之類可指定宿主路徑或外部位址）
volume 的 DriverOpts一律拒絕——type=none,device=/,o=bind 就是官方版的「把 / 掛進來」
network 的 Driver只收 bridge／none（macvlan／ipvlan 會直接接上宿主實體網路）
Mounts[].BindOptions.Propagation拒絕 shared／rshared（掛載會傳播回宿主）

順手可以做的兩件事，值得預設開啟：

  • publish 的埠強制綁 127.0.0.1：-p 5432:5432 預設是 0.0.0.0，開發用的資料庫會 出現在你所在的整個區網（咖啡廳 wifi 也算）。順帶把 -P（PublishAllPorts）關掉。
  • 禁 docker push：映像離開這台機器是資料外送路徑之一。要用再開。

⚠️ 改寫 body 要用 map 而不是結構體。用強型別結構體反序列化再序列化，會把 CLI 送來、 但你沒宣告的欄位悄悄丟掉——那等於竄改使用者的請求，而且會隨 docker 版本演進默默壞掉。 只讀寫你認得的欄位，其餘原樣保留。

四個一定會踩的坑​

全部是實際撞到才知道的，改規則時回頭看一遍：

  1. 「查無此物」要放行，讓上游自己回 404。docker compose up 的第一步就是 inspect 網路／volume 看它在不在，代理若回 403，compose 會以為是權限問題而中止， 永遠走不到「那就建一個」那一步。
  2. 具名 volume 若不存在，要由代理代建並蓋標籤。docker run -v somename:/data 在 volume 不存在時，daemon 會自動建一個——那個沒有標籤，之後就變成「自己建的東西 自己碰不到」。
  3. DELETE /containers/{id} 的路徑長度跟 /containers/json 一樣是 2。把「長度 2」 一律當成集合端點來路由，compose down 就會停在「容器刪不掉」。
  4. 拒絕自我掛網時，client 會把它當成功。daemon 對「已經接在這條網路上」回的也是 403， 很多 client 把 403 一律當「已接上、冪等成功」——於是拒絕被靜靜吞掉，30 秒後只剩一句 「服務一直沒健康」，真因完全不在畫面上。實際踩到的樣子：一套引擎在租戶內部網路起了 RPC 容器、要把開發容器接上去被舊規則擋下，整條流程看起來像「容器起不來」。 代理的拒絕訊息要說人話，client 收到 403 要去 inspect 網路驗自己在不在成員裡。

5. 為什麼多半得自己寫​

現成的 socket proxy（Tecnativa、wollomatic、CetusGuard 都還在維護）都是 method＋path 白名單：一旦放行 POST /containers/create，就擋不住 body 裡的 -v /Users。唯一做過 bind 白名單與租戶標籤的 sockguard 已在 2021 封存。 OPA 的 authz plugin 看得到 body，但作用在整個 daemon、分不出是哪個專案在呼叫。

好消息是這東西不大：Go 標準庫、無外部相依、約 1200 行含測試。實作要點：

  • 不要用 net/http 的 Server／ReverseProxy。docker 的 attach／exec／BuildKit session 會把連線升級成雙向裸串流，自己拿兩顆 net.Conn 接起來最單純。
  • 雙向管道要等兩個方向都結束。只等其中一個的話，docker exec（沒有 stdin）會在上行 立刻 EOF 時把整條連線關掉，指令看起來「沒有輸出」。上行結束只做半關（CloseWrite）。
  • 裸串流回應只能手寫標頭再接管道。resp.Write() 會一路把 body 抄到 EOF，而裸串流沒有 EOF，另一個方向（stdin）就永遠等不到人送。
  • 映像用 FROM scratch ＋ 靜態二進位（約 9MB）：沒有 shell 可被利用。

6. 驗證：自己攻自己​

規則寫了不等於有效。三層驗證，缺一不可：

單元測試（規則邏輯，跑得快）——把它放進映像 build 的 RUN 裡，規則寫壞 build 直接失敗：

RUN go vet ./... && go test ./... && CGO_ENABLED=0 go build -o /out/dood-proxy .

實機煙霧測試（整條路：CLI → 代理 → daemon）。單元測試涵蓋不到 attach／exec 這種 會升級成裸串流的端點，而那正是最容易寫壞的部分。至少要測到：

# 該擋
docker run --rm -v $HOME:/h alpine true          # 掛宿主家目錄
docker run --rm -v /:/host alpine true           # 掛整顆根目錄
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock alpine true   # 把 socket 傳給子容器
docker run --rm --privileged alpine true
docker run --rm --network host alpine true
docker volume create --driver local --opt type=none --opt device=/ --opt o=bind escape
docker inspect <別的專案的容器>
docker system df
docker network rm <DOOD_SHARED_NETWORKS 裡的網路>   # 共用網路可用不可刪

# 該過（少了這半邊，你只是做了一個不能用的沙箱）
docker run --rm -v <白名單內的目錄>:/w alpine ls /w
docker run -d --name x alpine sleep 60 && docker exec x echo hi   # ← 裸串流路徑
docker build -t t:1 .                                             # ← BuildKit session
docker compose up -d && docker compose down -v                    # ← 整個生命週期
docker run --rm --network <共用網路> alpine true                   # ← 借路
docker network connect <租戶網路> <開發容器自己>                    # ← 自我掛網

最後兩組是本篇後來才補的：巢狀 compose 的完整生命週期（建網路 → 建 volume → 起容器 → 移除）是日常真正走的路，§4 的前三個坑全是它測出來的；共用網路與自我掛網則是把「既有 基礎設施」接上沙箱時一定會用到的兩條路，少了它們沙箱只能玩全新的疊。

身分抽查（修補後最便宜的一眼）：

id                                   # 不該再有 0(root)：走代理後根本不需要 group_add
ls -l /var/run/docker.sock           # 不存在，或是指向 /run/dood/docker.sock 的 symlink
docker run --rm -v /:/hostroot:ro alpine ls /hostroot/host_mnt   # 該被代理擋下

逃逸抽查：在控制腳本裡放一個 check 動詞，實際嘗試幾種逃逸並判讀結果。要能分辨三種 情況：被代理擋下（好）、真的成功（洞）、連不到代理（設定壞了，不是洞，但也不能算通過）。 把後者誤報成「有洞」比不報還糟。

7. 沒防到什麼​

寫清楚比寫漂亮重要。這套不是牢房：

  • 白名單是字面比對。代理看不到宿主檔案系統，解析不了 symlink——白名單目錄裡若有一條 指向外面的 symlink，核心會跟隨它。這就是第一層仍然必要的原因。
  • kernel 是共用的。容器逃逸漏洞不在守備範圍。
  • host.docker.internal 仍連得到宿主上的服務。要斷就拿掉 extra_hosts。
  • 共用網路上的其他人。DOOD_SHARED_NETWORKS 借出去的是「路」：容器內的程式連得到那條 網路上的每一個服務（這就是借路的目的），只是 inspect／exec 不到它們的容器。放上去的 服務自己要有認證。
  • 能改代理設定的人＝能拆牆的人。容器內的程式若改了 compose，等你在宿主重建時就以 你的權限生效了——重建前看一眼 git diff。把環境設定目錄唯讀掛進容器， 正是為了「可讀、可提議，不可自行套用」。
  • 機密別放在會被掛進容器的目錄裡。tunnel token 這類東西要用 --token-file 之類的 方式指到掛載範圍之外的檔案；以環境變數注入的話，docker inspect 就明文可讀 （不過租戶隔離已經讓容器 inspect 不到同疊的其他容器）。

真隔離：一個專案一顆 daemon​

  • Linux：rootless dockerd（每專案一個 socket），或 Sysbox runtime 讓容器內跑真的 dockerd。
  • macOS：Colima／Lima 開第二顆 VM，各專案 DOCKER_HOST 指自己的 daemon，互相完全不可見。
  • DinD sidecar（兩個平台都行）：旁邊起一顆 docker:dind 當內層 daemon，開發容器用 DOCKER_HOST=tcp://dind:2375 只連得到它，子容器全跑在內層、碰不到宿主。代價：dind 那顆 要 privileged（它是唯一碰宿主的東西，裡面不跑你的程式碼）、巢狀儲存層較慢、映像快取 與宿主分家。Sysbox 是更乾淨的替代，但不支援 Docker Desktop for Mac。

代價是映像快取雙份 ＋ 多一顆 VM 的記憶體。單機資源緊的時候先掂量——一顆吃 24GB 的開發 容器旁邊再開一顆 VM，32GB 的機器塞不下。

順帶更正一個常見說法：「socket proxy 只能縮能力、給不了隱形」。那對 method＋path 型的 代理成立，但會過濾回應的代理可以給隱形——list 端點的回應改掉，別的專案就真的不在 容器的視野裡。要注意的是這仍不是租戶邊界，而是視野邊界：標籤是代理自己蓋的， 代理本身被繞過（例如真 socket 又被掛回去）就一起失效。

8. 一頁速查​

洞：-v /var/run/docker.sock ≈ 交出宿主 root
    → -v /Users/you:/h 讀走私鑰；docker inspect 讀走別人的祕密；--privileged 拿整台機器
    → -v /:/hostroot 再走 /host_mnt/Users/<you> ＝ 越過「只掛了專案目錄」的假象
    → cap_drop / no-new-privileges / read_only / 非 root user 在 socket 開著時形同虛設

兩層：
  1) Docker Desktop 共享目錄縮到只剩專案目錄（Docker 之外強制，繞不過）
  2) 過濾式 socket 代理（開發容器改連它，真 socket 只有代理摸得到）

範圍三旋鈕（.env，改完只重建代理）：
  檔案 ALLOWED/EXTRA_BIND_ROOTS ／ 物件 OWNED_PROJECTS（整疊）／ 網路 SHARED_NETWORKS（可用不可刪）
  透過代理建的東西自動蓋標籤，不用列；留空＝不放行；自己那疊不要認領
  「自己」＝第三種身分：只准唯讀 inspect ＋ 自我掛網

代理三件事：
  a) 預設拒絕的路由表        → 新版 docker 加端點不會自動變成洞
  b) 租戶標籤 ＋ 回應過濾     → 別的專案「看不到」，不只是「不能碰」
  c) 建立請求的 body 檢查     → bind 白名單、禁 privileged/cap-add/host ns/volume DriverOpts

四個一定會踩的坑：
  - 物件不存在要放行（回 404），否則 compose up 走不到「那就建一個」
  - 具名 volume 不存在要代建並蓋標籤，否則 daemon 建出沒歸屬的
  - DELETE /containers/{id} 的路徑長度也是 2，別當成集合端點
  - 自我掛網被拒時 client 會當成功（daemon 的「已接上」也是 403）：拒絕要說人話，client 要 inspect 驗成員

驗證：build 時跑單元測試 ＋ 實機煙霧測試（含巢狀 compose 全生命週期、借路、自我掛網）＋ check 動詞抽查
     判讀要分辨「被擋」「真的成功」「連不到代理」三種

沒防到：symlink（所以第一層必要）、kernel、host.docker.internal、共用網路上的服務、能改設定的人
真隔離：一專案一顆 daemon（rootless / Sysbox / Colima 第二顆 VM / DinD sidecar），代價是記憶體與快取雙份
修補後一眼：id 不該再有 0(root)；/var/run/docker.sock 不存在或只是指向代理的 symlink
