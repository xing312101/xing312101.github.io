網頁：讓 agent 用 Playwright 操作瀏覽器

1. 安裝​

npm install -D playwright
npx playwright install chromium         # 要測 Safari 引擎再加 webkit、Firefox 加 firefox

Python 版：pip install playwright && playwright install chromium，API 幾乎一樣。

2. 只登入一次​

讓人在有畫面的瀏覽器登入一次，把登入狀態存起來，之後的腳本直接帶著用，agent 不必碰密碼：

// login.mjs：node login.mjs，登入完回到終端機按 Enter
import { chromium } from 'playwright';
const browser = await chromium.launch({ headless: false });
const context = await browser.newContext();
const page = await context.newPage();
await page.goto('https://app.example.com/login');
await new Promise(r => process.stdin.once('data', r));
await context.storageState({ path: 'auth.json' });
await browser.close();
warning

auth.json 等於登入憑證：放在版控之外、用完刪掉。

3. 檢查腳本的骨架​

重點是順便收集錯誤：畫面看起來正常，背後可能有 JS 例外或 500。

// check.mjs：node check.mjs
import { chromium } from 'playwright';
const browser = await chromium.launch();
const context = await browser.newContext({ storageState: 'auth.json', viewport: { width: 1440, height: 900 } });
const page = await context.newPage();

const problems = [];
page.on('pageerror', e => problems.push(`JS 錯誤：${e.message}`));
page.on('console', m => m.type() === 'error' && problems.push(`console：${m.text()}`));
page.on('response', r => r.status() >= 400 && problems.push(`${r.status()} ${r.url()}`));

await page.goto('https://app.example.com/orders');
await page.getByRole('button', { name: '新增' }).click();
await page.getByLabel('名稱').fill('測試資料');

// 存檔：先掛好等待，再按
const saved = page.waitForResponse(r => r.url().includes('/api/orders') && r.request().method() === 'POST');
await page.getByRole('button', { name: '儲存' }).click();
console.log('儲存回應：', (await saved).status());

await page.screenshot({ path: 'after-save.png', fullPage: true });
console.log('問題：', problems);
await browser.close();

agent 跑完讀輸出、再讀截圖（圖片檔它看得懂），不對就改腳本再跑。

找元素的順序​

優先寫法說明
1getByRole('button', { name: '儲存' })跟使用者看到的一致，改樣式不會壞
2getByLabel('名稱')、getByPlaceholder(...)表單欄位
3getByTestId('order-row')畫面上沒有可辨識文字時，在程式裡加 data-testid
最後CSS 選擇器改版就壞

4. 常用操作​

要做的事寫法
手機尺寸browser.newContext({ ...devices['iPhone 13'] })（import { devices } from 'playwright'）
上傳檔案await page.locator('input[type=file]').setInputFiles('a.pdf')
下載const d = page.waitForEvent('download'); await click; await (await d).saveAs('out.xlsx')
確認對話框page.once('dialog', d => d.accept())（要在觸發前掛）
只截一塊await page.getByTestId('report').screenshot({ path: 'r.png' })
看列印版面await page.emulateMedia({ media: 'print' }) 再截圖；page.pdf({ path: 'p.pdf', format: 'A4' })（只有 Chromium）
攔截 API 回應await page.route('**/api/orders', r => r.fulfill({ status: 500 }))：測錯誤畫面

5. Playwright MCP：讓 agent 自己探索​

不想先寫腳本時，把 Playwright 包成 agent 的工具。agent 拿到的是頁面的無障礙樹（文字結構）， 不用靠截圖猜座標：

claude mcp add playwright npx @playwright/mcp@latest
腳本MCP
適合驗收、回歸、一次檢查很多項第一次看陌生頁面、找問題在哪
重跑一行指令要再叫 agent 走一次
token少（只讀輸出）多（每一步都回傳頁面內容）

常見做法：先用 MCP 摸清楚流程，再請 agent 把流程寫成腳本留著重跑。

6. 常見坑​

  • 受控元件：勾選框、開關要等存檔回來才變，check()／uncheck() 會誤判「沒變」。改成 click()，等回應，再讀狀態
  • 名稱互相包含：getByLabel('名稱') 也會比對到「英文名稱」，加 { exact: true }
  • 按了沒反應：先看 problems 裡有沒有 4xx／5xx，再懷疑選擇器
  • 模擬手機尺寸 ≠ 手機：viewport 換了，但引擎還是桌面版；WebKit 也不等於 iOS Safari。 App 內建瀏覽器、相機、列印要到模擬器或實機
  • headless 跟有畫面的結果不同時，用 headless: false 看一次
