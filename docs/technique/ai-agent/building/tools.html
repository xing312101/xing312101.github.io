工具與跑指令

接在 OS 沙盒之後。工具本身的設計也是安全的一部分：改錯地方、卡住、留下背景程序、把金鑰寫進紀錄，都是工具的問題，不是模型的問題。

1. 工具清單​

工具做什麼守門
read讀檔，可以指定行的範圍；大檔分段讀路徑在可讀範圍內（先取實際路徑）；機密檔擋
list列目錄、glob同上；指向外面的 symlink 不跟進去
search用 ripgrep 搜內容一律排除機密檔；只搜可讀範圍；結果有上限
edit字串取代，舊字串必須只出現一次路徑在可寫範圍內；先秀 diff；讀過之後檔案被改過就拒絕
write建新檔或整個覆寫同上；覆寫前必須先讀過，不准盲寫
bash跑指令乾淨的環境、逾時、輸出截斷、在沙盒裡跑、過權限規則
  • edit 的舊字串必須剛好出現一次：出現好幾次時不猜是哪一個，回一個寫給模型看的錯誤（「出現 3 次，請多帶幾行」）。
  • 讀過之後檔案被改過就拒絕（使用者同時在 IDE 裡改、或 bash 改了），要求重讀：不然模型拿舊的內容去改，會蓋掉別人的修改。
  • 只讀的工具可以同時跑，會改東西的照順序跑，bash 一律不跟其他工具同時跑：bash 可以在別的工具檢查完、打開之前把檔案換成 symlink（OS 沙盒 §4）。

2. bash：乾淨的環境​

  • 環境變數用白名單：只留 PATH、HOME、LANG、TERM、TMPDIR。工具鏈需要的（JAVA_HOME、ANDROID_HOME）由使用者在設定裡加。 用黑名單的話，總有一個沒列到的 *_TOKEN。
  • 不繼承任何金鑰，包括 agent 自己讀的那幾個：echo $ANTHROPIC_API_KEY、echo $MYAGENT_ANTHROPIC_API_KEY 都印不出東西。 用的是第三方或自建的模型服務時，印進對話的金鑰就送出去了。
  • 沙盒自己加的變數不能拿掉（proxy 的設定、JAVA_TOOL_OPTIONS）：先做乾淨的環境，再交給沙盒加上它的。順序反過來的話，網域詢問和 Gradle 的網路都會失效。
  • 不等輸入：stdin 接 /dev/null，設 GIT_TERMINAL_PROMPT=0。不然等輸入的指令會一直卡到逾時。
  • 工作目錄：每次都從專案根目錄開始，指令裡的 cd 只影響那一次。
  • 逾時：預設 2 分鐘，模型可以自己指定（有上限，例如 10 分鐘）。時間到就砍掉整個行程群組。
  • 輸出截斷：stdout、stderr 合在一起；超過上限（例如 30 KB 或 400 行），只給模型開頭和結尾，加上完整輸出的檔案路徑（權限 600）。 npm install 的 log 動輒幾千行，全部塞進上下文又貴又沒用。

3. 不留下程序​

agent 跑的指令會開背景程序（開發伺服器、gradle daemon、watch）。agent 結束時它們要一起結束：

  • 每個指令自己一個行程群組。主程式結束後，留下來的背景程序整組結束；逾時、中斷時也是整組。
  • 結束時收乾淨：還在跑的指令、MCP server、沙盒程式庫自己開的輔助程序（Linux 的 socat、macOS 的 log stream）。 收到 SIGTERM、SIGHUP（關掉終端機、SSH 斷線）時照正常流程收，最多等幾秒。Node 的 exit 事件裡不能等，只能同步送訊號。
  • 主程式被強制結束（SIGKILL、記憶體不足）時沒機會收尾，交給看門狗：一個很小的 shell 程序，stdin 接著主程式、自己一個工作階段（session）。 每開一個程序就向它登記，結束時取消。主程式不管怎麼結束，那條管線都會關；看門狗讀到 EOF，就把還登記著的先 SIGTERM、2 秒後還在就 SIGKILL。 不用定期檢查主程式還在不在。
  • 結束單一程序前先核對名稱：程序編號會被別的程式重複使用。 測試裡找程序也一樣：不要只比「命令列裡有這串數字」—— 別的程式（瀏覽器命令列裡的 uuid）也可能對得上，清理時就把它收掉了。
  • 收不到的要寫出來：自己脫離行程群組的（setsid、會自己轉成常駐程式的指令）。Linux 的 bubblewrap 開新的 PID namespace，指令結束時會一起收掉；macOS 沒有對應的機制。
  • MCP server 不一定守規矩：stdin 關了不結束、不理 SIGTERM、開了子程序就不管。每個 server 自己一個行程群組，連線斷了就整組收掉，下次用到再開新的。

4. 改檔的復原（/undo）​

  • edit、write 改檔前，先把原本的內容存起來（新檔就記「原本不存在」），權限 600。
  • /undo 還原上一輪改過的檔案，可以連續按，回到更早的輪次。
  • 還原前確認檔案在那之後有沒有被改過（使用者在 IDE 裡改、bash 改）。有的話先列出差異、問，不直接蓋掉。
  • 還原時一樣檢查實際路徑、不跟隨 symlink：不然 bash 換上的 symlink 會讓還原寫到工作目錄外面。
  • bash 改到的檔案追蹤不到：每輪結束時用 git status 比對，發現 bash 改了檔案，就提醒「這些改動不能用 /undo 還原」。
  • 只還原檔案，不改對話歷史：附加一則訊息告訴模型復原了哪一輪（為什麼不改歷史：轉接層、上下文與花費 §3）。

5. 對話紀錄與金鑰​

  • 每個 session 一份 JSONL：每則訊息、工具呼叫和結果、權限的決定和原因、花費、錯誤。用來接續、除錯、評測。
  • 裡面有讀過的檔案內容：目錄權限 700、檔案 600；不放進會同步到雲端的資料夾；預設保留 30 天，有指令可以清。
  • 金鑰永遠不寫進紀錄：工具結果送給模型、寫進紀錄或存檔之前，用已知的金鑰格式（sk-ant-、sk-proj-、AIza、ghp_、AKIA⋯）遮掉。 這是機密檔清單沒擋到時（例如程式碼裡寫死的 key）的最後一道防線。
  • 例外：/undo 的快照要能逐 byte 還原，所以原封不動地存，只放在本機。
  • 除錯模式把每次送給 API 的原始請求和回應存下來（金鑰和標頭先遮掉）：快取一直沒命中、歷史檢查回 400 時，比對前後兩次請求就知道哪裡變了。

6. 讀外面來的資料​

  • 外面來的 JSON 不要直接 JSON.parse 之後拿去合併：設定檔、價格表、快取、MCP 的訊息、模型給的工具參數，都可能帶著 __proto__、constructor 這類鍵。 遞迴合併設定時，target['__proto__'] 就是 Object.prototype，改下去整個程式的物件都受影響。統一用一個會丟掉這些鍵的解析函式，用測試擋直接呼叫 JSON.parse。
  • 網路連線只有一個模組能開（抓網頁的工具），位址由權限層檢查：本機位址、內網、雲端 metadata 位址都擋（防 SSRF）。 位址的標準寫法交給 URL、node:net，範圍比對用 net.BlockList，不要自己寫字串比對（0x7f.1、[::ffff:127.0.0.1] 這些寫法都是 127.0.0.1）。
  • 啟動其他程式也只有少數幾個模組能做（工具、權限層、讀金鑰的那一個），開了程序就要向看門狗登記。這些規則都由架構測試守著。
