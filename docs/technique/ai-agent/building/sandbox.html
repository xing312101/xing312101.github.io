OS 沙盒：規則擋不完的交給它

接在權限規則之後。權限規則看的是指令的文字，正規表示式永遠列不完所有危險的寫法。 沙盒換一個角度：不管指令怎麼寫，跑起來的程序只能碰允許的檔案和網域。白名單只是讓使用者少被問幾次，安全邊界是沙盒。

1. 三個平台​

不用自己寫：@anthropic-ai/sandbox-runtime（Apache-2.0）把三個平台包成同一個介面， 跟用哪家模型無關。它還在研究預覽，所以版本鎖死、包在自己的介面後面，以後要換成容器或 fork 都只動一個檔。

平台底下用的要注意的
macOSsandbox-exec（Seatbelt）Apple 標成不建議使用，哪天被拿掉就啟動不了（照第 6 節：拒絕跑指令）；備案是容器或 Linux VM
Linuxbubblewrap ＋ socat ＋ seccomp（apply-seccomp）seccomp 擋 Unix socket；allowWrite／denyWrite 不支援萬用字元，要列實際路徑
Windows專用的本機帳號 ＋ Windows 防火牆要先用系統管理員權限安裝一次；檔案權限會往下繼承，沙盒帳號實際寫得進的地方可能比政策多（第 5 節）

2. 預設政策​

預設為什麼
讀擋整個家目錄，只開工作目錄和少數必要的設定；工作目錄裡的機密檔照樣擋家目錄裡有各專案的 .env、~/.ssh 的私鑰。機密放在哪裡用黑名單列不完，用白名單才保險
讀（工具鏈）裝在家目錄的工具鏈（~/.cargo、~/.pyenv、~/.nvm）由使用者在設定裡加不加的話那些指令跑不起來
寫只開工作目錄、暫存目錄、agent 自己的快取資料夾。不開機器共用的 ~/.npm（npm_config_cache 指到自己的快取）沙盒裡改掉的共用快取，沙盒外的你下次就會用到
網路全擋；碰到沒列出的網域就問：允許一次、這次對話都允許、拒絕。本機位址、雲端主機的 metadata 位址內建就擋—
Unix socket擋ssh-agent、docker 都走 socket：不擋的話，~/.ssh 讀不到，指令還是能借 ssh-agent 用你的私鑰
不開的選項allowAppleEvents、enableWeakerNetworkIsolation官方標明：前者等於放棄隔離，後者會開一條資料外流的路

~/.gitconfig 也不開：沙盒裡的 git 用一份只留無害設定的副本（user.name 這類），不然 core.fsmonitor、alias 這種設定能讓 git 執行任意程式。

工具和沙盒用同一份政策（一個 policy 模組產生兩邊的規則），兩邊的機密檔清單、可寫範圍才不會走樣。

被擋時講清楚：從沙盒程式庫拿到被擋的檔案或網域，畫面和模型都看到「被沙盒擋了：讀 ~/.ssh/id_ed25519」，不是一個莫名的 Operation not permitted。 模型看得懂原因，才會換方法，而不是一直重試。

3. 工作目錄裡也要擋寫入的：延遲執行的繞道​

工作目錄可寫，所以指令能在裡面寫一個 .git/hooks/pre-commit。沙盒當下擋不了什麼 —— 但下次你自己 git commit 時，它在沙盒外、用你的權限執行。這類檔案就算在工作目錄裡也要擋寫入：

類別例子
git.git/hooks/、.git/config、.husky/、.githooks/
shell 環境.envrc
編輯器、IDE.vscode/tasks.json、.idea/、.vimrc
套件管理器、建置工具.yarnrc、.pnpmfile.cjs、.cargo/config.toml、gradlew、.mvn/
agent 的設定.claude/settings*.json、agent 自己放在 repo 裡的設定（例如「改完檔要跑的檢查」：改得到的話，下次自動跑的檢查就是它寫的指令）

macOS 的 Seatbelt 能直接比對萬用字元（**/.git/hooks）。Linux、Windows 的程式庫要實際的路徑， 所以啟動時自己走一遍專案（有上限：例如最多 5000 個資料夾、8 層，不進 node_modules、build），把巢狀 repo 的 .git/hooks、 子資料夾裡已經存在的 android/gradlew 這類位置交給沙盒。程式庫自己只找得到下一層的巢狀 repo —— 這是在 Linux 上實測才發現的。

接受的風險要寫出來：Gradle、pub 的共用快取（~/.gradle、~/.pub-cache）不開寫入的話，Flutter／Android 在沙盒裡 build 不起來。 會被執行的位置另外擋（init 腳本、gradle.properties、wrapper/dists），但快取裡的 jar 和套件原始碼還是寫得到。 完全擋掉要每個專案各用一份快取（代價是每個專案都要重新下載），所以寫進使用者的安全說明，讓使用者知道。

4. 沙盒擋不到、要另外處理的​

  1. 鑰匙圈：鑰匙圈透過系統服務讀，檔案規則不一定擋得住；用 security 存的項目，用同一個指令讀回來不跳確認視窗。 做法：security 放進危險清單，並且實測沙盒裡讀不讀得到（建一個假的測試項目去讀）。
  2. 請系統代為執行的指令：open、osascript 是請系統替你開程式，開出來的不是沙盒的子程序。放進危險清單，並實測開不開得到沙盒外。
  3. agent 自己的工具不在沙盒裡：沙盒只管 bash 和它的子程序。read、edit、write 由權限層用同一份政策檢查實際路徑。 這裡有一個時間差的洞：bash 可以在檢查之後、打開之前，把檔案換成指向 ~/.ssh 的 symlink（建 symlink 不需要讀目標，沙盒擋不到）。 修法：工具打開檔案時不跟隨 symlink（O_NOFOLLOW），或打開之後再確認一次實際路徑；bash 不跟其他工具同時跑。
  4. MCP server：用 stdio 啟動的 server 是別人寫的程式，以你的權限在跑。工具呼叫經過權限層，但擋不到 server 自己做的事： 要嘛放進沙盒，要嘛只允許設定檔列出的 server。
  5. 呼叫模型的主程式不在沙盒裡（它要連 API）。所以主程式本身不執行模型給的任何東西，模型只能透過工具做事。

5. 在沙盒外跑的程式，放在沙盒寫得進去的地方​

有些程式本來就在沙盒外跑：使用者核准在沙盒外跑的指令、MCP server、agent 自己跑的 git（看 bash 改了哪些檔）、搜尋用的 rg、 用系統管理員權限跑的安裝程式。如果那支執行檔所在的資料夾，沙盒裡的指令寫得進去，沙盒裡就能先換掉它 —— 之後在沙盒外、用你的權限（或系統管理員的權限）跑的就是換過的那一支。

macOS、Linux 上沙盒寫得進的就是政策列的那些，找程式時跳過就好。Windows 不一樣：「所有登入的帳號都改得了」這種檔案權限會往下繼承， 沙盒帳號實際寫得進的地方比政策多。做法：

  • 啟動時實際試寫一次，找出沙盒帳號寫得進去的資料夾（不只看政策）
  • 在沙盒外跑程式之前，比對它的實際路徑在不在那些資料夾底下（比之前兩邊都先取實際路徑：PATH 上可能是 8.3 短名稱、大小寫不同）
  • 在的話照設定：問（預設）／不跑／照樣跑。開沙盒時問一次，這次對話有效；沒有人能回答時（非互動模式）當成不跑
  • 能改在沙盒裡跑的就不用拒絕（例如搜尋的 rg）

一開始只想到用系統管理員權限跑的 winget，後來才發現所有在沙盒外跑的程式都一樣：修一個案例之前，先問「同一類的還有哪些」。

6. 啟動不了就拒絕跑指令（fail closed）​

  • 沙盒起不來，一律拒絕跑指令，不是改成沒有沙盒照跑。
  • Linux 上少了 seccomp 也算起不來：少了它擋不住 Unix socket（ssh-agent、docker.sock），只給警告太危險。
  • 真的要不經過沙盒跑，必須在啟動時自己加參數（例如 --no-sandbox）。這時狀態列整段標紅、白名單不生效、每個指令都要問。
  • 開發用的 container 裡常常起不了（不給 user namespace）：那裡的測試要能分辨「沙盒起不來」和「沙盒擋下了」。 CI 上設一個環境變數要求沙盒一定要起來，起不來是紅，不是「已跳過」（怎麼證明守得住 §4）。
