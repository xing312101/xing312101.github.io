權限規則：白名單只是少問幾次

接在總覽之後。權限規則決定每個工具呼叫要允許、問使用者、還是拒絕。 它擋的是「模型想做、使用者沒同意的事」；規則沒料到的寫法交給 OS 沙盒。

1. 判斷順序​

工具呼叫
 → 路徑正規化：取實際路徑；新檔看父目錄的實際路徑
 → 是機密檔？                         → 拒絕（讀、寫都擋）
 → 在可讀／可寫範圍外？                → 拒絕（範圍要加，改設定）
 → bash：在危險清單？                  → 一定問，標紅、講原因
 → bash：每一段都在白名單，而且資料夾已信任？ → 直接跑
 → 照目前的模式決定（一般／自動改檔／唯讀…）
 → 執行（bash 一律在沙盒裡）

順序本身就是規則：機密檔和範圍檢查在最前面，任何模式、任何白名單都繞不過去。

路徑：先取實際路徑，再比對​

漏洞例子修法
symlink 繞出工作目錄工作目錄裡一個指向 ~/.ssh 的連結，字串上看起來在目錄內先取實際路徑再比；新檔看父目錄的實際路徑
字首相同的目錄/work/app-evil 用字串字首比對會被當成在 /work/app 裡比「目錄＋路徑分隔符號」，不比字串字首
不分大小寫的檔案系統macOS 預設不分大小寫：.ENV 就是 .env。Node 的 fs.realpath（JS 版）回 .ENV，fs.realpath.native 回 .env整個程式只用一個取實際路徑的函式（用原生版），用測試擋直接呼叫 realpath

最後一條很容易漏：程式裡一處用 JS 版、一處用原生版，就會拿兩個不同的字串互相比，機密檔清單比不到。

2. 白名單：要符合全部的條件才直接跑​

白名單是不會改東西、或只是跑測試的指令：git status／diff／log、ls、cat、rg、grep、npm test、pytest、cargo test⋯⋯ 但「指令名稱在清單上」遠遠不夠。任何一條不符合，就不算白名單，要問：

  • 用 &&、||、;、|、換行串起來時，每一段都要在白名單裡。 git status && rm -rf x 混不過去。

  • 不能有 $( )、反引號、>／>>、<( )、FOO=bar 這種環境變數前綴、xargs、git -c。

  • 不能有任何展開或看不懂的語法：$VAR、${…}、~、萬用字元、{a,b}、&、( )、heredoc。解析不了就當成不在白名單，不要猜。 例：乾淨的環境保留了 HOME，cat $HOME/.ssh/id_ed25519 字面上像是一個相對路徑。

  • 路徑參數要在可讀範圍內：cat ~/.ssh/id_ed25519、ls ~、find / … 都不會直接跑。

  • 白名單指令的危險參數另外列：

    指令危險的參數為什麼
    rg--pre對每個檔案執行任意指令
    find-delete、-exec、-execdir、-ok、-okdir、-fprint、-fprintf、-fls刪檔、執行、寫檔
    tree-o寫檔
    git子指令前的全域選項（-C、--config-env）；diff、log 的 --output換目錄、換設定、寫檔
    npx套件沒裝的時候沒有 TTY 時會自動下載不存在的套件來跑

  • 只在信任的資料夾裡生效（第 5 節）：「跑測試」跑的是專案自己寫的程式，npm test 可以是任何東西。

要判斷這些，指令要真的解析（用 shell 的語法樹），不是用正規表示式找關鍵字。解析器回報看不懂的地方，就一律當成要問。

3. 危險清單：任何模式都要問​

類別例子
刪除、丟掉改動rm -r、rm -f、git reset --hard、git clean -f、git checkout -- …、git restore
推送、發佈git push、npm publish
碰別的機器ssh、scp、rsync；往外送資料的 curl／wget（-d、-F、-T、-X POST）
權限與系統sudo、chmod -R、chown -R、dd、shutdown、kill -9、killall
請系統代為執行（可能跑在沙盒外）open、osascript、launchctl、crontab
鑰匙圈security

問的時候標紅、講清楚為什麼危險。規則放在設定檔，使用者可以自己加。

4. 機密檔：只能改設定放行，不能在對話裡按「是」​

預設清單：

  • .env、.env.*（例外：.env.example、.env.sample、.env.template）、.envrc
  • *.pem、*.key、*.p12、*.p8、*.keystore、*.jks；id_rsa、id_ed25519、id_ecdsa（含 .pub）
  • credentials、credentials.json、.npmrc、.netrc、.pypirc、.git-credentials
  • Android／Gradle／Flutter：local.properties、key.properties、keystore.properties、secrets.properties

read、search、edit、write 一律擋，沙盒用同一份清單擋讀取。搜尋特別要擋：讀檔工具擋了 .env， grep -r API_KEY . 卻會把它印出來 —— 這是舊設計實際有的洞。

要讓 agent 碰某個機密檔，只能使用者自己改設定，不能在對話裡按「是」。一時手快按下去的「是」，不該能放出金鑰。

5. 信任的資料夾​

第一次在某個資料夾開啟時問：「信任這個資料夾嗎？」問的時候講清楚：資料夾裡的檔案可能讓 AI 做出意外的事； 信任之後，它會跑專案自己的程式（測試、檢查）。答案用實際路徑當鍵記下來，子目錄跟著同一個答案。

不信任的資料夾：

  • 只能用唯讀模式，白名單不生效，每個指令都要問
  • 不載入 AGENTS.md、CLAUDE.md、skills：那些是別人寫給 agent 的指令（提示注入最直接的入口）
  • 不跑「改完檔自動跑的檢查」（那些指令也是 repo 裡寫的）

信任了之後，指令照樣在沙盒裡跑。另外，工作目錄不能是家目錄、家目錄的上層或根目錄：不然整個家目錄都變成可讀可寫， 信任一次，底下每個專案也都算信任了。啟動時直接拒絕。

6. 要核准的東西必須看得到​

使用者按「是」之前看到的，必須是實際會執行的全部內容：

  • 看不見的字元標出來，不是拿掉：␍、<U+202E>（從右到左覆寫，能讓結尾是 txt.exe 的檔名顯示成 exe.txt）。 一般的輸出可以把控制碼清掉；核准畫面不行，清掉等於讓使用者核准一份跟實際不一樣的東西。
  • 太長的先顯示開頭＋結尾：危險的那一行常常在最後面。另外給一個鍵從頭一頁一頁看完， 看完才給「這次對話都允許」這個選項。
  • 貼上的內容不算回答：剪貼簿裡的東西不一定是使用者放的，一段貼上的文字裡夾著 y 不能當成同意。

7. 模式​

模式改檔跑指令
一般（預設）先秀 diff 再問白名單的直接跑，其他的問
自動改檔不問（畫面照樣印出改了什麼）同上
全自動不問不問，沙盒當安全邊界；要越過沙盒時才問
唯讀／計劃不准改只准跑唯讀的白名單
  • 危險指令在每一種模式下都要問。
  • 「全自動」只能在沙盒開著、信任的資料夾裡用：問的次數少很多，安全性反而比「一直問、使用者一直按是」高。
  • 工具清單整個對話固定不變，各模式不能做的事由權限層擋，不是把工具拿掉（轉接層、上下文與花費 §3）。
  • 安全和方便衝突的地方（例如「全部不問、也不開沙盒」的模式），做成設定：預設選安全的那個，開的時候把風險講清楚，讓使用者自己決定。

8. 舊設計實際找到的漏洞​

重新檢視一個舊原型的權限設計時找到的。每一條都要有「先紅後綠」的測試（怎麼證明守得住）：

漏洞例子修法
白名單的讀檔指令沒檢查路徑cat ~/.ssh/id_ed25519、find / -name … 直接跑，內容送給模型路徑參數要在可讀範圍內；沙盒再擋一次
環境變數裡的金鑰echo 在白名單，echo $ANTHROPIC_API_KEY 把金鑰印進對話跑指令一律用乾淨的環境（工具與跑指令 §2）
搜尋沒避開機密檔grep -r API_KEY . 印出 .env搜尋一律排除機密檔；沙盒裡也讀不到
「跑測試」其實是跑專案的程式別人給的 repo 裡跑 git status，.git/config 也能讓它執行任意程式信任的資料夾
只看指令文字，永遠擋不完正規表示式列不出所有危險的寫法OS 沙盒
變數展開、萬用字元繞過路徑檢查cat $HOME/.ssh/id_ed25519；萬用字元配上工作目錄裡的 symlink任何展開都不算白名單
檢查之後才換成 symlinkbash 在檢查完、read 打開之前，把檔案換成指向私鑰的 symlinkbash 不跟其他工具同時跑；打開時不跟隨 symlink（OS 沙盒 §5）
