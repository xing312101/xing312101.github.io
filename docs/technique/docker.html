install​

https://docs.docker.com/desktop/setup/install/mac-install/

# 1. dmg
#    從 https://docs.docker.com/desktop/setup/install 下載
# 2. brew
brew install --cask docker

裝完先做一件事：Settings → Resources → File sharing，把共享目錄縮到只剩你放專案的那個 （例如 ~/workspace）。預設會共享整個 /Users，任何容器都能 -v ~/.ssh:/x 把你的私鑰掛走。 理由與驗證見〈沙箱〉。

名詞先分清楚：image / container / volume​

三個東西的生命週期完全不同，這是所有「東西怎麼不見了」與「怎麼還在」的根源。

是什麼什麼時候消失
image（映像）唯讀的檔案系統快照 ＋ 啟動設定只有 docker rmi 或 image prune 才會
container（容器）image ＋ 一層可寫層 ＋ 一個行程docker rm 會；stop 不會（只是行程停了）
volume（資料卷）獨立於容器的資料只有 docker volume rm 或 down -v 才會

容器可寫層裡的東西隨容器一起消失——這就是為什麼資料要放 volume 或 bind mount。

容器生命週期：停、移除、重來​

最常搞混的一組。由輕到重：

你想做什麼指令容器容器內的資料volume
暫停，等下要回來docker stop <c>保留（stopped）保留保留
再起來docker start <c>———
重啟（設定不變）docker restart <c>保留保留保留
移除容器docker rm <c>（要先 stop）移除消失保留
強制移除（連跑著的）docker rm -f <c>移除消失保留
docker ps            # 在跑的
docker ps -a         # 含停掉的（找不到容器時先看這個）
docker logs -f <c>   # 追 log
docker exec -it <c> bash   # 進去看看（容器必須在跑）

⚠️ docker stop 之後容器還在，docker ps 看不到但 docker ps -a 看得到。 下次用同一個名字 docker run 會撞名字衝突——那時要的是 docker start，不是再 run 一次。

Docker Compose：起、關、重來​

docker compose（v2，沒有連字號）是 CLI plugin；舊寫法 docker-compose 是 v1，已不維護。

起​

docker compose up -d              # 背景起整疊（設定有變的容器會自動重建）
docker compose up -d --build      # 順便重建映像
docker compose up -d <svc>        # 只起某個服務（連帶起它 depends_on 的）
docker compose run --rm <svc> bash   # 拋棄式容器，跑完就清（不影響長駐那份）

關——這張表是重點​

你想做什麼指令容器網路volume
暫停整疊docker compose stop保留（停止）保留保留
只暫停一個服務docker compose stop <svc>保留保留保留
停掉並移除容器 ＋ 網路docker compose down移除移除保留
連 volume 一起砍（會刪資料）docker compose down -v移除移除刪除
移除已停止的容器docker compose rm移除（僅停止的）保留保留

三個常見誤解，順手更正：

  • down 不會刪 image。要刪映像是 down --rmi local（或 docker rmi）。
  • down 不會刪 volume，除非加 -v。所以「down 之後資料庫資料還在」是正常的。
  • down 不會收 profile 服務（實測）。docker compose --profile '*' down， 或用 docker compose -p <專案名> down（靠 label 反查，連 compose 檔都不用在手邊）。

profile：平常不起、要用才起​

services:
  cloudflared:
    profiles: ["remote"]      # 平常 up 不會帶它
docker compose --profile remote up -d cloudflared

專案名（-p / name:）​

compose 用「專案名」把一疊容器歸戶，預設取目錄名——所以同一份 compose 從不同目錄跑 會起出兩疊平行的容器。在 compose 檔裡釘死就不會：

name: myapp

之後不管從哪裡 up，compose 都對帳到同一疊、只重建有變的容器。

build image​

FROM node:22-bookworm-slim
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
CMD ["node", "src/index.js"]
docker build -t myapp .
docker build -t myapp . --no-cache      # 懷疑 cache 壞了才用
docker run -dp 3000:3000 myapp
docker image history myapp              # 看每層多大、哪層該優化

兩個實務要點：

  • COPY 的順序決定 cache 命中率：先 copy 依賴清單、裝完再 copy 原始碼，改一行程式碼 就不用重裝依賴。
  • .dockerignore 一定要寫：build context 是整個目錄打包上傳，node_modules/、 .git/、資料集忘記排除的話，build 會慢得莫名其妙（大到某個程度會直接失敗）。

跨平台​

docker build --platform linux/amd64 -t myapp .   # 在 arm Mac 上建給 x86 伺服器

volume 與 bind mount​

docker volume create mydata
docker run -d -v mydata:/var/lib/data myapp       # named volume（docker 管）
docker run -d -v "$(pwd)":/app -w /app node:22 npm run dev   # bind mount（你管）
docker run -d -v "$(pwd)/ref":/ref:ro myapp       # 唯讀，核心強制
named volumebind mount
放哪docker 自己的區域你指定的宿主路徑
適合資料庫資料、快取原始碼（要即時同步）、設定檔
跨平台一致路徑與權限依宿主而異

:ro 是核心強制的，容器內連 root 都寫不進去——擋手滑很有效。但它不是對抗性的安全 邊界：能下 docker 指令的人可以另起一個容器把同一個目錄用讀寫模式掛進來。詳見 〈沙箱〉。

network​

同一個 network 裡的容器可以用服務名互相連線（compose 自動建網、自動註冊 DNS）。

docker network create todo-app
docker run -d --network todo-app --network-alias mysql \
  -v todo-mysql-data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=secret -e MYSQL_DATABASE=todos mysql:8

docker run -it --network todo-app nicolaka/netshoot   # 除錯用的萬用工具箱
#   dig mysql        # 看服務名解析到哪個 IP

三個容易踩的點：

  • 容器內的 localhost 是容器自己，不是宿主。要連宿主上 publish 的服務，用 host.docker.internal（Docker Desktop；Linux 要在 compose 加 extra_hosts: ["host.docker.internal:host-gateway"]）。
  • ports: 是「宿主 → 容器」的對外開口，容器之間互連不需要它。
  • -p 3000:3000 預設綁 0.0.0.0 ＝ 你所在的整個區網都連得到。開發用的資料庫請寫 -p 127.0.0.1:5432:5432。

registry（push / pull）​

docker login -u <user>                     # token 見 https://docs.docker.com/go/access-tokens/
docker tag myapp <user>/myapp:1.2.3        # 別只用 latest，版本要能回溯
docker push <user>/myapp:1.2.3

沒有 registry 的離線部署（存檔 → 搬過去 → 載入），見〈Deploy〉。

清理磁碟​

docker system df                  # 先看誰佔空間
docker image prune                # 刪 dangling image（安全）
docker container prune            # 刪所有已停止的容器
docker builder prune              # 刪 build cache（常常是最大的一塊）

⚠️ docker system prune -a 會把所有沒在跑的容器用到的 image 都刪掉， 包含你別的專案的。加 --volumes 更會連資料一起。在多專案的機器上， 寧可分開跑上面那幾條指定範圍的。
