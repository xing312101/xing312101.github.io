GitLab CI/CD 通用核心

一套與語言/框架無關的 GitLab CI/CD 實作基礎：pipeline 觀念、自架 runner、pipeline 樣式、機密管理。 任何專案（web、後端、mobile…）都能套用；各語言/框架只要在自己的章節補上「build / 測試 / 發佈」的具體指令即可。

note

本系列為通用範例，所有網址、帳號、路徑皆為佔位符，請替換成你自己的值。各語言的實作範例見該語言章節（例如 Flutter Mobile CI/CD）。

推薦架構：混合式（雲端 + 自架）​

三大原則（跨語言通用）

  1. 能用免費雲端的就丟雲端 — 快檢每個 MR 都要跑，放在 always-on 的雲端 runner，不被你的電腦有沒有開機拖累。
  2. 只有「沒有免費雲端替代品」的工作才自架 — 例如需要特定 OS（iOS 需 macOS）、特殊硬體、或機器上的特定授權軟體。
  3. 發佈永遠要有手動關卡 — push 不該自動把成品推給正式用戶；正式釋出一定要有人按一下。

心智模型：控制面 vs 執行者​

  • GitLab = 控制面：依 .gitlab-ci.yml 的規則決定「什麼時候該跑哪個 job」。
  • Runner = 執行者：實際執行 job 的機器。雲端 hosted runner 由 GitLab 提供；自架 runner 是你自己機器上跑著的常駐 agent。
  • 觸發是 GitLab 端的事；自不自架，只影響「這個 job 由哪台機器執行」。

本核心的檔案​

檔案內容
intro本篇：架構總覽與原則
conceptspipeline / job / 觸發 / exit code 判斷 / resource_group / merge gate / compute minutes
self-hosted-runner自架 runner：安裝、註冊、tags、防火牆與公司網路（outbound-only）
runner-concurrencyconcurrent vs limit、多專案共用一台、全域狀態衝突、並發要開多少
pipeline-patterns快檢樣式、省分鐘技巧、通用 .gitlab-ci.yml 骨架
secretsCI/CD Variables 機密管理通則

建議閱讀順序：intro → concepts → pipeline-patterns → self-hosted-runner → secrets （runner-concurrency 等到自架 runner 要服務多條 pipeline 或多個專案時再讀。）

前置需求（通用）​

項目說明
GitLab 專案gitlab.com（SaaS，內建免費 Linux runner）或自架 GitLab
Runner雲端 hosted（SaaS 現成）或自架一台（見 self-hosted-runner）
版本鎖定用你語言的版本管理工具鎖 SDK 版本，讓 CI 與本機一致

語言/框架專屬的前置（SDK、build 工具、簽章…）屬於各語言章節，不在通用核心。
